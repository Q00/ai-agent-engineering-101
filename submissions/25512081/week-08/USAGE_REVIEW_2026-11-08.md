추가로 관측되지 않았고, 사용량 확인 로그는 계속 쌓이고 있었다.

## 적용한 보호 장치

`usage_limits.json`: ADMIL의 기존 전체 모델 기준과 동일하게 세션 80%, 주간 70%.
`usage_guard.py`가 2시간 코드 overseer를 실행하기 전과 실행 중 60초마다 native /usage를 읽는다.

- 기준 이상이면 새 코드 보완을 시작하지 않는다.
- 실행 중 기준에 도달하거나 사용량 확인이 실패하면 overseer 프로세스 그룹을 종료한다.
  중단된 출력은 별도 파일로 보존하고 비용을 0으로 기록하지 않는다. 다음 실행은 미커밋 변경부터 확인한다.
- 확인 실패는 사용률 0으로 간주하지 않고 대기한다.
- 다음 cron 실행에서 새 사용량이 두 기준 아래면 다시 실행한다. 즉, 리셋 직후 즉시 재개가
  아니라 다음 예약 시점에 재확인한다.
- `logs/overseer-quota.jsonl`에 검사·대기·실행·종료를 추가 기록한다. overseer/runs.jsonl에는
  paused와 quota를 함께 기록한다.

버전 관리되는 `overseer_quota.sh`를 서버의 ~/market-agent/overseer.sh에 설치했다.
기존 스크립트는 새 로그에 보존했다. cron 주기와 Opus 모델 설정은 유지했다.
이 보호 장치는 코드 보완만 제어한다. 시장 buyer/seller와 시간별 planner는 계속 실행하므로
공유 계정의 사용률은 이후에도 증가할 수 있다.

검증: 가짜 사용량과 무해한 자식 프로세스로 회귀 검사 8개 통과(실행 전 차단, 실행 중 종료,
확인 실패, 리셋 후 허용, 원래 출력 보존). 운영 Python에서도 8개 통과. bash 구문 검사를 통과했고,
실제 native 사용량으로 preflight 확인을 수행했다. 실제 코드 보완 모델 호출을 테스트로 실행하지 않았다.
