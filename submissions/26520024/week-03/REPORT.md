# 3주차: 생성 이미지 검토 업무는 누구에게 맡겨야 하는가? (26520024)

## 1. 실험 설정

관리자 1명과 LLM 입찰자 3명이 합성한 **텍스트 기반 검토 요청 6개**를 배정한다.
A는 성적 콘텐츠 안전성, B는 폭력 콘텐츠 안전성, C는 캐릭터·로고 유사성을 담당한다.
실제 이미지 분류나 법적 판단은 수행하지 않는다. 정답 담당자(gold)는 각 2개씩
균등하게 지정하고, 실행 전에 커밋했다(`b06ac13`).

OpenAI 모델을 Codex CLI 0.153.0과 기존 ChatGPT 로그인으로 호출했다.
모델은 `gpt-6-astra`, 추론 수준은 `low`, 환경은 기존 conda `base`의 Python 3.8.19다.
Temperature와 최대 출력 토큰 수는 **직접 설정할 수 없으며 내부 값은 미확인**이다.
매번 새 세션에서 기본 도구를 비활성화하고 system/user 문자열을 전달했다.
이는 API의 역할별 메시지를 직접 지정하는 방식은 아니다. 구현에는 Codex의 도움을 받았다.

정확한 문구는 [prompts.json](prompts.json)에 있다. `baseline`은 전문 분야를 구분하고,
`homogeneous`는 능력 설명만 모두 동일한 일반형으로 바꾼다. `overconfident`는
C에게만 모든 태스크에 자신감 95 이상으로 입찰하라는 문장을 추가한다.
태스크·순서·모델·관리자는 동일하며, 유효한 입찰 중 자신감이 가장 높은 쪽에 낙찰한다.
동점은 A, B, C 순서로 처리한다. 잘못된 JSON은 재시도 없이 입찰 없음으로 처리한다.
로그인된 `base` 환경에서 이 폴더로 이동한 뒤
`python run_experiment.py --repetitions 3`으로 실행한다. 검증 방법은 [README](README.md)에 있다.

## 3. Smith(1980)와의 비교

출처: [Smith의 분산 센싱 사례 및 III·VI절](https://reidgsmith.com/The_Contract_Net_Protocol_Dec-1980.pdf).

| 비교 요소 | Smith의 분산 센싱 | 이번 구현 |
|---|---|---|
| 참여자 | 센서·처리 노드가 동적으로 역할을 맡음 | 고정 관리자와 프롬프트로 역할을 정한 입찰자 3명 |
| 입찰 생성 | 위치·센서 정보에 따른 프로그램 규칙 | LLM이 자신감과 이유를 JSON으로 생성 |
| 입찰의 정직성 | 협력적 정보 제공을 전제하며 진실성 보장은 명시하지 않음(해석) | 형식만 검사하며 실제 능력은 검증하지 않음 |
| 좋은 배정의 기준 | 공간적 커버리지와 센서 구성 | 사전 지정 담당자와의 일치 여부이며 검토 정확도는 아님 |
| 협상 비용 | 메시지 트래픽; 자격 조건·직접 계약으로 절감 | 프로토콜 메시지 수와 별도로 호출·토큰 수 기록 |
| 실패 양상 | 노드 고장; 재공고를 통해 복구 지원 | 동점 편향·불필요한 입찰 관찰; 파싱 실패·중단 처리는 오프라인 테스트 |

## 4. 결과 해석

3회 반복을 합치면 baseline은 18/18개를 정답 담당자에게 배정했지만 homogeneous는
6/18개에 그쳤고, 실행당 메시지는 30개에서 42개로 40% 증가했다. T02에서 baseline의
B는 100점으로 입찰하고 A와 C는 거절했으나([001:29–40행](logs/001-baseline.log#L29)),
homogeneous에서는 셋 모두 100점으로 입찰하여 동점 규칙에 따라 A가 선택됐다
([002:29–40행](logs/002-homogeneous.log#L29)). 과신 지시는 입찰 행동만 바꾸고 낙찰은
바꾸지 않았다. Overconfident의 정답 배정은 18/18개였으며, 메시지는 실행당 34개로
baseline보다 13.3% 증가했다. C는 T05가 자기 전문 분야 밖임을 인정하면서도 95점으로
입찰했지만([003:99행](logs/003-overconfident.log#L99)), B의 100점 입찰이 낙찰됐다
([003:94–100행](logs/003-overconfident.log#L94)). C의 분야 밖 입찰 12건은 모두 95점으로
해당 전문가의 100점보다 낮았다. 따라서 **이번 과신 조건에서 배정 성능 저하는 관찰되지
않았지만**, 이를 과신에 대한 견고함의 증거로 볼 수는 없다. 프로토콜 자체는 능력 주장의
진위를 검증하지 않기 때문이다. 또한 homogeneous의 정답률은 사전 담당자와의 일치율이지
일반형 모델의 실제 업무 능력이 아니다. 쉬운 태스크 6개, 고정된 태스크·조건·동점 처리 순서,
미확인 샘플링 설정, 3회 반복이라는 한계가 있으며 실제 이미지 탐지 성능은 측정하지 않았다.
