# Week 07 LAB 2: 서명 영수증과 선택형 할인

## 바뀐 거래

판매자는 실제 A2A 첫 가격 제안에 선택형 가위바위보를 안내한다. 별도 장난감 게임이 아니라
같은 거래의 다음 제안 가격에 영향을 준다. 참여하지 않으면 기존 숫자 흥정을 그대로 한다.

| 조건 | 처리 |
|---|---|
| 참여 | 구매자가 같은 task에 `RPS rock`, `RPS paper`, `RPS scissors` 중 하나를 보냄 |
| 구매자 승리 | 해당 상품의 고정 최저가로 제안 가격을 낮춤 |
| 구매자 패배 또는 무승부 | 게임 직전 제안 가격을 유지. 가격 인상 없음 |
| 구매 확정 | 게임 후 별도의 숫자 제안을 보내고 판매자가 수락해야 완료 |
| 반복 | task당 한 번만 가능. 재요청은 같은 결과를 보여 주며 재추첨하지 않음 |
| 이미 최저가인 첫 제안 | 추가 할인 여지가 없으므로 게임을 제안하지 않음 |

예: 의자 최초 제안이 198이면 승리 후 180, 패배나 무승부 후 198이다.
게임 결과만으로 영수증을 발급하지 않는다. 이후 180 또는 198에 실제 합의하면 그 금액으로
서명한다. 이는 0원·두 배 도박을 대체한 사용자 승인 조건이다.

판매자의 패는 구매자 선택 전에 난수로 정하고, task·패·nonce의 SHA-256을 공개한다.
게임 뒤 원래 패와 nonce를 공개하므로 상대가 사전 공개 해시와 비교할 수 있다.
검증은 사전에 본 해시와의 비교까지 해야 하며, 해시만으로 서비스 전체의 공정성이 증명되지는 않는다.
게임 요청에 들어 있는 예산이나 해시 숫자는 구매 제안으로 해석하지 않는다.

다른 학생의 buyer가 이 텍스트 프로토콜을 사용해야 실제 게임이 진행된다. 모든 buyer가
자동 참여한다고 보장할 수 없다. 본인 buyer의 예산 보호나 출력 계약은 바꾸지 않았다.

## 서명과 가격 정책

- 기존 `shop_key.pem`의 Ed25519 키를 읽고 바꾸거나 새로 만들지 않는다.
- 영수증은 `shop`, `item`, 정수 `price`, 실제 A2A `task` 네 필드에 서명한다.
  키 정렬, 공백 제거, UTF-8 직렬화를 적용하고 base64 `sig_seller`를 붙인다.
- 서명이 성공한 뒤에만 구매 완료와 artifact를 내보낸다. 서명 실패에는 unsigned 영수증을 내지 않는다.
- 최초 제안 상한은 최저가의 110%를 내림한 정수다. 기본 상품은 램프 110, 의자 198, 책장 286이다.
- 고정 최저가 100/180/260은 유지하고, 같은 거래에서 제안 가격을 올리지 않는다.
- 추가 요금 없이 실제 수락 금액을 영수증에 기록한다. 최저가를 제안할 때는 상대에게도 명시한다.
- 좋은 후기 강요, 후기 대가 할인, 다른 가게 허위 비방이나 가짜 후기는 구현하지 않았다.

이는 투명한 가격, 작은 최초 마진, 빠른 합의, 선택형 판촉 전략이다. 평점 상승을 보장하는
전략은 아니며, 가위바위보 할인은 수익률과 통신 횟수에 비용이 생길 수 있다.

### 최종 검증

최종 코드 실행 폴더: `logs/lab2-20261020T123359473302Z/`.
오프라인 테스트 65/65가 통과했다. 가위바위보 9가지 조합, 승패·무승부 후 실제 SDK
영수증, 재추첨 방지, 게임 없이 일반 거래, 자연어 게임 요청의 예산 숫자 오인 방지를 포함한다.
실행 소스 해시 일치, Python 파일 20개의 구문 검사, 기존 두 개인키의 수정 시각 보존도 별도 확인했다.
최종 코드의 공식 모델 테스트도 **25/25 통과**, 종료 코드 0이다. 램프 판매 3회 모두
실제 응답에 선택형 게임을 제안했고, 일반 구매는 110에 완료되어 서명이 검증됐다.
책장 최저가 보호 3회, 구매 예산 보호 3회, 좋은 후기 가게 선택 3/3도 통과했다.
공식 구매자는 게임에 참여하지 않으므로 게임 승패에 따른 할인 영수증은 앞의 SDK
오프라인 통합 테스트로 별도 검증했다. 공개 시장에서의 실제 참여 결과와는 구분한다.

`verify_result`는 공개한 패와 nonce의 해시만 검사한다. 결과 금액과 승패 규칙은
별도 코드와 테스트가 검사하며, 상대는 첫 제안에서 기록한 commitment와도 비교해야 한다.
가위바위보 자체는 모델 호출 없이 코드로 판정한다. 상품 선택과 일반 가격 협상은 모델이 수행한다.

초기의 시장 미연결 데모 방안은 사용자가 실제 거래 할인을 선택하면서 폐기했다.
오프라인 검토에서 게임 문장 안의 예산을 일반 가격으로 오인할 가능성을 발견하여,
문장 어디에 있든 `RPS` 토큰이 있으면 게임 안내 경로로 분리하고 회귀 테스트를 추가했다.

기존 `eraseanything` 기반 week-07 `.venv`를 사용했다. conda 환경이나 패키지는 변경하지 않았다.
실제 협상 모델은 기존 Codex CLI의 `gpt-6-astra`, reasoning `low`이며 로그인은 그대로 사용한다.
