# Why this description

The write_note description connects the user's intent to "save or record a result" with a concrete file-writing action, so the model can distinguish it from read_file and calculator. It explicitly says that the tool appends text, preserves existing content, creates missing files, and adds a newline; the model should not assume it overwrites a report. The relative outputs/ path, .txt extension, nonempty content, and 4000-character limit explain the constraints before a call is attempted. Stating that write_note neither calculates values nor reads input separates the three tools' responsibilities without hard-coding their execution order. These are design reasons, not observed improvements: a comparison of actual model runs is still pending because no API key was available during implementation.
