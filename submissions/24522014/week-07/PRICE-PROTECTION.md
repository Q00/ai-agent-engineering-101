# 공개 가격 보호와 초기 응답 단축

사용자 승인에 따라 첫 가격 105/195/280과 최저가 100/180/260은 유지하면서 공개 가격 초과 결제를 방지한다. 구매자가 현재 공개 제시가보다 높은 금액을 제안하면 그 금액을 수락하지 않고, 낮은 공개 가격을 다시 제시해 확인을 요청한다. 예를 들어 lamp 105 공개 후 115 제안에는 input-required 상태로 105를 재안내하며 영수증을 만들지 않는다. 구매자가 105로 재제안하면 협상 하네스가 수락을 판단하고 현재 동의한 가격 105로 서명한다. 최저가 이상·공개가 이하의 더 낮은 재제안도 기존 정책대로 수락 가능하다.

이 확인 단계는 초과 제안에만 추가된다. 영수증 가격만 사후 변경하거나 합의가 없는데 거래를 완료하지 않는다. `confirmation_required` quote data와 숫자 하나만 포함한 가격 안내를 유지한다. 반복해서 높은 금액을 보내도 확인 전에는 완료 영수증을 발행하지 않는다.

초기 가격은 사용자가 이미 정한 값이므로 `opening_decision`은 설정·최저가를 검증한 뒤 모델 호출 없이 반환한다. 로그에는 `controller: configured_price`, provider/model null로 기록해 모델이 판단했다고 꾸미지 않는다. 초과 제안 보호도 `controller: price_protection`으로 기록하며 추가 추론을 하지 않는다. 나머지 제안 협상은 Claude Code + Haiku로 판단하고 검증 오류에 대한 기존 제한적 재시도·서명 실패 보호를 유지한다. 모델 장애 시 성공 거래를 만들어 내는 fallback은 아니다.

## 검증과 운영

로컬 26개 검사와 카드 버전 0.5.0 소스의 공식 거래 검사 25/25가 통과했다. 초기 가격에 모델 호출이 없는지, 높은 제안 반복에 영수증이 생기지 않는지, 낮은 공개가 확인 후 정확한 가격·task의 영수증이 나오는지 확인했다. 실제 배포 전 사용자가 이벤트를 변경하여 두 개선을 카드 0.6.0의 새 약속 이벤트와 함께 적용한다. 현재 검증·배포 상태는 `REVIEW-PROMISE-EVENT.md`를 따른다. OCI와 C-SERVER는 사용하지 않는다.

이후 사용자가 새 이벤트를 명시적으로 변경했다. 이전 이벤트에 이미 참여한 거래의 10월 29일 지급 조건은 별도 보존하고 새 거래에는 `REVIEW-PROMISE-EVENT.md`의 즉시 최저가 조건을 적용한다.

공개 가격 보호와 초기 가격 무추론 응답은 2026-10-22 09:34 KST에 카드 0.6.0으로 새 이벤트와 함께 실제 적용했다. 공개 진단에서 lamp 115 초과 제안을 완료하지 않고 105로 재확인하는 것을 확인했다. 일반 첫 가격 응답은 세 품목 모두 해당 진단에서 약 0.14초였으며 모든 사용자에게 보장하는 지연은 아니다.
