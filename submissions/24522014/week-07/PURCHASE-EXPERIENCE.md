# 정상 구매와 협상 안내 개선

2026-10-22 사용자 요청에 따라 카드 0.8.0을 준비했다. 일반 제시가 105/195/280, 최저가 100/180/260과 이벤트 조건은 유지한다. buyer 정책·키·owner·기억·운영 호스트도 바꾸지 않는다.

## 확인한 문제와 변경

기존 판매자는 후속 메시지가 양의 정수 하나일 때만 가격 제안으로 처리했다. 따라서 서비스 질문이나 명확한 문장형 구매 의사에도 숫자를 보내라는 안내만 반복했다. 실제 초기 로그 `logs/seller/20261022T045830686243Z-6d9a8294.json`과 `20261022T050308525448Z-5feee03f.json`에는 품질 보증·사후 서비스·환불 정책 문의가 있었으나 첫 응답은 가격과 이벤트 공지뿐이었다.

명확하고 조건 없는 다음 형식을 추가로 인식한다: `I offer 105`, `I can pay 105`, `I accept 105`, `I agree to pay 105`, 선택적으로 현재 품목 `for the lamp` 등. `I accept the quoted price`와 `I accept your quote`는 해당 task의 현재 제시가를 확인한 것으로 처리한다. `105에 구매하겠습니다`도 지원한다. 임의의 자연어 전체를 이해한다고 주장하지 않는다.

예산 언급, 부정문, 다른 품목, 여러 가격, 보증 등을 조건으로 붙인 문장은 구매 동의가 아니다. 이때 task를 열어 두고 현재 가격·확인 방법을 다시 안내한다. 서비스 관련 문의에는 합의 품목·가격과 task가 일치하는 서명 영수증을 제공한다고 설명하며, 이 모의 시장에 제품 보증·배송·수리·반품 기능은 구성되어 있지 않음을 알린다. 기존 환급 참여 조건은 그대로 유지한다. 지원하지 않는 서비스를 약속하지 않는다.

첫 견적에도 구매 확인 방법을 안내한다. 가격은 계속 첫 줄에 있고 가격 텍스트의 숫자는 하나만 유지한다. 현재 제시가와 정확히 같은 제안은 이미 검증한 조건의 확인이므로 추가 모델 호출 없이 서명한다. 제시가보다 낮은 가격 제안은 기존 Claude Code + Haiku 협상으로 처리하고, 초과 제안은 낮은 현재 제시가를 재확인한다. 최저가 미만 판매·확인 전 영수증 발급·타인의 후기 제출은 허용하지 않는다.

정수가 아닌 후속 문의도 `controller: purchase_guidance`, `phase: clarification` 로그로 남겨 반복 문의와 병목을 추적한다. 가격 확인은 `controller: quote_confirmation`으로 기록해 모델 협상과 구분한다.

## 범위와 검증

직전 관측의 결렬 22건은 예산 부족 13건, buyer 모델 429 실패 5건, 나머지 서비스 요구를 포함한 협상 결렬 4건이었다. 이번 수정은 대화 형식과 안내를 개선한다. 예산 부족을 할인으로 해결하거나 다른 buyer의 API 제한을 수정한 것은 아니다. 서비스 안내가 구매자 기대를 충족하여 결렬을 없앤다고 보장하지 않는다.

로컬 검사 38개가 통과했다. 실제 JSON-RPC/SDK 경로에서 서비스 질문 → 안내 → 명시적 구매 확인 → 영수증, 조건부·부정·예산 메시지의 미구매, 문장형 초과 제안 보호, 기존 협상 경로, 서명·예산·이벤트 동작을 확인했다. 공식 거래 검사와 공개 배포 검증은 진행 중이다.

자체 공개 진단은 시장 주문·결과·별점으로 제출하지 않으며 진단 task는 분석에서 제외한다. 이전 홍보 측정 경계를 보존하기 위해 새 배포는 `.market/purchase-deployment.json`에 별도로 기록한다. 기존 `.market/marketing-deployment.json`을 새 URL로 덮어쓰지 않는다.

배포 이후 조회는 `measure_marketing.py --profile purchase`로 별도 스냅샷을 남긴다. 이벤트 약속과 구매율을 구분하며, 진단 task를 제외한다. 이전 홍보 구간은 기본 profile로 계속 조회할 수 있다.
