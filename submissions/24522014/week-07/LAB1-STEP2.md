# LAB 1 Step 2: 학생이 정한 가게 선택·기억·후기 규칙 구현

2026-10-20, 학번 24522014 (kcwarni).

사용자가 직접 지정한 일곱 가지 규칙을 `market_buyer.py`와 `buyer_memory.py`에 구현했다. 흥정은 기존 `buyer.BuyerTransport`와 `run_autonomous`를 재사용한다. 목표는 정직한 가게에서 예산 내 구매 성공률이다.

## 선택 규칙

| 사용자 규칙 | 구현 |
|---|---|
| 직접 거래 경험 | 같은 이름·품목의 정상 구매 중 현재 예산 이하였던 경험을 우선한다. 과거 가격은 선택의 참고 정보이며 실제 제안은 현재 협상에서 결정한다. |
| 나쁜 공개 후기 | 별점 1~2점 중 영수증 가격 불일치·과다 청구를 구체적으로 지적하는 서로 다른 후기 2개 이상이면 우선순위를 낮춘다. 같은 문장 반복은 한 건으로 센다. |
| 신규 가게 | 경험이 없다는 이유로 위험 표시하지 않는다. 믿을 만한 과거 구매가 없으면 후보가 된다. |
| 예산 내 거래 결렬 | 가게·품목·예산·결과를 저장하고 3점의 중립 후기를 남긴다. 회피 대상으로 등록하지 않아 예산이 커졌을 때도 다시 고려한다. |
| 통신 오류 | 최근 1시간 내, 최근 5건 중 연속적인 실패 구간에서 통신 오류가 2회 이상이면 우선순위를 낮춘다. 성공이 있으면 앞선 오류 집계는 중단하며 시간이 지나면 복원된다. |
| 합의와 영수증 불일치 | 성공으로 세지 않고 1점, 결과 receipt는 null로 보낸다. 원본 영수증·마지막 제안·task와 buyer 로그를 보존하고, 같은 가게 이름을 이후 선택에서 제외한다. |
| 정상 구매 | 완료 상태, 품목, task, 양의 정수 가격, 예산, 마지막 제안과 영수증의 가격 일치를 확인한 경우 5점. |

후보의 우선순위는 통신 오류 반복 여부, 공개 가격 문제 반복 여부, 같은 품목의 정상 구매 경험 순으로 정한다. 모든 조건이 같으면 이름으로 결정한다. 최근 통신 오류 1건만 있는 가게는 신규 가게보다 불리하지 않다. 직접 가격 불일치가 확인된 가게는 후보에서 제외하며, 모두 제외되면 거래하지 않고 빈 shop과 receipt null을 출력한다.

공개 후기 판별은 영어·한국어의 명시적인 표현을 확인하는 제한적인 규칙이다. 모든 자연어 표현이나 악성 후기를 정확히 판별한다고 주장하지 않는다. 선택은 코드가 수행하므로 공개 후기를 하네스 프롬프트에 넣지 않는다. 흥정 하네스는 기존 방식으로 현재 가게의 가격과 대화 이력을 받는다.

## 기억

기본 파일은 `.market/buyer-memory.jsonl`이다. 거래마다 한 줄을 추가하고 원본 기록을 삭제·요약 덮어쓰기하지 않는다. 식별자는 `shop_name`이며 URL은 당시 증거로만 저장한다. 기억이 손상되면 조용히 무시하지 않고 실행을 실패시킨다. 키트가 buyer를 하나씩 실행하는 형태를 전제로 하며 같은 기억 파일에 여러 buyer를 동시에 실행하지 않는다.

품목·예산·결과·원본 영수증·마지막 제안·오류 종류·선택 이유·후기를 저장한다. `logs/market-buyer/`에는 실행별 선택 근거와 결과를 별도 보존한다. 최근 기록 개수는 일시적 장애 판단에 적용하며, 정상 구매 경험과 직접 불일치 증거는 전체 기록에서 확인한다.

최근 5건, 1시간, 오류 2회는 명시적인 초기 설정이다. `--memory-window 3|5|10|20`으로 장애 판단의 기억 범위를 바꿀 수 있다. 비교 실험으로 성공률의 최적값을 찾았다고 주장하지 않는다. 이전 Round 0 로그만으로는 기억 정책별 구매 결과를 비교할 수 없다.

## 실행 및 검증

저장소 루트에서 명령의 계약은 다음과 같다.

```powershell
& ./submissions/24522014/week-07/.venv/Scripts/python.exe -X utf8 ./submissions/24522014/week-07/market_buyer.py --shops <가게목록.json> --item lamp --budget 120
```

선택 이유를 먼저 출력하고, 마지막 줄에 `{shop, receipt, stars, review}` JSON을 출력한다. 예산 검사는 기존 buyer의 판단 검증과 전송 직전 검사 양쪽에서 유지한다. 영수증 서명은 목록 입력에 공개키가 없으므로 이 buyer에서 검증했다고 표시하지 않으며 공식 키트에 맡긴다. 로컬 일치 확인과 시장의 서명 검증을 구분한다.

`test_market_buyer.py`는 URL 변경 후 기억, 반복 공개 후기, 일시 장애와 복원, 불일치 증거 보존, 예산 초과 전송 방지, 후기와 원본 영수증 보존을 검사한다. 최초 테스트는 격리 디렉터리에 프롬프트를 복사하지 않아 3개가 실패했고, 이 실패를 커밋한 뒤 테스트 환경을 수정해 13개 모두 통과했다.

`verify_lab1_step2.py`는 공식 market test의 buyer 항목만 새 증거 디렉터리에서 실행한다. 실행 소스·프롬프트를 복사해 당시 버전을 보존하며 운영 기억과 기존 테스트 결과를 덮어쓰지 않는다. 검증 결과는 `logs/lab1-step2/integration/` 아래에 남는다. 전체 market test 통과와는 구분한다.

실행 결과는 **13/13 buyer 검사 통과**다. lamp 구매는 105·100·105로 예산 120 이내였다. bookshelf 제안은 3회 모두 최대 230에서 멈췄고 거래 없이 취소했다. 후기 선택 검사는 3회 모두 나쁜 후기의 가게에 요청하지 않고 좋은 후기의 가게에서 구매했다. 보고서는 `logs/lab1-step2/integration/20261020T113033838937Z/buyer-check-report.json`에 있다. 이는 공식 테스트의 고정 상대에서 사용자 정책을 검증한 결과이며, 기억 길이의 최적화 실험이나 실제 시장의 정직한 가게 구매 성공률 추정은 아니다.
