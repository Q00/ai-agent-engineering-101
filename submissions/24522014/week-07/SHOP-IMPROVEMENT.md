# 가게 개선: 서명, 협상 설명, 가격, 가동 유지

2026-10-20, 학번 24522014 (kcwarni). 후기와 별점을 높이기 위한 사용자 승인 개선 작업이다. 높은 별점이나 최적 가격을 보장하는 결과로 보고하지 않는다.

## 근거와 변경

처음 후기 0건의 직접 원인은 판매 상대가 후기·별점을 제출하지 않은 것이었다. 이후 받은 첫 3점 후기는 230 제안에서 설명 없이 No deal로 끝났다는 내용이다. 해당 후기와 조정 전 상태를 `logs/shop-improvement/reviews-before.json`, `before.json`에 보존했다.

| 품목 | 기존 첫 제시가 중앙값 | 첫 제시가 참고값 | 유지한 최저가 |
|---|---:|---:|---:|
| lamp | 150 | 120 | 100 |
| chair | 260 | 210 | 180 |
| bookshelf | 340 | 300 | 260 |

기존 첫 제시가 통계에는 테스트가 포함된다. 실제 시장 판매 영수증의 품목별 중앙값은 lamp 114, chair 215, bookshelf 302.5였다. 이를 참고해 `shop_policy.json`과 seller 프롬프트의 시작 가격 지침을 조정했다. 하네스가 가격을 결정하고 기존 코드의 최저가 검증은 유지한다. 이는 고정된 초기 개선 실험이며 자동 가격 최적화나 최적값 탐색 결과는 아니다.

seller는 이제 합의 가격·품목·task가 일치하는 Ed25519 서명 영수증을 발급한다. 서명 키를 읽을 수 없으면 거래를 실패 상태로 종료하고 unsigned 판매 완료를 내보내지 않는다. 완료 메시지에는 합의 가격과 서명 영수증 발급을 알린다. 결렬 메시지에는 구매자 제안과 마지막 공개 제시가, 구매가 완료되지 않았음을 알리며 비공개 최저가는 노출하지 않는다.

`run_market.py`는 Windows에서 키트가 실행되는 동안 프로세스 범위로 자동 절전을 방지한다. 전역 전원 설정은 바꾸지 않고 정상 종료 시 요청을 해제한다. 사용자가 직접 절전·종료하거나 네트워크가 끊어지는 경우까지 가동을 보장하는 기능은 아니다.

## 검증과 배포

- seller 단위·프로토콜 검사 6개 통과. 최초 출력의 예상 오류 로그가 PowerShell stderr로 표시되어, 해당 예상 로그를 assertLogs로 검사하는 형태로 정리했다. 원래 로그도 보존했다.
- 동일 소스·설정·프롬프트의 격리 복사본으로 수정하지 않은 공식 market test를 실행해 25/25 통과했다. 운영 buyer 기억과 테스트 기억을 분리했다.
- 공식 보고서와 로그를 원본 그대로 제출 위치에 복사했고 이전 파일은 별도 보존했다. 실행 소스 해시와 프롬프트 일치도 확인했다. 테스트에 사용한 비밀키 복사본은 제거했다.

- 기존 shop/buyer 키, kcwarni GitHub 소유권, 실제 거래 기억이 유지됨을 확인했다.

## 효과 평가의 범위

`live-comparison.json`에 조정 전후 누적 판매 수·평균 판매가·점유율·후기 수·별점을 저장했다. 배포 직후 스냅샷만으로 별점 상승이나 가격 조정의 인과 효과를 입증할 수 없다. 품목·예산·상대 구성도 달라질 수 있으므로 이후 충분한 실제 거래와 받은 후기에서 효과를 평가해야 한다. 테스트용 자기 거래나 작성하지 않은 후기를 성과로 넣지 않는다.

관측값은 판매 5 → 6건, 받은 후기 1 → 4건, 평균 별점 3 → 3, 누적 평균 판매가 261.4 → 약 249.67, 점유율 0.006 → 0.005였다. 이 구간에는 검증 중 기존 seller가 운영된 시간도 포함되므로 증가한 후기·판매를 새 코드의 효과로 해석하지 않는다.

실행 증거는 `logs/shop-improvement/`와 `logs/market-kit.log`에 있다. 키트는 계속 실행 중이며 운영 로그와 기억은 추가된다. 현재 PID는 `.market/process.json`에서 확인한다.
