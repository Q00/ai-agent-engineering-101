## 1. 가게 선택과 기억

목표는 정직한 가게에서 예산 내 구매 성공률이다. 사용자가 직접 지정한 일곱 가지 규칙을 `buyer_memory.py`, `market_buyer.py`에 구현했다. 같은 품목을 예산 안에서 정상 구매한 가게를 우선하고 과거 가격을 현재 가격으로 가정하지 않는다. 신규 가게는 중립으로 취급한다. 영수증과 합의 가격이 직접 불일치한 가게는 제외하며 반복되는 공개 가격 문제와 최근 통신 장애는 우선순위를 낮춘다. 예산 부족은 부정행위로 분류하지 않는다.

기억은 `.market/buyer-memory.jsonl`에 거래마다 추가한다. 식별자는 가게 이름이고 당시 URL, 품목, 예산, 결과, 가격, 원본 영수증, task, 합의 가격, 검증 상태와 선택 이유를 보존한다. 최근 5건·1시간·오류 2회는 초기 설정이며 최적값을 구했다고 주장하지 않는다. 상세 설계와 한계는 `LAB1-STEP2.md`, `LAB1-STEP2-DESIGN.md`에 있다.

## 2. 공개 후기와 하네스

공개 후기를 하네스에 직접 넣지는 않는다. 선택 코드가 1~2점 후기의 구체적인 영수증 가격 문제를 검사하고 서로 다른 문제 후기 2개 이상이면 가게 우선순위를 낮춘다. 제한된 영어·한국어 표현에 의존하므로 모든 허위 후기나 가격 문제를 판별하지 못한다. 협상 하네스에는 선택된 가게의 현재 가격, 품목·예산과 대화 이력을 제공한다. 사용자 규칙에 따라 정상 구매는 5점, 가격 불일치는 1점, 예산 내 결렬·일시 통신 문제는 부정행위로 단정하지 않는 중립 후기를 생성한다. 로컬 영수증 일치 확인과 시장 키트의 서명 검증을 구분한다.

## 4. 서명 구현과 실패 기록

seller는 `{shop,item,price,task}`의 정렬·공백 없는 UTF-8 JSON에 기존 Ed25519 키로 서명한다. 가격은 정수이며 완료 task와 서명 영수증을 연결한다. 서명 키를 읽지 못하면 unsigned 완료 대신 실패한다. 반대편 키트가 영수증을 검증한 뒤 buyer 서명을 추가한다. 최초 starter는 seller 서명이 없었으며 R2 요건을 충족하지 못했다.

구현 후 canonical UTF-8, 변조 탐지, 잘못된 가격과 키 실패를 확인했다. 초기 로컬 프로토콜 검사에서는 예상 오류 로그가 PowerShell stderr로 나타났고 assertLogs로 예상 실패를 명시적으로 확인하도록 고쳤다. 이후 테스트 task를 취소해 SDK dispatcher 경고도 제거했다. 원본 실패·성공 로그와 변경 이력은 보존했다. 격리한 동일 소스 복사본으로 공식 거래 검사 25/25 PASS를 확인했고 운영 기억에 테스트 기록을 섞지 않았다. `LAB2-STEP1.md`, `LAB2-STEP2.md`, `LAB2-STEPS34.md`와 `logs/shop-improvement/market-test/`가 증거다. 일정 안내의 이후 수정은 8개 로컬 검사로 검증했으며 25/25 전체 검사를 다시 실행한 것으로 보고하지 않는다.

### 챌린지 1: 가격 조정

자기 거래와 후기를 참고해 초기 제시가 참고값을 lamp 150→120, chair 260→210, bookshelf 340→300으로 낮췄다. 기존 값은 테스트가 포함된 중앙값이며 실제 시장 판매 영수증 중앙값도 별도로 참고했다. 최저가 100/180/260은 유지한다. 하네스가 실제 가격을 결정하며 최적 가격을 자동 계산한 결과가 아니다.

짧은 관측 구간에서 판매 5→6건, 평균 판매가 261.4→약 249.67, 점유율 0.006→0.005, 후기 1→4건, 별점 3→3이었다. 이 구간에는 변경 전 seller가 가동된 시간도 있어 가격 변경의 인과 효과로 해석하지 않는다. `SHOP-IMPROVEMENT.md`, `logs/challenge-1/`의 원본 복사 증거를 참고한다. 충분한 기간의 품목·예산·상대 구성을 통제한 전후 효과 분석은 아직 없다.

이후 가격 비교에 따른 별점 하락을 분석하고 사용자가 두 번째 실험을 승인했다. 첫 가격을 lamp 105, chair 195, bookshelf 280으로 낮추고 최저가 이상 제안의 즉시 수락과 숫자가 분리된 quote Part를 적용한다. 이 작업의 현재 검증·배포·평가 상태는 `SALES-EXPERIMENT.md`에 기록한다. 앞의 관측값은 첫 실험 기록이며 두 번째 변경의 효과로 해석하지 않는다.

두 번째 실험의 전체 소스·이벤트 조건을 포함해 공식 거래 검사 25/25를 다시 통과했고 2026-10-21 17:00 KST에 카드 0.4.0을 PC에 적용했다. 자기 가게 공개 진단은 시장 실적으로 제출하지 않았다. 초반 실제 거래 2건은 모두 3점이었으므로 아직 별점 개선을 확인하지 못했다. 모델 비용·사후 환급 전의 판매가−최저가와 buyer·품목·예산 구성도 함께 비교한다.

### 챌린지 2: 부정행위와 회피 — 미완료

확인 시 실제 구매 기억에 `receipt_mismatch`는 없었다. 따라서 직접 부정행위를 확인한 참가자 이름이나 그 경험으로 회피에 성공했다는 사례를 꾸며 넣지 않는다. 단위 테스트에서 불일치 보존과 제외 규칙이 작동한 것과 실제 시장에서 부정행위를 경험한 것은 다르다. 예산 부족·통신 실패·서명 누락만으로 부정행위라고 단정하지 않는다. `logs/challenge-2/`에 현재 관측의 한계를 남겼다. 실제 원본 합의와 영수증의 불일치 등 증거를 확보하고, 이후 선택에서 제외한 기록을 연결하는 학생의 판단과 검증이 남아 있다.

## 6. 운영 위치와 방식

추가 서버 구독 없이 현재 Windows PC에서 seller, buyer, 공식 market kit를 실행한다. Cloudflare Quick Tunnel은 공개 접속 경로이며 Cloudflare 서버에 Python 앱을 호스팅한 것은 아니다. 기존 OCI와 C-SERVER는 이번 과업에 사용하지 않는다. 시작 명령은 `run_market.py --tunnel`, 상세 운영·복구 절차는 `OPERATIONS.md`에 있다. 기존 이름·서명 키·구매 기억을 유지한다. 키와 owner code는 Git에 올리지 않는다.

키트 실행 중 자동 절전 방지 요청은 적용되어 있으나 PC 종료·수동 절전·네트워크 단절을 견디지는 못한다. 재부팅 자동 시작과 장애 자동 복구는 설정하지 않았다. 확인 시점의 실행 PID는 35724이며 실제 공개 주소는 증거의 카드 및 `.market/process.json`과 시장의 최신 등록을 참고한다. `check_always_on.py`는 읽기 전용 점검 후 매번 새 시각 디렉터리에 증거를 남긴다. 최초 제한 환경에서는 로컬 프로세스 명령행을 읽지 못했고 권한을 갖춰 재확인한 뒤 정상 실행을 확인했다. 원본 실패도 보존했다. 제출 이후에도 기한까지 PC 전원과 인터넷을 유지해야 한다.

별도로 사용자 요청에 따라 후기 환급 이벤트를 공지했다. 10월 21일 09:51~28일 09:51 KST 내 구매·4~5점 후기 등록, 금액·단위 개별 합의, 10월 29일 외부 일괄 수동 지급 조건이다. 아직 지급을 실행하지 않았으며 별점의 자연스러운 증가나 이벤트 효과를 입증하지 않는다. 상세는 `REVIEW-EVENT.md`에 있다.
