# 구매 후 한 달 이내 전액 환불

사용자 승인에 따라 신규 5점 약속 최저가 이벤트를 종료하고, 제품에 만족하지 못하면 구매일로부터 1개월 이내에 실제 구매 금액 전액을 환불하는 이벤트로 교체했다. 별점·후기 작성·후기 수정은 조건이 아니다. 일반 가격과 협상 최저가는 유지했다.

## 대상과 기한

- 0.9.0 가게의 새 보증을 받고 구매한 건이 대상이다. 첫 실제 배포는 2026-10-22 16:50:10 KST이며 이전 구매를 소급 적용한 것으로 표시하지 않는다.
- 구매 대상 기간은 기존 종료일인 2026-10-28 09:51 KST까지다. 별도 종료일 선호를 요청했으며 답변 전에는 기존 날짜를 유지한다고 안내했다.
- 신청 기한은 구매 시각으로부터 달력상 1개월 뒤 같은 날짜·시각까지(포함)다. 같은 날짜가 없으면 다음 달 마지막 날 같은 시각까지다. 예: 10월 31일 12시 → 11월 30일 12시. 시간대는 KST다.
- 금액은 원본 영수증의 실제 구매액 100%이며 거래와 같은 금액 단위다. 후기 조건·환율·공제를 추가하지 않는다.
- 불만족 사유와 원본 서명 영수증으로 신청하고 실제 구매·구매자 본인 확인 후 외부 수동 방식으로 지급한다. 자동 송금이나 시장 결제 취소 기능은 없다. 지급일을 임의로 약속하지 않았다.
- 구매 때 제시한 조건과 기한은 별도 서명 보증서로 보존한다. 이벤트 종료나 정책 변경이 이미 발급된 보증서의 기한을 줄이지 않는다. 이벤트 기간에 보증을 제시한 열린 협상도 그 조건을 유지한다.

## 안내와 신청

공개 카드·quote data에는 전체 조건을 표시하고 가격 응답에는 `Full refund within one calendar month if dissatisfied. No review required.`를 표시한다. 가격을 읽는 buyer가 혼동하지 않도록 텍스트 숫자는 가격 하나만 남긴다. 제품 보증·배송·수리 등 지원하지 않는 별도 서비스까지 보장하지 않는다.

구매 영수증의 기존 5개 필드와 서명은 유지한다. 별도 `refund_coverage` artifact에 구매 시각·환불 기한·금액·조건·`sig_terms`를 첨부한다. 같은 공개 A2A 주소에 `A2A-Version: 1.0`으로 새 SendMessage를 보내 신청한다. 새 요청에는 원래 구매 taskId를 taskId로 재사용하지 않고, 아래 data Part의 receipt에 원본 구매 task를 넣는다.

```json
{
  "kind": "refund_request",
  "receipt": {"shop": "원본 값", "item": "lamp", "price": 105, "task": "원본 구매 task", "sig_seller": "원본 서명"},
  "reason": "제품에 만족하지 못했습니다"
}
```

원본 보증서·영수증 일치·서명·기한을 확인해 `pending_buyer_and_market_verification`으로 접수한다. 접수는 지급 완료가 아니다. 동일 구매의 중복 신청은 같은 claim ID와 최초 접수 시각을 보존한다. 기한 내 접수한 건은 나중 조회 시 기한이 지났다는 이유로 취소하지 않는다. 변조 영수증·미보증 구매·기한이 지난 최초 신청은 지급 대상으로 자동 등록하지 않는다.

## 사람이 해야 할 지급

1. 제출 폴더 Python으로 `list_refund_requests.py`를 실행해 진단을 제외한 신청을 확인한다. 상주 알림은 별도로 설치하지 않았다.
2. 시장 원장의 task·구매자·품목·가격·서명 검증된 실제 거래를 확인한다. 공개 영수증을 복사한 사람이 아닌 구매자 본인인지 확인하고 외부 지급 수취인을 정한다. 별점이나 후기 변경을 요구하지 않는다.
3. 구매액 전액을 직접 지급하고 task·claim ID와 실제 지급 증빙을 별도로 보존한다. 원본 `logs/refund-requests/`와 `logs/refund-coverage/`는 수정하지 않는다. 계좌·인증 정보는 공개 저장소나 공개 A2A에 넣지 않는다.

신청 원본의 `paid: false`는 접수 당시 상태다. 실제 지급한 뒤 원본을 고쳐 쓰지 말고 별도 지급 증빙을 함께 확인해 중복 지급을 막는다.

## 기존 약속과 검증

`review_event.json`은 신규 참여 중단 상태다. 기존 약속 이벤트 원본은 `review_event_promise_legacy.json`, 그 이전 4~5점 후기 후 환급 원본은 `review_event_legacy.json`에 보존했다. 이미 성립한 할인·환급 약속과 기존 10월 29일 지급 약속은 취소하지 않는다.

로컬 검사 46개와 공식 전체 거래 검사 25/25가 통과했다. 달력상 월말·연말 경계, 기한 포함, 기한 후 중복 조회, 조건 보존, 변조·미보증 구매 거절, 접수와 지급 구분, 기존 서명·예산·가격 보호를 검증했다. 공식 원본은 `logs/shop-improvement/market-test/20261022T074848266845Z/`에 있다.

공개 진단에서 lamp 105 구매 후 영수증과 환불 보증서의 서명을 검증했다. 환불 신청과 중복 신청은 같은 claim ID이며 `paid: false`다. 진단 구매·후기·환불 지급은 시장 실적으로 제출하지 않았다. 진단 claim `b9032252e8184c35a49a8f925e3943c2`는 실제 지급에서 제외한다. 최초 목록 조회는 진단 1건 제외, 실제 신청 0건이었다.

첫 배포 PID 19640의 공개 주소는 https://limits-worlds-distribute-lang.trycloudflare.com 이었다. 이후 원격 연결 종료 오류로 키트가 종료되어 사용자 요청에 따라 같은 코드·키·기억·보증 기록으로 재연결했다. 현재 주소와 복구 시각은 `logs/satisfaction-refund/recovery-verification-*.json`을 따른다. 다른 서버나 OCI·C-SERVER는 사용하지 않았다.

측정은 `measure_marketing.py --profile refund`, 신청 조회는 `list_refund_requests.py`로 한다. 실제 구매·신청·지급을 구분하며 아직 판매·별점 개선 효과를 입증한 것은 아니다.

복구 시 PID 40712로 2026-10-22 18:28:50 KST에 재실행했다. 공개 주소는 https://contributing-analysts-carol-milwaukee.trycloudflare.com 이다. 가게·buyer 생존, 카드 0.9.0과 환불 공지, 키·기억 유지를 확인했고 buyer의 실제 구매 원장 등록도 다시 확인했다. 자동 재시작 서비스는 추가하지 않았다.

복구 감사 도구의 첫 시도는 파일명 순서로 과거 `live-verification-first.json`을 선택해 assert가 실패했다. 시각이 포함된 검증 파일만 선택하도록 수정했으며 해당 실패 구현은 커밋 이력에 보존했다. 가게의 실제 공개 검증은 이 오류와 별개로 통과했다.
