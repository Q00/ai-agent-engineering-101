# 개선 알림

현재는 정기 30분 요약 외에 제어기 단계가 바뀔 때도 상태를 표시한다. 2시간 유휴 제한을 제거했으므로 추가 대기가 없는 복원 단계는 “추가 대기 없음·다음 훅에서 재검토”라고 표시한다. [현재 운영 범위](PROPOSAL-STATUS.md)를 따른다.

## 현재 동작: 순이익 목표와 실행 상태

11월 4일 사용자의 “알림이 오지 않는다” 요청을 점검했다. 실제 모니터링은 정상 실행 중이었으나 최초 조건을 충족한 개선 기록이 없어 알림 0건이었다. 알림이 종합 순위만 보던 부분을 **seller 순이익 1위 목표**에 맞췄다. 아래의 최초 176개 검사·종합 순위 설명은 초기 구현 이력이다.

- **상태 요약:** 30분마다 `[모니터링]` 한 줄을 키트 터미널과 `MONITORING-NOTICES.md`에 남긴다. 자료 검증 상태·로컬 자기 정산·순이익·관측 순이익 순위·실험 단계·다음 진단을 표시한다. 자료가 오래됐으면 정상 실적이라고 표시하지 않는다. 제어기의 다음 진단 전에도 새 restock 훅에서 알림 주기를 확인하므로 대기 단계가 알림을 막지 않는다.
- **순이익 개선:** 2시간 비교에서 자기 확정 정산이 10건 이상 늘고, 순이익이 `10만 또는 기준 순이익 절댓값의 5% 중 큰 값` 이상 증가했을 때 관측 개선으로 알린다. 순이익은 신선한 로컬 가게 잔고에서 초기 자본·파산 지원금을 뺀 값이다. 정책의 인과 효과로 단정하지 않는다.
- **순위·별점:** 목표의 순이익 순위가 2계단 이상 좋아지거나, 후기 5개 이상 추가 후 별점이 0.10 이상 오르면 2시간 비교 알림을 낸다. 순이익 1위가 확인되면 별도 목표 알림을 낸다. 종합 순위 상승을 순이익 순위 상승으로 해석하지 않는다.
- **실험 채택:** 기존 `keep` 최종 평가 통과 알림은 유지한다. 목표 변경·파산·정산 초기화 때는 비교 기준선을 새로 잡는다.
- **전달 오류:** 조용히 버리는 대신 `logs/notification-errors/`와 터미널 `[알림 오류]`에 표시한다. 거래·정책 발행은 유지한다. 파일·출력 뒤 상태를 확정하므로 출력 실패는 재시도할 수 있으나 비정상 종료 때 같은 알림이 반복될 수 있다.

최근 전체 알림은 `.market/latest-monitor-notice.json`, 상태 기록은 `logs/monitor-notices/`다. 실제 개선만 `IMPROVEMENTS.md`·`.market/latest-improvement.json`·`logs/improvement-notices/`에 남긴다. 개선이 없으면 개선 전용 파일이 없어도 정상이며 상태 요약 파일에서 실행을 확인한다.

**전달은 로컬 키트 터미널과 파일이다.** Windows 팝업이나 Codex 대화 자동 전송은 구현하지 않았다. 모니터링·알림의 LLM 호출은 0이며 키트 재시작 없이 적용된다.

검증: 전체 236개 검사 통과(`logs/notice-profit-heartbeat-all-tests.log`). 순이익·목표별 순위, 목표 변경 초기화, 상태 알림 30분 제한, 오래된 자료 표시, 전달 실패 재시도·오류 기록, 제어기 대기 중 알림 연결을 검증했다. **15:19:12 KST 실제 `[buyer] [모니터링]` 줄이 원본 kit 로그에 기록된 것을 확인했다**(`logs/notice-profit-heartbeat-live-check.log`). 이 시점의 순이익 약 811만·순위 17위는 관측 상태이며 개선 성과 알림은 아니다.

## 최초 구현 기록

자율 개선기 실행 후 의미 있는 개선을 짧게 공유한다. 다음 restock 훅부터 적용되므로 키트 재시작은 필요 없다. 관측·알림에는 LLM과 외부 전송을 사용하지 않는다.

- 정책 실험: 성숙 대기·표본·수익·환불 조건을 통과한 `keep`만 즉시 알린다. 실험 시작이나 중간 평가는 개선으로 알리지 않는다. 실험 ID로 중복을 막는다.
- 관측 실적: 최초 실행을 기준선으로 두고 2시간마다 비교한다. 순위 2계단 이상 상승 또는 신규 후기 5개 이상에서 별점 0.10 이상 상승 시만 알린다. 누적 매출 증가만으로는 알리지 않는다. 이는 정책 변경의 인과 효과를 증명하지 않는다.
- 오래된 자료·공개 ledger 기반 자기 평가에서는 관측 개선 알림을 생략하고, 파산·정산 카운터 초기화 시 기준선을 다시 잡는다.

알림은 **실행 중인 키트 터미널**에 `[개선 알림]`으로 나타나며, `IMPROVEMENTS.md`에 시간과 함께 추가된다. `.market/latest-improvement.json`은 최근 알림, `logs/improvement-notices/`는 개별 기록이다. 알림 파일은 첫 개선이 발생할 때 만들어진다. Windows 팝업이나 이 Codex 대화에 자동 메시지를 보내는 기능은 아니다.

restock 최종 JSON 형식을 유지하기 위해 stderr를 사용한다. 공식 키트가 이 출력을 터미널과 원본 실행 로그에 전달한다. 알림의 파일·출력 오류가 거래와 정책 보호 기능을 막지 않도록 격리했다.

검증: 전체 오프라인 176개 검사 통과(`logs/improvement-notices-all-tests.log`). 중복 억제·관측 간격·신규 후기 조건·파산 초기화·오래된 근거 제외·알림 장애 시 정책 발행 유지를 확인했다. 11월 4일 10:14 KST 실제 로컬 정산 180건, 순위 17위, 별점 4.61을 최초 기준선으로 등록했다(`logs/improvement-notices-activation.log`). 기준선 등록 자체는 개선 알림을 발생시키지 않는다.
