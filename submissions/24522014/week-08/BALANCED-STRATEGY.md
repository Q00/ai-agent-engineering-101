# R3 SHOP·BUYER 균형 회복 전략 — 2026-11-04

## 목표를 바꾼 이유

현재 목표는 **Players 종합 Top 3**다. seller 순이익을 보호하면서 SHOP ALL과 BUYER ALL을 함께 올린다. 이전 순이익 단독 목표와 하루 8회 연구 구매는 이력으로 보존한다.

공식 점수는 SHOP ALL = 순이익 백분위 50% + 매출 30% + 별점 20%, BUYER ALL = 잉여 50% + forum 30% + 거래 수 10% + 글 수 10%다. Players는 두 ALL의 합이다. 자체 추정 가중치로 공식 ALL을 대체하지 않는다.

11월 4일 13:57→18:02 관측에서 순이익은 7,043,696→9,551,064원으로 증가했지만 SHOP ALL은 .592→.569, BUYER ALL은 .618→.532로 하락했다. 합계 .109 하락 중 buyer가 .086(약 79%)을 차지했다. 절대 이익 증가만으로 상대 순위가 유지되지는 않는다. buyer 활동 축소가 유력한 병목이지만 상대 참가자의 성장과 점수 변화를 통제한 인과 분석은 아니다. 이는 적용 전 진단이며 변경의 성과가 아니다.

## 토큰과 비용

명확한 현재 가격 처리, 포럼 수집·생성·반응 분석, 후기 연결, 점수 기록, 보증 평가와 자율 제어는 LLM을 호출하지 않는다. 모호한 협상만 모델로 보내며 **시간당 최대 2개 주문, UTC 하루 최대 24개 주문**, 주문당 최대 3턴이다. JSON 재시도 최대 2회를 고려하면 buyer 의사결정 하네스 호출 상한은 하루 144회다. 실제 토큰은 입력 길이와 실행 결과에 따라 달라지며 seller 호출은 이 buyer 한도와 별도다. 480회 시도를 480회 LLM 호출로 계산하면 안 된다.

포럼은 기존대로 5분 수집·30분 분석이며 추가 LLM 호출은 없다. 게시 상한은 채우는 목표가 아니다. 실제 거래·유용한 내용과 시간 조건이 있어야 게시한다.

## 보증 실험의 손실 제한

인증된 A등급 비식품·일반 판매에만 적용한다. 가격 실험 중에는 새 보증 실험을 배정하지 않는다. 가격은 `floor((원가+누적 보관비)/0.8)+1` 이상이어야 한다. 20% 전액 환불 스트레스에서도 차익이 양수인 조건이며, 실제 불량률을 20%로 추정한다는 뜻이 아니다.

보증 견적 및 서명 영수증의 **판매가 전액**을 준비금으로 묶는다. 신규 배정 후 책임액은 잔고 10%·100만원 중 작은 값 이하여야 하며, 별도로 기본 현금 100만원(초기 자본 20%)과 재고 7일 보관비를 남긴다. 보증 종료는 실제 정산 시각도 반영하고 결과 미확정 결제는 계속 확보한다. 10분 견적 만료 시 새 요청을 요구하며, 실험 중단 후에도 이미 약속한 보증은 지킨다.

30분마다 정산 후 6시간 이상 지난 같은 SKU의 대조군을 비교한다. 보증 판매에서 명시적 환불을 관측하거나 양쪽 각 3건 이상에서 평균 차익이 대조의 90% 미만이면 새 배정을 중단한다. 공개 환불 표본은 불완전하므로 전체 고장률·인과적 이익 증명으로 보지 않는다. 영구 보증 정책으로 자동 승격하지 않는다.

## 적용과 검증

267개 테스트 통과(`logs/balanced-validation-final.log`). 추가 20개는 잘못된 견적 해석, 모델 일/시간 한도, 후기 오귀속, 오래된 자료, 보증 현금·마진·만료·약속 유지, 실제 seller 영수증과 종합 점수 악화 복원을 검사한다. 외부에 시험 결제를 만들지 않았다.

짧게 실행되는 buyer/restock/review 훅은 새 파일을 읽는다. **상주 seller의 영수증·보증 변경은 키트 재시작 1회가 필요하다.** `.market/strategy-consumer.json` features에 `actual_grade_receipt`, `bounded_warranty_v1`이 있어야 새 seller다. 기존 heartbeat만으로 새 코드 적용을 주장하지 않는다.

사용자의 추가 요청으로 일일 실험 한도를 **2회→6회**로 늘렸다(UTC 날짜 기준, 재입고 예산 시험과 공유하는 제어기 한도). 이미 실행한 횟수는 초기화하지 않으며, 동시 1개·가격 변경 최대 3%·기준선 2시간·시험 2시간·성숙 확인 6시간·현금 보호는 유지한다. 따라서 매일 6개 완료를 보장하는 설정은 아니다. `daily_trial_limit`은 실험 한도이며 제거한 2시간 유휴 대기와 다르다. 적용 후 양쪽 ALL·순위·잉여·매출·별점·차익·환불을 함께 비교하며, 점수 개선은 아직 확인되지 않았다.
