# 정산 결과 연결

`settlement_memory.py`는 기존 buyer-memory.jsonl을 덮어쓰지 않고, R3 주문별 payments.jsonl을 읽어 선택 시 사용하는 기억의 사본을 보정한다. 합의 완료만 있고 결제가 없으면 awaiting_payment, 결제 거부는 payment_refused와 사유, 가게·SKU·가격이 다르면 payment_record_mismatch로 구분한다. 일치하는 paid=true와 ledger가 있어야 market_settled로 표시한다.

과거 R2 기록은 주문 필드가 없어 이번 연결 대상에서 제외한다. 거부 자체를 영수증 사기라고 간주하지 않는다. 선택 시에는 이미 적용한 정책대로 서로 다른 SKU의 과거 가격을 직접 비교하지 않는다. 원본 관측과 키트의 결제 결과를 연결한 것이며 시장 서명을 새로 검증한 것은 아니다.

현재 공개 계약은 고장 파일에 이름과 시각만 제공하므로 같은 이름의 구매를 정확히 구분할 수 없는 사례가 있다. 고장·검수·반품률을 임의로 채우지 않는다. 정산 후 후기 기준은 사용자에게 질문한 상태라 review 훅은 아직 추가하지 않았다. 이번 연결은 다음 R3 buyer 호출에서 실행되며 추가 키트 재시작은 필요 없다.

기존 검사와 정산 연결 검사 총 32개가 통과했다. 원본은 logs/settlement-memory-tests-20261102.log다. 실제 R3 자료로의 동작은 아직 미검증이다.
