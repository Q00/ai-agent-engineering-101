# R3 자율 개선 루프 — 구현과 운영

**현재 목표는 seller 순이익 1위**다. [순이익 중심 전략](PROFIT-FIRST-STRATEGY.md)에 따라 가격 인상·인하 모두 시간당 원가 차익 개선을 요구한다. 거래 수 증가만으로 차익 감소를 허용하던 최초 Top 3 기준은 현재 목표에서 사용하지 않는다. 순이익 Top 3의 동일 조건 거래를 비교 근거로 연결했고, 목표 변경 시 기존 목적의 진행 실험을 종료했다. 상위권 공개 조회는 별도 `leader_monitor.py`가 30분마다 수행하며 제어기 자체는 로컬 자료만 읽는다.

사용자가 요청한 `병목 진단 → 작은 정책 변경 → 효과 평가 → 악화 시 복원`을 `strategy_controller.py`에 구현했다. `strategy_controller.json`의 enabled=true로 제한된 자동 실행을 켰다. 모델·네트워크를 추가 호출하거나 코드를 자동 수정하지 않는다. 초기 기준선 수집 후 비교 후보 대기로 진행했다. 11월 4일 자기 거래 자료를 `local_acp_v1`로 전환했고, 장기 개선 효과는 아직 확인하지 않았다.

최신 보완은 [LOCAL-SELF-EVIDENCE.md](LOCAL-SELF-EVIDENCE.md)에 있다. 자기 정산 수·매출·실험 거래는 로컬 ACP 확정 정산을 사용하며 공개 정산은 시장 가격 비교에 사용한다. 원가·SKU·실험 ID는 동일 unit의 서명 제안과 연결한다. 기존 표본·가격·품질 제한은 유지하며, 이전 표본 기반 기준선도 로컬 자료로 맞춘다.

## 실행 흐름

`30분 관측 → R3 기준선 → 비교 가능한 병목 후보 → 한 정책 실험 → 기존 정책 복귀 → 거래 성숙 대기 → 유지 또는 복원`

1. 실행 중인 restock 훅이 제어기를 호출한다. 정상 진단은 30분 간격이며 현금·자료 오류 등 안전 조건은 훅 호출 때 먼저 확인한다.
2. 최소 2시간의 R3 관측과 그 사이 가게 정산 10건을 기다린다. 같은 캐시를 반복 읽은 것을 독립된 관측으로 추가하지 않는다.
3. 같은 SKU·등급·무보증 거래 가격과 현재 재고의 정책 견적을 비교한다. 비교 가격 3건 이상, 자기 가게의 같은 조건 정산 3건 이상이 있어야 SKU 가격 실험을 시작한다. 비교 가격은 시장 전체가 아닌 제한된 표본이다.
4. 한 번에 하나만 실험한다. 2시간 실험 창이 닫히면 우선 직전 정책으로 복귀하고, 창 안에 정산된 거래를 고정해 최소 6시간 더 기다린다. 정상 유지 판정까지 시작 후 약 8시간 이상 걸린다.
5. 같은 조건의 실제 정산 수·원가 기반 차익과 가게 운영 지표로 평가한다. 개선이 확인되면 후보 정책을 다시 적용하고, 악화·자료 부족이면 직전 정책을 유지한다. 12시간 안에 평가하지 못한 실험도 복원한다.

자동 변경은 UTC 하루 최대 2개 실험, 새 실험 사이 최소 2시간이다. 복원과 현금 보호는 이 간격을 기다리지 않는다. Top 3에 이미 들어간 관측에서는 새 실험보다 유지에 우선한다.

## 자동으로 바꿀 수 있는 값

| 대상 | 한 번의 변경 | 전체 범위 |
|---|---|---|
| 특정 SKU의 비식품 견적 | 현재 배율에서 최대 ±3% | 기본 견적의 94~103%, 일반 가격 하한·정가 상한 적용 |
| 재입고 예산 비율 | 잔고 대비 1%p 축소 | 잔고 2~5% |
| 안전상 재입고 일시 중단 | 준비금 미달·관측 실패 시 적용 | 기존 현금·재고 제약과 함께 사용 |

식품·인증 A/B·배송/안전 시간·예산 검사·서명·보증 조건·원가 및 보관비 하한은 자동 변경 대상이 아니다. 손실 회수 할인 단계에는 견적 실험을 덧씌우지 않는다. buyer 구매 조건과 포럼 게시 빈도는 이번 초기 제어기의 실험 대상에 포함하지 않았다. 포럼·buyer 구매 패턴은 진단 근거로 기록한다.

SKU 견적은 관측 중앙값보다 5% 이상 높거나 낮을 때 검토한다. 장기 재고가 3개 이상이고 재고 원가가 잔고의 20%를 넘으면 재입고 비율 축소를 검토한다. 두 종류를 동시에 시험하지 않는다. 이미 수락된 정책은 유지하며 새 실험의 직전 정책을 별도로 보존한다.

## 평가와 복원 조건

- 인하 실험: 같은 SKU·등급·무보증 정산 속도가 5% 이상 늘고 시간당 매매차익 감소가 10% 이내인지 확인한다.
- 인상 실험: 시간당 매매차익이 5% 이상 늘고 정산 속도 감소가 10% 이내인지 확인한다.
- 재입고 축소: 실험 종료 시 재고 원가가 줄고 정산 속도가 허용 범위 안인지 확인한다.
- 공통: 실험 기간 가게 정산 10건 이상이 필요하고 SKU 실험은 전후 각 3건 이상이 필요하다. 가게 운영 지표도 악화 허용 범위를 넘으면 채택하지 않는다.
- 현금 준비금 침범, 후기 5건 이상 추가 후 표시 평점 0.10 이상 하락, R3 카운터 초기화·파산은 복원 조건이다. 2시간 후 충분한 정산 표본에서 운영 성과가 크게 악화돼도 먼저 복원한다.
- 명시적 환불이 실험 대상 unit에 연결되면 낙관적 차익으로 채택하지 않는다. 결제 거절과 A2A 합의는 실험 정산으로 세지 않는다.

가게 운영 지표는 `현금 + 재고 원가 − 시작 자금 − 지원금`의 변화도 함께 본다. 재입고 지출만으로 공식 순이익이 감소한 것을 곧바로 영업 악화로 오인하지 않기 위한 원가 기준 보조값이다. 미판매 재고의 실현 가능한 가치를 보증하지 않으며 공식 순위 점수와 다르다. 시장·시간대·상대 행동이 바뀌므로 전후 비교를 인과 효과로 확정하지 않는다.

## 실제 적용과 재시작

기본 정책 파일 `r3_policy.json`을 수정하는 방식이 아니라 `.market/strategy-policy.json`의 제한된 실행 값을 읽는다. seller는 매 견적에서 유효한 실행 값을 확인하고 하한을 다시 적용한다. 같은 단가의 여러 제안 중 어떤 실험에서 결제됐는지 모호하면 실험 효과 입증에서 제외한다. 실제 서명 제안에 정책 버전·실험 ID·unit 원가를 남긴다.

이미 실행 중인 restock 훅은 새 제어기를 읽지만 **상주 seller는 새 코드 적용을 위해 키트 재시작 1회가 필요하다.** 새 seller의 protocol=1 heartbeat가 확인되기 전에는 가격 실험을 시작하지 않는다. 기존 claim code가 설정된 터미널에서 다음을 실행한다.

```powershell
& ./submissions/24522014/week-08/.venv/Scripts/python.exe -X utf8 -u ./submissions/24522014/week-08/run_market.py --tunnel
```

실행 값의 유효기간은 최대 1시간이며 새 관측으로 갱신한다. 오래되거나 손상된 실행 값은 기본 제약으로 돌아간다. 자료가 오래되면 진행 실험을 복원하고 신규 매입을 보류한다. 상태는 파일로 보존하고 OS 파일 잠금으로 중복 작성자를 막는다. 프로세스가 종료되면 OS 잠금이 풀리므로 재시작 시 이어서 평가할 수 있다.

## 기록과 끄기

- `.market/strategy-state.json`: 기준선·활성 실험·직전 값·평가 창·현재 단계.
- `.market/strategy-policy.json`: 실제 적용 값·버전·유효기간·실험 ID.
- `.market/strategy-consumer.json`: seller가 새 실행 값을 읽는지 확인하는 heartbeat.
- `logs/strategy-controller/`: 진단·시작·창 종료·유지·복원과 근거를 새 JSON으로 보존.

`strategy_controller.json`의 enabled를 false로 바꾸면 다음 훅에서 기본 정책으로 복원한다. 이 중단 경로는 시장 관측 파일이 손상돼도 실행된다. 제어기 자체의 관측·판단·기록에는 LLM을 호출하지 않는다.

## 검증

로컬 자기 정산 연결 후 전체 168개 검사가 통과했다(`logs/local-self-evidence-all-tests-final.log`). 실제 로컬 정산 176건 모두 원가 연결을 확인했다. 아래 154개 결과는 최초 구현 시점의 이력이다.

전체 오프라인 154개 통과: `logs/strategy-controller-all-tests-release.log`. 추가 22개는 정상 실험→성숙 대기→채택, 차익 악화·불충분 표본 복원, 현금·별점 보호, 반복 캐시·R2 상태 제외, 운영 중단, 카운터 초기화, 환불·기한 초과, 적용 값의 한도·유효기간·가격 하한·식품 유지, 실제 restock 예산 반영, 파일 상태 복구·OS 잠금, 모호한 영수증 귀속 제외, 실제 seller의 견적·서명 ID 연결을 검증한다. 별점 보호가 정상 30분 진단 간격을 기다리지 않고 다음 훅에서 실행되는 것도 확인했다.

첫 상태 전이 검사에서는 이벤트 이름 인자와 세부 필드 이름이 충돌해 실패했다. 수정 후 통과했으며 `logs/strategy-controller-tests-first.log`를 보존했다. 실제 파일로 실행한 초기 상태는 collecting_baseline·price_consumer_ready=false·model_calls=0이다(`logs/strategy-controller-live-status.log`). 실제 시장에서 8시간 이상 실험을 완료한 성과는 아직 없다.
