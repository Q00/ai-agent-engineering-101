# 영수증 표기 수정 확인 (2026-11-06)

구매자가 카테고리로 주문한 거래의 영수증 `item`에 그 카테고리 이름을 넣도록 고쳤습니다. 키트 경로는 안전하지만, q00 요청 원문이 기록에 없어 그 부분은 추론입니다. 재시작 전까지는 동작이 바뀌지 않습니다.

## q00의 표기 (공개 원장 저장 표본, 11-03 21:04~11-05 10:42 KST)

- **이름 영수증의 `item`:** 모두 주문의 카테고리 하위 분류 문자열입니다(예: 김치, 침구, 가공/조리 육류). q00의 결과 행 726건 중 SKU가 아닌 557건, 값 18종입니다.
- **별점:** SKU 영수증 169건은 전부 1점이고, 이름 영수증 557건은 평균 4.86입니다. 검증된 거래만 보면 SKU 102건, 이름 351건입니다.
- **우리 가게:** 표본 안의 q00 평가 4건은 모두 1점이고, 후기는 "Ordered 침구, receipt names G#" 형식입니다.

## 요청 원문은 확인하지 못함

- **기록 없음:** `seller_r3.py`는 요청 원문을 남기지 않습니다. `logs/pricing`에는 없고, `logs/seller`는 옛 판매 코드의 기록입니다.
- **추론 근거:** 이름 영수증을 쓰는 12개 가게의 영수증이 다른 buyer에게는 대부분 SKU이고 q00에게만 이름입니다. q00이 요청에 SKU를 쓰지 않는다고 보는 이유입니다. 다만 다른 가게의 코드는 볼 수 없습니다.
- **만약 q00이 SKU도 함께 적는다면:** 수정 후에도 SKU 영수증이 나가므로 효과가 없을 뿐, 손해는 없습니다.
- **앞으로의 기록:** 요청 형식(`sku`, `category`, `other`)을 `logs/pricing`과 `signed-offers`에 남깁니다. 원문은 남기지 않습니다.

## 키트 경로 (`scripts/market_kit.py`, 읽기만 함)

| 위치 | 확인 내용 |
|---|---:|
| 391-397 | 판매자가 지정한 `unit`을 찾습니다. `acceptable`이 있으면 SKU가 그 안에 있어야 하고, 없으면 SKU 또는 하위 분류가 `item`과 같아야 합니다. 카테고리일 때도 같은 단위를 찾습니다 |
| 407 | `line_items`의 id와 영수증 `item`이 같아야 하며, 키트가 `item`을 그대로 넣습니다 |
| 421 | `co.item`은 실제 SKU입니다. 카테고리 영수증이어도 체크아웃은 SKU를 담습니다 |
| 452 | 증명서는 `co.item`과 비교하므로 영향이 없습니다 |
| 511 | `co.item`이 영수증 `item`과 같거나 `acceptable` 안에 있으면 통과합니다 |
| 746 | 영수증 `item`이 주문 `item`과 정확히 같거나 `acceptable` 안에 있어야 서명합니다 |

**이름을 넣을 수 없는 이유:** 746행 때문에 상품 이름은 주문 `item`과 같지 않으면 서명되지 않습니다. 그래서 상품 이름으로 맞은 요청에는 지금처럼 SKU를 넣습니다.

**맞지 않는 주문:** 넣는 값은 구매자의 글자가 아니라 단위 자신의 카테고리입니다. 요청에 단어로 있을 때만 넣으므로 사실과 다른 이름이 들어갈 수 없고, 주문의 `acceptable`에 없는 단위는 키트가 체크아웃을 409로 거절합니다.

## 영수증 `item`을 읽는 우리 코드

- **판매 기록과 시세:** 공개 정산 행의 `item`과 `sku`를 쓰고, 이 값은 `co.item`이라 항상 SKU입니다. `signed-offers`도 `sku`를 그대로 저장합니다.
- **`low_star_monitor.py:105`:** SKU일 때만 `receipt_format`으로 분류합니다. 카테고리 영수증에 불만이 오면 다른 분류로 넘어갑니다.
- **`review_policy.py`, `market_buyer.py`, `r3_selection.py`:** 구매 쪽 코드라 우리 판매 영수증을 읽지 않습니다.
- **`satisfaction_refund.py`:** 영수증 필드를 그대로 서명합니다. 현재 판매 경로에서 호출되지 않는지는 이번 범위에서 확인하지 않았습니다.
