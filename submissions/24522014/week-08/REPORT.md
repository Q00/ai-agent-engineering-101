[architecture.tex](architecture.tex)가 원본이고 [architecture.pdf](architecture.pdf)가 한 페이지 결과입니다. 회색은 수업이 제공한 부분, 파랑은 우리 결정 코드, 초록은 코드 제약, 주황은 모델입니다. 실선은 실행, 점선은 다음 결정으로 돌아오는 기억입니다. 보라색 점선 상자는 저장소 밖의 승인 운영 루프입니다. 11-14 설정으로 다시 빌드했습니다(`24581572`, `logs/architecture-build-20261114.log`). 마감 전에 설정이 바뀌면 다시 빌드합니다.

| | 키트 기본형 | 우리 구조 |
|---|---|---|
| 판매 결정 | 스타터는 "harness가 모든 수를 결정" | 규칙이 결정합니다. 모델은 설정으로 켤 때만 씁니다 |
| 구매 결정 | 모델이 협상 | 선택 → 하한 → 규칙 → 게이트 → 모델 순서의 사다리입니다. 대부분 모델 전에 끝납니다 |
| 모델 장애 | 해당 harness 실패 | agy → Codex → 규칙. 어느 단계가 죽어도 거래는 계속됩니다 |
| 재입고 | 명령이 없으면 무작위 | 근거와 현금 한도가 있는 정책입니다. 1M 이상 전용 칸, 중간 가격대 칸, 시험 경로가 서로 한도를 나눠 씁니다 |
| 기억 | 키트가 상태 파일과 훅만 제공 | R3 전용 기억, 정산 연결, 고장 귀속, A/B 결과, 시장 관측 |
| 정책 변경 | 사람이 코드 변경 | 저장소 안에서는 제어기가 작은 실험을 합니다. 저장소 밖에서는 승인, 되돌릴 조건, 유지 시험이 있는 운영 루프가 설정을 바꿉니다 |

독창성의 핵심은 두 가지입니다.
1. **모델을 줄였습니다.** 측정해서 모델이 하던 일을 코드로 옮겼고, 모델은 규칙이 못 읽는 응답에만 남겼습니다.
2. **설정 변경을 시험으로 만들었습니다.** 변경마다 되돌릴 조건을 먼저 정했고, 그래서 실패한 시도(4절)도 몇 시간 안에 되돌렸습니다.

이 구조가 순위에 유리하다는 대조 실험은 없습니다.
