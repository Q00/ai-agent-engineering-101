# seller 순이익을 지원하는 선택적 buyer

사용자 요청에 따라 buyer를 거래 수 최대화에서 **판매 전략에 필요한 정보 수집**으로 전환했다. 상대의 파산을 목표로 하지 않으며, 정보 가치가 없거나 불리한 거래를 줄인다. buyer 예산은 시장이 발급한 주문 예산이고 seller 잔고와 별도다. buyer 축소를 seller 현금 절약으로 계산하지 않는다.

## 구매를 검토하는 조건

- 현재 보유 재고, R3 자체 판매 이력 상위 10개 SKU, 신선한 순이익 Top 3의 반복 판매 SKU와 관련된 비식품을 조사한다. 카탈로그 가치 3만 이상을 초기 대상으로 둔다.
- 인증 A/B, 가치·주문 예산 상한, 보증 조건과 영수증·서명·정산 검사를 유지한다. 알려진 불량이 있는데 보증을 강제할 수 없는 후보와 반복 통신 장애·영수증 불일치 후보는 제외한다.
- 같은 가게·SKU를 최근 6시간 안에 조사했거나 구매했다면 반복하지 않는다. 최근 1시간의 같은 등급·보증 공개 정산 3건 이상이 있으면 새 구매 없이 해당 정보를 사용한다. 중복 ledger는 표본 수에 더하지 않는다.
- 이미 확인한 가격이 가치 상한을 넘으면 협상하지 않는다. 유효한 가격 참고가 있으면 기존 가치 상한과 참고가의 102% 중 낮은 값으로 협상 한도를 제한한다. 과거 가격이 현재 견적을 보장하지는 않는다.

## 경쟁 가게를 고르는 방식

기본은 품질·위험·가격 조건이다. 그다음 **같은 SKU·관측 등급·관측 보증·요구 보증·불량 위험 구분**이고, 관측 가격이 카탈로그 가치의 2% 이내 차이인 경우 순이익 Top 3 외 가게를 우선한다. 양쪽에 유효한 가격 근거가 있어야 한다. 알려진 대체 가격이 나쁘거나 대체 가게 가격이 미상이면 선두 가게를 무조건 배제하지 않는다. 경쟁 가게 목록이 1시간 넘게 오래됐으면 이 구분을 사용하지 않는다. 같은 GitHub 주인의 가게는 구매 후보에서 제외한다.

## 실행 상한과 비용

`buyer_support.json`: **시간당 최대 1회·UTC 하루 최대 8회·협상 최대 3턴**이다. 실제로 시작할 시도만 OS 잠금 안에서 예약해 중복 실행·동시 주문이 한도를 초과하지 않게 한다. 실패·결제 대기 시도도 사용한 조사 슬롯으로 남긴다. 새 UTC 날짜여도 시간 간격은 유지한다.

선택·건너뛰기·보고는 Python 규칙이며 LLM 호출이 없다. 실제 협상은 기존 모델을 사용한다. 의사결정 응답 재시도 1회를 포함하면 새 buyer의 코드상 의사결정 호출 상한은 정상 설정에서 하루 8×3×2=48회다. 실제 과금 토큰은 응답 길이·실패·서비스 동작에 따라 달라진다. seller의 협상 호출은 별도다. 건너뛰면 빈 shop·receipt=null 결과를 반환하며 거래 성공이나 후기를 만들지 않는다.

현재 seller가 식품 공급을 보류하므로 buyer 연구도 비식품에 집중한다. 기존 식품 구매 안전 조건 함수는 유지한다. config의 enabled=false는 buyer 연구를 중단하며 과거의 무제한 구매 전략으로 돌아가지 않는다.

## 연구 결과가 판매 전략에 들어가는 경로

1. 예약 기록을 키트의 `payments.jsonl`과 연결하고 paid=true·실제 ledger·주문·가게·SKU·가격·상한 일치를 확인한다.
2. 사후 `buyer-deals/<ledger>.json`의 실제 등급·보증을 연결한다. 고장·환불이 관측된 거래는 긍정적인 가격 참고에서 제외한다.
3. 최근 1시간의 확정 연구 가격을 `purchase_monitor.py`의 **외부 가격 비교**에 보충한다. 공개 ledger와 번호가 겹치면 한 번만 세고 공개 기록을 우선한다. 공개 이벤트 시각이 없으면 로컬 결제 후 review 시각이라고 명시한다.
4. 같은 등급·보증 그룹에서 우리 판매 기준가를 비교하는 데 사용한다. 현재 무보증 seller에 보증 6시간 가격을 같은 조건으로 적용하지 않는다. 자기 seller 판매 건수·매출·실험 평가에는 계속 로컬 ACP 자기 정산만 사용한다. 연구 구매를 시장 전체 수요 검증으로 확대하지 않는다.

## 기록과 현재 결과

- `.market/buyer-support-state.json`: 최근 조사 예약·주문·선택 당시 경쟁 가게 여부.
- `logs/market-buyer/`: 선택·제외 이유, 실제 협상 결과, 지원 모드와 자금 출처 구분.
- `.market/buyer-support-summary.json`, `logs/buyer-support/`: 30분마다 확정 구매와 상대 가게에 지급한 주문 예산을 요약한다. seller 순이익 기여를 증명했다고 표시하지 않는다.
- `purchase-intel.json`의 research_price_rows: 외부 가격 자료로 보충한 연구 거래 수.

새 buyer 실행부터 적용돼 키트 재시작이 필요 없다. 기존 진행 중인 협상은 이전 설정으로 끝날 수 있다. seller의 재고 수량·가격·보증은 이번 작업에서 확대하지 않았다.

11월 4일 실제 최초 연구 1건은 `G1515d951`을 305,000에 구매한 B등급·보증 6시간 거래였다(ledger 2400818, 선택 상한 328,536). 선택 당시 순이익 Top 3 밖의 가게였으며 그 시점 선두 가게들에 지급한 금액은 0이었다. 이 금액은 buyer 주문 예산 지출이며 seller 잔고 차감이 아니다. 현재 1건으로 판매 이익 개선을 단정하지 않는다(`logs/buyer-support-activation.log`).

전체 오프라인 228개 검사 통과(`logs/buyer-support-conditions-release-tests.log`). 실제 CLI의 무거래·모델 미호출, 가격·품질·동일 조건 대안, UTC·일/시간/쌍 한도, R2·오래된 정보 제외, 확정 결제 연결·공개 ledger 중복 제거를 확인했다. 상태 갱신은 OS 잠금 안에서 중복·한도를 다시 확인한다. 최초 통합 검사에서 이전의 소액·식품 자동 구매 기대와 새 연구 범위가 충돌했다. 소액 fixture는 실제 연구 조건에 맞췄고 식품은 거래 보류와 안전 조건 유지로 검증했다. 최초 실패 로그는 보존했다.
