# R3 계약 연결: 기본 동작 검증

## 구현과 출처

`seller_r3.py`는 공식 upstream d4b4d53e의 `scripts/starter_round3/seller.py`를 복사해 수정했다. 재고에서 SKU·카테고리·이름에 맞는 unit을 선택하고, expired 표시와 다른 협상에서 예약 중인 unit을 제외하는 기본 동작은 수업 코드다. 원가 아래 가격을 막고 unit을 영수증에 포함하는 것도 기본형 동작이다. 이 부분을 자체 독창성으로 주장하지 않는다.

자체 연결은 `r3_harness.py`다. 기존 하네스의 gpt-6-luna 호출과 원본 입출력 로그를 이용하고 ask/counter 행동 이름을 변환한다. 모델 실패는 거래 실패로 기록하며 호출은 별도 스레드에서 수행한다. 이 어댑터의 실제 모델 호출은 아직 확인하지 않았다.

buyer는 비어 있지 않은 SKU를 받을 수 있게 수정했다. `--order`를 받으면 주문 품목·예산과 명령 인자가 같은지 검사하고, acceptable에 포함되며 재고 수량이 양수인 offer만 후보로 삼는다. 서로 다른 SKU의 과거 가격은 직접 비교하지 않는다. 가게 선택 뒤 SKU 이름순으로 한 상품을 고르는 것은 계약 연결을 위한 임시 기본 선택이며 수익·품질 최적화 정책이 아니다. 결과에 인증서 요구와 식품 use_within_hours를 넣어 키트가 결제 전 확인하게 한다. 구매 기억의 purchased는 A2A 완료 기준이며 정산 완료와 동일시하지 않는다.

## 검사와 적용 상태

`test_r3_contract.py`는 SKU 허용과 예산 초과 거절, 재고 필터, 주문의 SKU와 식품 결제 제약 연결을 모델 없이 확인한다. 기존 검사와 합해 19개가 통과했다. 원본은 `logs/r3-contract-tests-20261102.log`다. 실제 Round 3 주문·정산 성공을 입증하는 검사는 아니다.

설정 후보는 `agent-r3.json`에 있다. 실행 중인 키트는 기존 `agent.json`을 시작 때 읽었으며 새 seller 설정은 아직 활성화하지 않았다. 새 seller의 Round 2 가격 결정은 기존 자체 seller와 다를 수 있다. 활성화 시점과 전략을 결정한 뒤 설정을 적용하고 재시작한다.

## 다음에 결정할 핵심 전략

1. 공급: 기본 무작위 공급을 유지할지, 관측 판매 수요에 근거한 소량 공급으로 바꿀지. 초기 보유금과 식품 폐기·상품 보관비를 함께 고려한다.
2. 판매: 원가를 항상 지킬지, 유통기한 임박 식품에는 손실 제한 판매를 허용할지. R3 규칙은 원가 미만 판매를 허용한다.
3. 구매·평가: SKU 가치·품질·보증을 선택과 정산 후 후기에 어떻게 반영할지. 게시판 판단에는 실제 정산 근거와 추정을 구분해야 한다.

기본형에는 재고 파일의 갱신 지연과 협상 중 재고 변경 위험이 남아 있다. 최종 재고·증명서·식품 사용기한 검증은 키트와 시장의 정산 단계에서도 확인한다.
