# R3 순위 관측 기반 자율 개선 루프 제안

상태: 아래는 최초 설계 제안의 이력이다. 이후 사용자가 구현을 승인해 제한된 정책 실험·평가·자동 복원을 구현하고 enabled=true로 연결했다. 최신 범위·유효기간·초기 대기와 검증은 [STRATEGY-CONTROLLER.md](STRATEGY-CONTROLLER.md)를 따른다. 아래 제안 중 buyer 조건·게시글 간격 변경은 초기 구현에 포함하지 않았다. 경쟁자와 수요가 변하므로 Top 3 진입을 보장하지 않는다.

## 목표와 판단 순서

1. 파산 위험을 제한하는 현금·보관비·환불 준비금 조건을 먼저 만족한다.
2. 가게·buyer 각각 R3 정산 20건 조건을 확인한다.
3. 공식 Players 3위와 내 점수 차이를 관측한다. 공식 점수 필드가 없으면 추측 순위를 만들지 않는다.
4. 가게 순이익·매출·별점 및 buyer 잉여·게시판 평가·거래 수 가운데 개선 여지가 큰 항목을 찾는다.
5. 작은 정책 실험 하나를 실행하고, 결과가 확인될 때까지 다른 변경을 겹치지 않는다.

R2 거래·후기·가게 선호·가격·순환 구매 규칙은 입력에서 제외한다. 같은 owner의 자기 가게 구매는 시장 규칙상 불가능하며 실험 대상도 아니다.

## 제안 구조

`관측기 → 진단기 → 실험 선택기 → 제한 검사 → 정책 버전 저장 → 실행 → 평가 → 유지/복원`

관측기는 현재 `market_intel.py`를 확장한다. 30분마다 공개 시장과 자체 정산을 요약한다. 순위뿐 아니라 현금, 자금 회수 시간, 미판매 재고 원가, 문의→정산 비율, 결제 거절 원인, 실제 보관비·환불도 수집한다. 자료가 오래되거나 수집 실패하면 관측 실패를 기록하고 공격적인 정책 변경은 보류한다.

진단기는 먼저 코드 규칙으로 원인을 좁힌다. 모델은 필수 요소가 아니다. 작은 수치 요약으로도 판단 가능한 경우 LLM을 호출하지 않는다. 모델 조언이 필요한 정체 상황에만 제한된 요약을 보내고, 모델이 코드·서명·안전 조건을 직접 바꾸지 못하게 한다.

| 관측한 병목 | 실험 후보 | 먼저 제외할 원인 |
|---|---|---|
| 매출은 높고 순이익은 낮음 | 할인폭 축소, 회수 느린 SKU 매입 축소 | 보증 환불·재고 매입에 따른 잔고 감소 |
| 방문은 많고 정산은 적음 | 특정 SKU 견적을 3% 낮추는 소량 실험 | 서버 연결·예약 잠김·인증·checkout 실패 |
| 방문 자체가 적음 | 수요 근거 있는 다른 SKU를 소량 시험 | 재고 노출·등록 오류, 제한된 ledger 표본 |
| 별점 하락 | 거래별 원인에 맞는 상태 안내·조건 보완 | 누적 평균 변동과 최근 후기 원인 혼동 |
| buyer 잉여가 낮음 | 실거래 가격 대비 가치가 큰 SKU·보증 선택 | 고장·환불 반영 전 잠정 가치 |
| 게시판 평가가 낮음 | 실제 수요에 도움이 되는 정산 정보의 내용·빈도 조절 | 글 수와 유효 투표 수 혼동 |
| 현금이 준비금에 접근함 | 즉시 신규 매입 중단, 재고 회수 우선 | 파산 자금을 이익으로 오인 |

## 실험을 작게 유지하는 조건

- 관측은 30분, 정책 변경은 최소 2시간 간격으로 시작한다. 표본이 부족하면 더 기다린다.
- 첫 실험은 가격 3% 조정처럼 한 SKU의 한 변수만 바꾼다. 초기 최소 정산 표본은 10건을 제안하되 이는 검증 전 설정이다.
- 보관비·보증·고장 손실을 평가한다. 비식품의 최종 성과 판단은 가능하면 판매 후 6시간을 지난 거래로 한다. 즉시 보이는 잉여를 확정 이득으로 계산하지 않는다.
- 비슷한 SKU·등급·가격대의 관측과 비교하고 시간대·시장 수요 변화도 기록한다. 단순 전후 차이를 인과 효과로 단정하지 않는다.
- 나빠지면 자동 복원한다. 현금 준비금 위반은 즉시 중단 조건이며, 별점·정산 전환율 악화는 충분한 표본과 함께 판단한다.
- 바꿀 수 있는 값은 가격·매입 수량·탐색 비중·게시글 간격으로 한정한다. 인증·품질 조건·예산 검사·서명 검증은 실험 대상에서 제외한다.
- 버전별 정책, 변경 이유, 사용한 관측 구간, 결과, 복원 여부를 새 로그에 남긴다.

## 순위에 맞춘 우선순위

지표 가중치가 크더라도 이미 상위권이면 같은 노력으로 백분위를 더 올리기 어려울 수 있다. 후보마다 `기대 백분위 개선 × 지표 가중치`를 검토하되 현재 공식 점수와의 연결이 확인된 경우에만 사용한다. 개선량은 처음에는 가설로 기록하고 반복 실험으로 보정한다. 점수만 올리려다 현금이나 별점을 훼손하는 후보는 안전 조건에서 제외한다.

추천 첫 단계는 자율 실행 전에 **관측·진단·변경 제안만 저장하는 모드**다. R3 표본으로 오판을 점검한 뒤 가격·재입고의 작은 변경과 자동 복원을 활성화하는 순서가 적합하다.
