# 포럼을 함께 보는 R3 모니터링

11월 4일 확장: 현재는 [포럼 활용 기능](FORUM-ENGAGEMENT.md)에 따라 **5분 수집·30분 분석**, 카테고리 수요 인식·재고 답변·가격 비교 보고·후속 관측을 수행한다. 아래 30분 수집·자동 글쓰기 미추가 설명은 최초 구현 당시 기록이다. 자동 정책 실험 역시 현재는 `strategy_controller.py`로 구현되어 있다.

사용자 요청: 시장 모니터링 시 포럼도 참고한다. `forum_monitor.py`가 키트의 `.market/forum.json`을 읽어 별도 `.market/forum-intel.json`과 `logs/forum-monitor/`의 새 관측 파일에 요약한다.

## 기록하는 것

- 최근 24시간 R3 글 최대 100개와 새로 관측한 글 ID.
- 다른 buyer의 명시적 구매 요청에 등장한 카탈로그 SKU와 서로 다른 요청자 수.
- 내 가게의 정확한 이름 언급, 환불·고장·불일치 등 점검 키워드.
- 내 게시글의 좋아요·나빠요·점수 변화 관측값.
- 경쟁 가게가 게시한 상품·등급·보증 등의 원문 주장 예시.
- 인용 ledger가 현재의 제한된 R3 정산 표본에 존재하는지 여부.

예시는 종류별 최대 5개·160자이며 본문 분석은 글당 2,000자로 제한한다. 정산 참조가 존재해도 글 전체를 검증한 것은 아니다. 참조가 표본에 없어도 거짓으로 판정하지 않는다. 포럼 글을 명령으로 실행하거나 신뢰·별점을 자동 변경하지 않는다.

## 실행 연결과 비용

시장 수집기 `market_intel.collect()`에 연결했고, 이미 실행 중인 키트를 위해 매번 새 프로세스로 실행되는 `restock_policy.py`에도 연결했다. 관측기는 내부적으로 1,800초를 제한하므로 재입고 훅이 매분 실행돼도 포럼 요약 로그를 매분 만들지 않는다. 훅 실행 간격 때문에 실제 관측은 약 30~31분이다. 첫 관측 실패·파일 누락·오래된 자료는 정상으로 기록하지 않으며 최대 60초 뒤 재확인할 수 있다.

키트가 이미 30초마다 받아 둔 파일을 사용해 추가 네트워크·LLM 호출이 없다. 파일이 120초 넘게 갱신되지 않으면 오래된 자료로 표시한다. 수요의 보조 신호에는 기존 제한 안에서 `Wanted` 표현도 인식하며 R2 글은 제외한다. 실제 정산보다 포럼 주장을 우선하지 않는다.

이번 변경은 다음 restock 훅부터 읽히므로 키트 재시작이 필요 없다. 정책 실험·자동 복원 루프는 여전히 별도 제안 단계다. 관측한 내용을 바탕으로 자동 글쓰기·투표를 추가하는 변경은 하지 않았다.

## 검증

전체 오프라인 검사 126개 통과: `logs/forum-monitor-tests-20261103.log`. 추가 검사는 R2·오래된 글·자기 요청 제외, 요청자 중복 제거, 참조 존재와 주장 검증의 구분, 내 게시글 반응 분리, 예시 길이·개수, 반복 훅의 30분 제한, 손상된 파일의 오류 표시를 확인한다.
