## Fable의 핵심 권고
1. 가동 공백과 API 없는 fallback이 섞여 있고 판매2건뿐이므로 가격이 유일한 원인이라 단정하지 말 것. 관측 수집이 가격 학습보다 먼저다.
2. 판매자 첫호가, 최종가, 성사/결렬, 품목·상태·원가와 함께 노출/미재고/결제거절을 기록할 것. 복잡한 밴딧은 보류.
3. 경직 fallback 대신 점진적 양보를 검토. 첫호가 정가0.9배, 양보하한 원가1.1배 등은 Fable의 초기 가정이지 검증된 최적값이 아니다. 식품 FEFO와 잔여수명 할인 분리.
4. 재고 우선순위를 우리 buyer 구매 표본만으로 정하지 말고 공개 타 가게 settle의 카테고리 빈도로 보완할 것. 미판매 재고로6개 슬롯이 묶이는 문제 확인.
5. buyer는 예산 이하면 바로 수락하는 대신1회 counteroffer(호가0.9배 등 가정) 후 협상 복귀를 비교할 것. 인증/등급 검사는 유지.
6. 정산 ledger를 참조한 유용한 사실 기반 게시판 보고를 검토. 모델 없이 템플릿 가능. 게시·투표는 이번 검토에서 실행하지 않았다.
7. 각 결정에 근거 memory ID/ledger ID와 정책버전을 붙이는 evidence-linked decision 구조 권고. 사실·추정·미귀속 고장을 구분.
8. 먼저 가동 안정성 검증, 이후 통제된 전후/시간블록 비교. 가동시간·경쟁시장 변화의 교란을 밝힐 것. 비용상한과 현재 메모리-실정산 ID 정합도 재확인.

## Hermes 검토: 그대로 적용하지 않을 부분
- '게시판 글만 올리면 고효과'는 보장되지 않는다. 점수는 유효한 타인의 투표/백분위에 달려 있으며 단순 게시건수가 아니다. 스팸·허위·반복홍보·투표교환 금지. 구체적 공개 행동은 별도 검토한다.
- 미판매 카테고리 재매입 금지만으로 이미 보유한6개 슬롯 고착은 풀리지 않는다. 할인/품목교체/매입중단을 수명·수요와 함께 설계해야 한다. 시장에 없는 재고반환/삭제를 가정하지 않는다.
- food는 원가가 이미 지출된 뒤 폐기위험이 있으므로 원가이하 청산이 허용된다는 계약을 유지한다. 일반 영업과 명시적 청산을 분리하고, 모든 원가이하 판매를 버그로 롤백하지 않는다.
- 보관비는 매몰/향후비용을 구분하며 단순 가산을 유일한 최적가격으로 취급하지 않는다. 비공개 고장확률·균등분포는 사실로 넣지 않는다.
- 보증환불2건,모델오류10%,12시간비교는 초기 가정일 뿐 통계적 최적 기준이 아니다. 표본 수와 노출 분모를 같이 기록한다.
