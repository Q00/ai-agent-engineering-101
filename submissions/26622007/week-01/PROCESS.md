## 2026-09-16: convert_units 구현

- 실제 변환은 미터 기준의 Decimal 환산표를 사용한다. 예: 10 inch × 0.0254 ÷ 0.01 = 25.4 cm.
- 길이 단위 6개를 enum으로 노출하고 필수 인자 `value`, `from_unit`, `to_unit`을 지정했다. 반환 문자열에는 목표 단위를 포함한다.
- `calculator`의 설명과 계산 로직, `read_file`의 설명은 유지했다. 새 도구 설명에는 단위를 맞춘 뒤 합계는 calculator로 구한다는 역할 구분을 담았다.
- 실패 입력은 예외를 잡아 도구 결과로 반환한다. 모델이 오류를 관찰하고 다음 행동을 선택할 수 있도록 했다.
- 오프라인 테스트는 알려진 환산값, 반대 방향 변환, 동일 단위/0/음수, 잘못된 단위/숫자, 실제 문제 합계를 검증한다.

## 2026-09-16: 사용자 추가 테스트 — 1m - 1km + 10ft

- 사용자 요청: `1m - 1km + 10ft`도 테스트. 모델에는 이 식을 계산하고 결과를 m로 보여달라고 요청했다. 정답이나 도구 순서는 전달하지 않았다.
- 독립 검산: 1 - 1000 + 10 × 0.3048 = **-995.952 m**. Python 도구를 연결한 회귀 테스트를 추가했고 통과했다.
- 실제 실행 원본: `logs/20260916T063904285290Z-mixed-subtraction.txt`. 동일한 Nemotron 무료 모델과 temperature=0을 사용했다.
- 첫 요청은 도구 이름에 설명문이 섞인 잘못된 호출이었다. 허용 목록 검사가 실행을 거부하고 `error: tool is not available in this run`을 관찰 결과로 전달했다.
- 모델은 다음 호출에서 `convert_units(value=10, from_unit="ft", to_unit="m")`를 정상 요청하여 `3.048 m`를 얻었다. 1 km = 1000 m는 모델이 직접 환산값을 작성했다.
- 이후 `calculator(expression="1 - 1000 + 3.048")`가 `-995.952`를 반환했고 최종 답변에도 음수 부호와 m 단위가 유지됐다.
- 4회 모델 호출, 도구 요청 3회(거부 1회, 정상 실행 2회), 입력+출력 토큰 4488. 최종 답은 맞았으나 처음부터 모든 도구 요청이 유효했던 실행은 아니다. 실패 호출도 원본에 보존했다.
