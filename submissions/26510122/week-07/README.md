# Week 07: signed A2A shop and review-aware market buyer

Run from this directory with Python 3.10+ and a signed-in Codex CLI:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python ../../../scripts/market_test_week07.py .
python3 ../../../scripts/check_week07.py . --github outSeop
```

`agent.json` defines the week-06-compatible shop and buyer plus `market_buyer`.
The shared `harness.py` invokes `gpt-5.6-luna` with strict JSON schemas.
Python code enforces the shop reserve, buyer budget and receipt fields; the
market kit verifies the seller signature before countersigning.
`market_buyer.py` stores its own history by shop name under
`state/market-memory.json`, which is deliberately ignored by Git.

`shop_key.pem` and `buyer_key.pem` are generated by the market kit. Never commit
them. The shop reads the former when signing an Ed25519 receipt. A deployment on
another machine must use the **same** shop key that the market kit registered.

In Round 1+, `market_buyer.py` keeps private memory in the ignored
`state/market-memory.json`, keyed by the market's stable shop **name** rather
than its changing URL. It counts deals, no-deals, errors, and receipt trust
failures, and appends timestamped observations with item, budget, outcome,
offers and receipt evidence. Older summary-only entries remain usable. The
selector shows the model matching-item observations at similar budgets first;
it treats other-item outcomes and public reviews as less directly relevant. A
receipt that disagrees with the order or lacks the required signature/task
marks that shop `avoid`; an ordinary no-deal does not. When alternatives exist,
the selector excludes shops marked `avoid` by its own experience or by repeated
bad reviews. One model call chooses an eligible shop and records separate
trustworthiness and feasibility judgments plus a factual reason in the local
log. A second model call phrases the public review from the observed result;
code rejects unsupported ratings, prices or accusations and uses a factual
fallback. Neither the private budget nor other shops' histories are published.
Old observations are retained if later clean trades change an `avoid` decision.

The course market installer was placed in a sibling `agent-market/` directory
under the workspace root, with this directory as its agent directory. Its
`join.sh` and supervisor logs are outside the submission. On this Mac, one
`launchd` service runs the buyer with `--buyer-only` and a second runs the shop
through a Pinggy SSH tunnel on port 443. The shop supervisor renews the free
tunnel before its URL expires and rejoins with the same shop name and key.
Do not start `join.sh` alongside these services: that would join twice. The
Mac must stay online and awake for both agents to remain reachable.
The claim code is not stored in this repository or in `join.sh`.

`adapt_prices.py --snapshot logs/challenge-1/before.json` converts a captured
dashboard snapshot to `pricing-policy.json`. The shop reloads that policy at
each new negotiation, caps its opening ask, and never lowers its reserve.

## Seller V1 observation phase

`pricing.py` records **new** seller tasks in the ignored
`state/pricing_state.sqlite`. It does not choose a price. Legacy opening asks
come from the seller model and the existing 1.12× reserve cap. Each task stores the
actual opening ask, numeric buyer offers, model-call count, receipt price and
status. Non-experimental tasks are labeled `legacy_cap_1.12`; historical
log-only tasks are not inserted into this experiment database.
The legacy cap uses floating-point multiplication and `ceil`; for a lamp reserve
of 100 it currently evaluates to 113, so its label is a policy name rather
than an exact price arm. The randomized experiment uses exact decimal
rounding and verifies every emitted ask.

An exposed task remains `UNRESOLVED` after its last counter until stronger
evidence arrives. An issued seller receipt is `RECEIPT_PENDING`, never a counted
sale by itself. Explicit seller rejection, A2A cancellation and model-call
failure have separate statuses. `TIMED_OUT` requires an independently verified
market/A2A deadline; this version does not assign it automatically. A restart
preserves recorded rows, although the existing Seller's in-memory active
negotiations do not resume after a restart.

To reconcile issued receipts with the official Round 2 ledger, run:

```bash
.venv/bin/python reconcile_pricing.py
.venv/bin/python pricing.py --item lamp
```

The command scans ledger entries after a durable cursor, matches the receipt's
task, shop, item and price, and records `DEAL_COUNTED` or
`RECEIPT_NOT_COUNTED`. The first run seeks to an hour before the earliest new
local attempt; later runs are incremental. A local launchd job runs this command
every three minutes; if it stops, unreconciled receipts stay pending. Tests can use `PRICING_STATE_PATH` to place
their database outside the live `state/` directory.

A 5% live canary assigns Low/Mid/High opening asks among new tasks. The other
95% use the legacy policy. UCB can choose an arm only inside the canary and
only after the readiness and ledger-freshness gates below pass. Baseline and
experimental trades must be analyzed separately.

### V1 record validation and offline experiment preparation

The SQLite schema now keeps `negotiation_status` and `ledger_status`
independently. `last_activity_at` tracks Seller-side negotiation activity;
`ledger_result_at` and the ledger observation table track market results. The
`events` table preserves opening asks, Buyer offers, Seller counters and receipt
events in insertion order. Incoming numeric offers and counters use the A2A
message ID for duplicate detection. Older rows remain in place; receipt-issued
rows are not called completed without an explicit `seller_deal` trace.

```bash
.venv/bin/python pricing_audit.py --log logs/market-kit.log
.venv/bin/python pricing_audit.py --log logs/market-kit.log --apply-completions
.venv/bin/python reconcile_pricing.py --backfill
.venv/bin/python pricing_report.py --legacy-log logs/market-kit.log
.venv/bin/python pricing_report.py --json
.venv/bin/python pricing_simulator.py
.venv/bin/python -m unittest discover -s tests -p 'test_pricing*.py'
```

`--apply-completions` uses only matching `seller_deal` log lines. A missing
completion remains unresolved. `--backfill` rechecks official ledger entries
since the first local task, keeping the durable cursor monotonic. The report
shows the new SQLite cohort separately from the first 600 historical log tasks.
Historical tasks with no explicit outcome stay `UNKNOWN`.

`reconcile_pricing.py` is an incremental command, not a Seller background
thread. A separate local launchd job now runs it periodically. If the job is
stopped, its stored ledger cursor falls behind and issued receipts remain
`PENDING`; the market board can still count those deals. The board also includes
earlier trades that predate this SQLite database, so its cumulative deal total
should not equal this database's count even after reconciliation.

`pricing_ucb.py` evaluates UCB readiness; its CLI only reports results. Run
`.venv/bin/python pricing_ucb.py --item lamp` (or `chair`/`bookshelf`). It excludes
the historical `legacy_cap_1.12` cohort and recommends no arm until each
Low/Mid/High arm has at least 30 buyer-visible asks, no ask mismatch, and at
most 5% pending/unknown outcomes. Counted margin is normalized by reserve and
capped at 1; no-deals receive zero. The score uses a conservative
per-exposure mean plus a fixed exploration bonus. These defaults are safety
gates for this randomized experiment, not evidence that UCB already works.
With `WEEK07_PRICE_UCB_AUTO=1`, the Seller uses its recommendation on a canary
task only if the latest full ledger reconciliation finished within ten minutes.
Otherwise it keeps the randomized arm. The local supervisor currently disables
this gate while the dated sale runs.

`pricing_experiment.py` provides a deterministic traffic split for collecting
real Low/Mid/High observations. `WEEK07_PRICE_EXPERIMENT_PERCENT=0` is the
default and keeps every opening under the legacy policy. A nonzero integer
percentage selects that fraction of new task IDs, then hashes each selected
task to one of the three arms within its item. The model still makes the same
opening call, but on a selected task the tool's exact candidate price replaces
its opening ask; follow-up decisions, reserve guard, signed receipt and A2A
format are unchanged. The actual emitted ask is recorded and later compared
with the assignment. Once both gates pass, UCB replaces the randomized arm on
selected canary tasks only; it does not change the other 95%.
The local Pinggy shop supervisor previously used a 5% traffic split, but now
sets it to 0% while the sale runs. Earlier Low/Mid/High observations
remain in SQLite as a separate cohort; they are not merged with sale data.

`WEEK07_TIME_SALE=1` makes Python read the current Asia/Seoul time once when
a new negotiation starts. From 2026-10-22 00:00 through 2026-10-28 23:59:59
KST, the exact integer opening ask is ceiling(1.09 × reserve); afterward it is
ceiling(1.12 × reserve). A negotiation retains its opening cohort if the clock
crosses the campaign deadline mid-task. The opening model still runs, but its suggested first ask
is replaced by this deterministic tool output. Follow-up negotiation, reserve
checks, signed receipts and A2A formats are unchanged. SQLite records
`campaign_sale_1.09` and `campaign_regular_1.12` separately. This before/after
comparison is observational: buyer traffic and order mix can vary by date, so
it cannot by itself prove the sale caused a change in market share.
An hourly :00–:19 proposal and an initial 1.06× campaign briefly ran on
2026-10-22 before this higher-price campaign replaced them. Their
`hourly_regular_1.09` and `campaign_sale_1.06` rows remain in SQLite and are
not silently relabeled as the new campaign observations.

`pricing_simulator.py` provides the shared exact price calculation and an
offline-only simulator. It uses decimal ceiling rules for 1.06, 1.09 and 1.12 times reserve and
balanced, seeded blocks per item. It can read a JSON list of task IDs, items
and reserves with `--tasks`; it never invents transaction results. It verifies
an `opening_ask_actual` if supplied. Its unit-test outcome fixtures are not
market observations and never enter the live database.

### Pricing data tool boundary

`PricingRecorder` is the Python boundary for transaction data: Seller calls
named recording methods, reconciliation calls ledger-observation methods, and
the report calls read-only methods. Only `pricing.py` contains production SQLite
queries. The model cannot submit SQL.

`pricing_tool.py` exposes one read-only MCP function, `get_price_stats(item)`,
with `lamp`, `chair`, and `bookshelf` as the only inputs. It opens the SQLite
database in read-only mode and returns small policy-level aggregates, keeping
pending and unresolved outcomes visible. It returns no task IDs, raw trades,
credentials, or SQL. The Codex CLI harness can connect this tool for **Seller
opening decisions only** with `WEEK07_PRICING_STATS_TOOL=1`; the default is off.
The database is selected by the operator's `PRICING_STATE_PATH`, never by the
model. No extra API key is needed when using the signed-in Codex CLI. A tool
call still adds the returned summary to the model context and consumes tokens.

For an isolated opt-in check using a test database, run:

```bash
WEEK07_PRICING_STATS_TOOL=1 PRICING_STATE_PATH=/absolute/path/to/test.sqlite \
  .venv/bin/python seller.py --port 9999
```

The running market Seller has **not** enabled this flag. The opt-in may affect
the model's opening ask, although the same reserve guard and 1.12× cap remain
in place. It is separate from the unstarted Low/Mid/High experiment.

### Agent Card draft for a later discovery experiment

The default `WEEK07_CARD_VARIANT=baseline` preserves the base Card. A
`transparent` variant is implemented but not enabled in the running market:

```bash
WEEK07_CARD_VARIANT=transparent .venv/bin/python seller.py --port 9999
```

It describes the actual protocol: negotiable asks, whole-number offers, and a
signed receipt on completed deals. It makes no cheapest-price or guaranteed
reliability claim. The shop name, A2A interface URL, protocol version,
capabilities, and `negotiate` skill ID remain unchanged. Changing the flag for
the market requires restarting the Seller/kit; do this only as a separate Card
comparison after holding the price policy fixed.

When `WEEK07_TIME_SALE=1` during the campaign, the live Card's description and
skill description disclose "Time Sale Now!" and the KST end date without
revealing the price ratios or private reserve. This is an opening-price
policy, not a promised final transaction price. The campaign
notice is omitted from Cards created after the deadline. The buyer-selection model in
our code is not supplied with the current time.

The market's `shops.json` contains name, URL, and reviews, not Card description
or skills. Our own `market_buyer` chooses a shop from that list before its A2A
buyer fetches the Card. A Card effect on shop selection requires evidence that
other Buyers read Cards before choosing. Health checks and post-selection
Card reads alone do not establish that exposure.
