# Week 07: signed A2A shop and review-aware market buyer

Run from this directory with Python 3.10+ and a signed-in Codex CLI:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python ../../../scripts/market_test_week07.py .
python3 ../../../scripts/check_week07.py . --github outSeop
```

`agent.json` defines the week-06-compatible shop and buyer plus `market_buyer`.
The shared `harness.py` invokes `gpt-5.6-luna` with strict JSON schemas.
Python code enforces the shop reserve, buyer budget and receipt fields; the
market kit verifies the seller signature before countersigning.
`market_buyer.py` stores its own history by shop name under
`state/market-memory.json`, which is deliberately ignored by Git.

`shop_key.pem` and `buyer_key.pem` are generated by the market kit. Never commit
them. The shop reads the former when signing an Ed25519 receipt. A deployment on
another machine must use the **same** shop key that the market kit registered.

In Round 1+, `market_buyer.py` keeps private memory in the ignored
`state/market-memory.json`, keyed by the market's stable shop **name** rather
than its changing URL. It counts deals, no-deals, errors, and receipt trust
failures, and appends timestamped observations with item, budget, outcome,
offers and receipt evidence. Older summary-only entries remain usable. The
selector shows the model matching-item observations at similar budgets first;
it treats other-item outcomes and public reviews as less directly relevant. A
receipt that disagrees with the order or lacks the required signature/task
marks that shop `avoid`; an ordinary no-deal does not. When alternatives exist,
the selector excludes shops marked `avoid` by its own experience or by repeated
bad reviews. One model call chooses an eligible shop and records separate
trustworthiness and feasibility judgments plus a factual reason in the local
log. A second model call phrases the public review from the observed result;
code rejects unsupported ratings, prices or accusations and uses a factual
fallback. Neither the private budget nor other shops' histories are published.
Old observations are retained if later clean trades change an `avoid` decision.

The course market installer was placed in a sibling `agent-market/` directory
under the workspace root, with this directory as its agent directory. Its
`join.sh` and supervisor logs are outside the submission. On this Mac, one
`launchd` service runs the buyer with `--buyer-only` and a second runs the shop
through a Pinggy SSH tunnel on port 443. The shop supervisor renews the free
tunnel before its URL expires and rejoins with the same shop name and key.
Do not start `join.sh` alongside these services: that would join twice. The
Mac must stay online and awake for both agents to remain reachable.
The claim code is not stored in this repository or in `join.sh`.

`adapt_prices.py --snapshot logs/challenge-1/before.json` converts a captured
dashboard snapshot to `pricing-policy.json`. The shop reloads that policy at
each new negotiation, caps its opening ask, and never lowers its reserve.

## Seller V1 observation phase

`pricing.py` records **new** seller tasks in the ignored
`state/pricing_state.sqlite`. It does not choose a price. Opening asks still come
from the seller model and the existing 1.12× reserve cap. Each task stores the
actual opening ask, numeric buyer offers, model-call count, receipt price and
status. All new tasks are labeled `legacy_cap_1.12`; historical log-only tasks
are not inserted into this experiment database.
The legacy cap uses floating-point multiplication and `ceil`; for a lamp reserve
of 100 it currently evaluates to 113, so its label is a policy name rather
than an exact price arm. A later randomized experiment must define exact
integer rounding separately and verify every emitted ask.

An exposed task remains `UNRESOLVED` after its last counter until stronger
evidence arrives. An issued seller receipt is `RECEIPT_PENDING`, never a counted
sale by itself. Explicit seller rejection, A2A cancellation and model-call
failure have separate statuses. `TIMED_OUT` requires an independently verified
market/A2A deadline; this version does not assign it automatically. A restart
preserves recorded rows, although the existing Seller's in-memory active
negotiations do not resume after a restart.

To reconcile issued receipts with the official Round 2 ledger, run:

```bash
.venv/bin/python reconcile_pricing.py
.venv/bin/python pricing.py --item lamp
```

The command scans ledger entries after a durable cursor, matches the receipt's
task, shop, item and price, and records `DEAL_COUNTED` or
`RECEIPT_NOT_COUNTED`. The first run seeks to an hour before the earliest new
local attempt; later runs are incremental. It is currently a manual command, so
unreconciled receipts stay pending. Tests can use `PRICING_STATE_PATH` to place
their database outside the live `state/` directory.

Low/Mid/High randomization and UCB are **not active**. Before testing those arms,
verify the recorded ask equals the buyer-visible ask, choose a justified rule
for unresolved and infrastructure-error outcomes, and run simultaneous
per-item assignment while keeping follow-up negotiation fixed. Baseline trades
and randomized trades must be analyzed separately.
