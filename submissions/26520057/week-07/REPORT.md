# Week 07 실험 보고서 — 26520057

## 1. Buyer 선택과 기억

초기에는 Claude Code Haiku가 가게 요약을 읽고 선택했다. 이후 선택 지연을 줄이려고 코드로 점수를 계산했다. `score()`는 공개 별점과 해당 가게에서 내가 받은 거래 경험의 별점을 합쳐 평균을 낸다. 자료가 없으면 3점이다. 최신 정책은 공개 시장의 현재 라운드 점유율 상위 5개 중 이 점수가 가장 높은 가게를 선택한다. 오프라인 가게는 제외하되 6위로 대체하지 않는다. 순위 API가 실패하면 구매하지 않는다.

`memory.json`은 거래마다 `{shop, item, budget, offers, price, result, stars, ts}`를 저장한다. URL이 바뀌어도 이름으로 기억한다. 모든 과거 별점에 같은 가중치를 주므로 단골 고착과 과거 평가 편향이 생길 수 있다. 한때 4점 상한을 사용했지만 철회했고, 기존 기억을 고쳐 과거 평가를 숨기지는 않았다.

광고 도달 범위를 늘리려고 상위 5개 제한을 도입했지만 균등 순환은 아니다. 같은 가게가 점수 1위이면 계속 그곳에서 구매한다. 속도 개선은 시장 주문 제한을 우회하지 않고 협상 내부의 불필요한 모델 호출을 줄인다. 실제 기록 `logs/server/fast-top5-buyer.log`에서 15:41:15 주문 이후 15:41:17 책장 262 거래, ledger #88852의 `verified True`, `review accepted`를 확인했다.

## 2. 리뷰와 harness

`summary()`는 가게의 점수, 최신 리뷰 3개, 내 최근 거래 3개를 harness에 보여줄 수 있다. 다만 현재 `HARNESS_PICK=False`이므로 가게 선택에서는 이 요약을 모델에 보내지 않고 별점 평균을 사용한다. 협상은 시장 최저가를 먼저 제안하고 명시적 견적을 예산 안에서 수락하며, 애매한 답변만 기존 `decide()`/Claude Haiku에 넘긴다. 예산은 코드로 제한한다.

사용자가 선택한 광고 실험은 다른 가게에서 성공한 거래 후기에 우리 가게를 추천하는 문구를 덧붙인다. 현재 문구에는 가상 시장에서의 품질 취향 비판, 가상 장인 소재 설정, 고정가와 빠른 결제 안내가 들어 있다. 이는 검증된 품질 비교가 아니다. 본인이 연결된 가게 광고임을 숨긴 문구를 실험한 과정도 Git 이력에 남아 있다. 실제 거래 평가와 광고가 섞여 신뢰를 낮출 수 있으며, 광고가 유입을 늘렸다는 인과 효과는 입증하지 못했다. 4점 상한은 적용했다가 철회했다.

추가로 공개 리뷰에서 반복적인 설명 없는 저평점을 관측하는 `review_policy.py`를 도입했다. 정상 영수증을 인정하는 1~2점 리뷰가 계정당 최소 3개이고 해당 관측 표본의 75% 이상일 때만 그 계정 소유 가게를 제외한다. 공개 피드 일부만 보며, 한국어·다양한 영문 표현을 완전히 해석하지 못한다. 검출은 구매 선호용 휴리스틱이고 특정 참여자의 부정직함을 확정하지 않는다. 실제 검출/회피가 없는데 있었다고 보고하지 않는다.

## 4. 서명·프로토콜 실패와 수정

초기 market test는 20/25였다. 판매자 서명 검사가 3회 실패했고 한 Buyer 실행에서는 출력이 없었다. 원인을 모두 확정하지 못한 실패도 이력에 남겼다. 이후 `{shop,item,price,task}`를 키 정렬·공백 없는 UTF-8 JSON으로 만들고 Ed25519로 서명했다. task는 실제 A2A 협상의 ID를 사용하며 kit가 검증 후 buyer 서명을 붙인다. 단순히 영수증 모양만 맞는 것과 실제 시장에서 인정되는 거래를 구분했다.

Cloudflare Workers는 동일 키로 서명하고 Durable Object에 task를 보관한다. `workers/verify.py`는 세 품목의 하한, 원본 키 서명, 가격 변조 거부, 종료 task 재사용 거부, GetTask, CancelTask, 직접 구매 및 수락 표현을 검사한다.

가격 고정화 때 내가 구현한 제안 해석 정규식이 `I offer 260.` 같은 마침표로 끝나는 문장을 거부했다. 숫자만 쓰는 기존 검사는 통과했지만 문장형 제안 재현 검사에서 실패했다. 이를 고치고 소수·음수 가격은 계속 거부하도록 회귀 검사를 추가했다. 로컬 통과 후 첫 공개 검사는 실패했고, 재시도는 전체 통과했다. 배포 반영 지연 가능성은 있으나 원인을 확정하지 않았다. 성공 로그뿐 아니라 실패와 한계를 함께 보존했다.

최근 ledger에서 마지막 성공 후 실패 9건 중 2건은 하한보다 낮은 예산, 7건은 책장 260에 충분한 예산이 있었지만 7~8번 협상하고 끝난 사례였다. 당시 Buyer 입력 원문은 없으므로 이 7건을 전부 정규식 버그 때문이라고 단정하지 않는다. 원본은 `logs/workers/recent-failed-visits.json`, 진단 한계는 `offer-punctuation-diagnosis.txt`에 있다.

## 5. Challenge 1: 가격 실험

초기 harness 호가는 lamp 150, chair 220, bookshelf 330~350이었다. `logs/challenge-1/before.txt`의 2026-10-20 관측은 거래 11/방문 24, 점유율 1.2%, 평점 3.47, 매출 2,157이다. 이후 시장 가격에 가까운 110/200/285로 낮추고 판매/이탈에 따른 호가 조정 폭을 +2/-3에서 +20/-30으로 바꿨다. 초기 30건 하한 이상 수락, 5점 약속 할인도 시도했다.

현재 Workers는 들어온 고객의 거래 완료를 우선해 100/180/260 고정가, 평가 조건 없는 구매, 한 요청 구매를 지원한다. Python 실습 판매자는 이전 동적 가격 전략을 남겼다. 이후 R2 누적 평균 188.17과 점유율 0.7%는 위 초기 R1 평균 196.09 및 점유율 1.2%와 다른 모집단이다. 가격을 바꿔 점유율이 개선됐다고 결론내릴 수 없다. 같은 R1을 나중에 조회하면 분모가 늘어 점유율은 0.6%로 보인다. 과거 스냅샷을 덮어쓰지 않고 둘 다 보존했다.

## 7. 배포와 운영

가게: Cloudflare Workers, `workers/src.js`, 공개 URL은 README에 기재했다. Durable Object SQLite 저장소에 협상 상태를 저장하며 `SHOP_PRIVATE_KEY`는 secret이다. Buyer/kit: 연구실 `VPN_HAILAB-sv117`의 사용자 디렉터리에서 systemd 사용자 서비스로 실행한다. linger와 재시작 정책을 설정했다. 서버 인터넷·인증이 끊기면 거래가 중단되며, 서비스가 재시도해도 항상 즉시 복구된다는 보장은 없다.

서버 Claude 인증 후 실행 파일이 사라진 사례가 있어 재설치하고 ExecStartPre로 실행 파일 존재를 점검했다. 첫 실패 ledger #86363과 이후 성공 #86598을 보존했다. Mac Buyer는 중지해 이중 실행을 피했고, 같은 이름·키·memory를 서버로 옮겼다. `.market/server.env`, 개인키, 인증 파일은 제출하지 않는다.

로그는 정리해서 성공처럼 만들지 않는다. 검사 도구가 재생성하는 파일은 이전 사본을 별도 폴더에 보존한다. 공식 검사 결과는 `test-report.json` 및 `logs/market-test.log`, Workers 검사는 `logs/workers/`, 서버 실행은 `logs/market-kit.log`와 `logs/server/`에 있다.
