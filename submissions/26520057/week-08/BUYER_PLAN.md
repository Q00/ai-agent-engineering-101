## 판단 기준

현재 [라이브 리더보드](https://market.ourolabs.ai/board)의 Round 3 설명과 API의 `saved`를 기준으로 삼는다. 일부 규칙 문서에 예전 Surplus 설명이 남아 있어 이를 혼동하지 않았다. SAVED는 실제 사용 가치에서 지불액을 뺀 값을 상품 정가로 나누고, 거래 100건을 0점으로 더한 것처럼 완화한 평균이다. 절대 금액이 큰 물건을 사는 것보다 **정가 대비 절약과 실제 사용 가능성**을 높여야 한다. ALL은 SAVED 50%, 게시판 반응 30%, 거래 수 10%, 게시글 수 10%의 상대 순위를 반영한다.

조사 초기에는 71개 Week 8 주문에서 17건이 정산됐고, SAVED 0.021, ALL 0.102였다. 큰 누적 주문 수에는 이전 운영이 포함되므로 현재 폭주로 해석하지 않았다. 실행 중 요청 간격은 120초였다. 구매한 17개 상품의 평균 지불액은 정가의 약 85.5%였다. 정가 초과 지불도 2건 발견했다.

새 비교 정책을 전환하기 직전의 별도 기준점은 **23건, SAVED 0.0297, ALL 0.115**다. 이 사이 기존 buyer의 KRW 호가 상한 버그도 먼저 수정했으므로 전체 기간의 모든 변화가 새 비교 정책 때문인 것은 아니다.

## 확인한 원인

- 임의로 선택한 한 가게가 품절·사용 한도 초과·조건 불일치이면 주문을 끝냈다.
- 상품가·예산·인증 품질을 비교하지 않고 작은 모델에 선택과 가격 제안을 맡겼다.
- `상품명: 161006 KRW` 형식을 호가로 인식하지 못해 261750이라는 예산액을 제안하고 결제한 사례가 있었다.
- 식품 유통기한과 등급 문제를 checkout에서야 발견했다. grade C 식품 중 필요한 시간은 충분했던 경우까지 일괄 거절했다.
- 37개 결제 시도 중 20개가 거절된 초기 표본에는 유통기한, 등급, 미인증, 재고 소진, 시장 결제 거절 등 서로 다른 원인이 있었다.

## 적용한 동작

1. **최대 3개 가게·서로 다른 SKU를 우선 비교.** 실제 재고와 허용 SKU, 구매 가능성, 자신의 정산 이력과 공개 정상 거래 기록을 이용한다. 빈 재고와 자기 계정 가게를 제외한다. 가게의 모델 이용 한도 초과와 특정 SKU의 실패를 구분해 잠시 피한다.
2. **비율을 기준으로 제한된 흥정.** 인식한 기존 호가, 사용자 예산, 상품 정가 대비 상한을 모두 지킨다. 첫 할인 제안을 한 뒤 최대 3번의 가격 제안으로 끝낸다. 가게가 할인 대신 기존 호가의 서명된 역제안을 보내도 buyer가 그 호가와 한도 안에서 검토할 수 있다. 최종 금액을 올려 놓은 영수증은 거절한다.
3. **지불 전 실제 checkout을 검증.** 가게 서명, 정확히 요청한 SKU, 시장 인증서, 실제 품질·유통기한·보증, 가격을 확인한다. 설명과 인증 품질이 다르면 인증된 품질의 가격 상한을 다시 적용한다. 조건이 맞지 않으면 예약을 취소하고 같은 주문의 다른 후보로 넘어간다.
4. **한 번만 결제.** 선정한 checkout 세션을 공식 키트가 다시 읽고 검증해 재사용한다. 동일 영수증으로 checkout을 중복 생성하지 않는다. 기존 buyer 키의 closed mandate 서명, open mandate 예산과 시장의 중복 정산 검사는 그대로 유지한다. 실제 결제 이후에는 다른 가게로 재시도하지 않는다.

### 가격·품질 한도

| 조건 | 정가 대비 추가 가격 상한 |
|---|---:|
| 충분한 유통기한이 인증된 식품 | 95% |
| 비식품 A/B + 실제 6시간 이상 환불 보증 | 95% |
| 비식품 A, 위 보증 없음 | 85% |
| 비식품 B 또는 등급 미확인, 위 보증 없음 | 80% |

이는 목표 가격이 아닌 **추가 과지불 방지선**이다. 예산과 기존 호가가 더 낮으면 그 값이 우선한다. 일률적인 30% 할인 조건 때문에 쓸 만한 거래를 버리지 않는다. 상대적으로 절약이 큰 적합한 후보를 먼저 검토한다.

식품 등급은 남은 유통기한의 비율이다. C라도 시장 인증서가 증명하는 남은 시간이 사용자 요구보다 충분할 때만 허용한다. 최소 여유 시간도 더한다. 필요한 유통기한에 못 미치는 경우는 계속 거절한다. 비식품은 A/B 조건을 유지한다. 6시간 보증이 더 높은 가격 한도의 근거였다면 실제 checkout에도 그 보증을 요구한다.

## 호출·권한 범위

- 초기 10개 완료 주문에서 8개 정산을 확인한 뒤 주문 간격을 120초에서 90초로 조정했다. 동시 주문은 하나이며 429 대기와 기존 제한을 유지한다. 한 주문 최대 3개 가게, 가게당 가격 제안 최대 3번, helper 약 175초 제한.
- 표준 가격·후보 선택은 검증 가능한 코드가 처리하고, 해석되지 않는 가격 문구만 기존 무료 로컬 Qwen을 제한적으로 사용한다. 모델 출력도 숫자가 실제 문구에 있는지와 상한을 검증한다.
- 외부 모델 API·유료 fallback·새 결제 키를 사용하지 않는다.
- 게시판 글과 투표는 실행하지 않았다. 이 항목 40%는 구매 동작과 별도이며, 외부 게시에는 명시적 승인이 필요하다.
- SHOP과 재부팅 자동 실행은 변경하지 않는다. 이전 유료 서비스는 계속 중지·비활성 상태다.

## 검증과 관찰

오프라인 검증은 과거 KRW 과지불, 숫자 없는 가격 문구, 호가 초과 영수증, 기존 호가의 역제안, 위조 인증서, 품질·유통기한·상한, SKU 바꿔치기 방어, 예약 취소, 후보 대체, prepared checkout 재사용과 기존 checkout 경로를 다룬다. 실제 결제 키 대신 임시 키와 mock 서버를 사용했다. SHOP의 자금·가격·보증과 실제 무료 모델 loopback 검증도 다시 확인했다.

첫 10개 완료 주문에서 8개 정산을 확인했다. 최종 동결 비교(시장 HTTP 시각 2026-11-06 05:07:34 UTC)는 **18개 완료 주문 중 16개 정산(88.9%)**, 결제 시도 16개 모두 정산이다. 구매 시점 평균 할인율은 전환 이전 23개 거래의 15.9%에서 새 정책 16개 거래의 **26.3%**로 높아졌다. 누적 거래는 23→39개, SAVED는 0.0297→**0.0566**이다. ALL은 0.115→0.111이며 점수 있는 Buyer 54개 중 50위이므로 상대 순위가 올랐다고 해석하지 않는다. 구매 성과와 상대 순위는 별도로 관찰한다. 소수의 순차 표본이며 통제 실험은 아니다.

실행 첫 주문은 약 4초에 완료됐고, 22900짜리를 17710에 정산했다(원장 `3152324`). 지불 전 검사한 것과 같은 checkout 세션을 공식 키트가 재사용한 첫 실거래다. 이어서 원장 `3152823`, `3153337`도 정산됐다. 작은 초기 표본이므로 장기 성공률이나 순위를 보장하지 않는다.
