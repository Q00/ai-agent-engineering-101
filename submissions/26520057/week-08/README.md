## 목표와 기준점

SHOP ALL은 [공식 시장 규칙](https://market.ourolabs.ai/agent.md)의 장부이익(Book) 50%, 매출 30%, 평점 20%를 반영한다. 단순 거래 수나 최저가보다 **시간당 실제 장부이익, 정산 매출, 신뢰할 수 있는 품질**을 함께 높이는 것이 목표다. 상위권 진입을 보장하지 않는다.

조사 시작 시점은 판매 2건, 매출 37,993, Book 0, ALL 0.044였다. 두 판매가 모두 매입 원가와 같았다. 방문 61회에는 이전 운영과 재고가 없던 시기가 포함되므로 이를 새 정책의 전환율로 해석하지 않는다. buyer의 큰 누적 주문 수도 현재 폭주의 근거가 아니며, Week 8 로그에서는 20분에 11건으로 120초 간격을 지켰다.

공개 정산 원장 12,000개 이벤트에서 약 47.3분의 완료 정산 2,103건을 분석했다. 침구 387건, 침대/매트리스 322건, 김치 238건, 음료 145건, 과자 87건 등이 관찰됐다. 기존 4개 재고의 카테고리는 이 표본 중 25건(약 1.2%)만 커버했다. 이는 카테고리 단위의 참고치이며 특정 SKU가 모든 해당 주문에 적합하다는 뜻은 아니다. 숨겨진 주문 예산이나 타 계정의 비공개 자료는 사용하지 않는다.

## 적용한 순서

1. **먼저 발견 가능하게 만들기.** 기존 localhost.run 주소는 내부 가게가 정상이면서 공개 주소는 오류를 내 시장 검색에서 빠졌다. 공식 키트의 무료 Quick Tunnel과 건강 검사·재등록 기능으로 전환했다. 같은 가게 키로 이름과 거래 기록을 유지한다. 임시 주소는 바뀔 수 있고 무료 터널에는 가용성 보장이 없다.
2. **원가 판매를 없애기.** 실제 매입 원가와 공개 체결 가격을 기준으로 견적을 결정한다. 원가 가산 하한은 A 15%, B 10%, C 8%이며, 등급·카테고리 체결 가격도 반영한다. 이는 환불·보관료 전 매출총이익 기준이다. 대화 중 가격은 올리지 않고, 제안이 호가보다 높아도 호가까지만 받는다. 표준 SKU·숫자 응답은 코드가 처리하고 애매한 문장만 무료 로컬 모델이 해석한다.
3. **수요에 맞춰 제한적으로 재고 확대.** 최근 공개 정산에서 실제 팔린 SKU를 우선하고, 보유 카테고리의 중복을 줄인다. 비싼 상품도 제한된 시험 물량으로 취급한다. 단기 부패 위험을 줄이기 위해 식품은 기본 보존기간 720시간 이상만 첫 단계에 포함한다. 공급 급등 계수가 1.12를 넘는 SKU는 새로 사지 않는다.
4. **품질을 구조화해서 보여주기.** 현재 등급, 시장 인증서, 남은 유통기한, 실제 보증 조건을 견적과 영수증에 담는다. 자격이 되는 A등급 비식품에는 6시간 파손 환불 보증을 제안할 수 있다. 보증은 견적·영수증에 표시된 경우에만 제공하며, 약속한 보증은 이후 취소하지 않는다.

## 자금과 실행 한도

| 항목 | 한도 |
|---|---:|
| 현금 예비금 | 3,500,000 크레딧 |
| 보유 재고 원가 | 1,000,000 크레딧 |
| 한 번의 보충 계획 | 최악 매입가 기준 500,000 크레딧 |
| 보유 수량 | 60개 |
| SKU 목표 수량 | 최대 6개 |
| 한 SKU의 재고 자본 | 최대 600,000 크레딧 |
| 식품 재고 자본 | 최대 350,000 크레딧 |
| 견적·체결 보증 노출 합계 | 최대 500,000 크레딧 |

매입 계획은 시장 최대 급등 50%와 A등급 최대 원가를 함께 적용한 보수적 상한으로 계산한다. 공급 창이 닫히면 구매하지 않는다. 품절·예약 만료·동일 재고 중복 약정을 방어하며, 이미 체결한 보증 노출은 취소 요청으로 지우지 않는다. 수업 크레딧은 모델 API 요금과 별개다.

## 무료 모델과 서비스

`qwen3:4b` Q4_K_M을 전용 Ollama `127.0.0.1:12571`에서 실행한다. GGUF digest는 `359d7dd4bcdab3d86b87d73ac27966f4dbb9f5efdfcc75d34a8764a09474fae7`로 고정했다. 클라우드를 끄고 CPU 4스레드·서비스 CPU 4코어·메모리 6GiB를 제한했다. 컨텍스트 4096, 출력 96토큰, 모델 호출은 한 번에 하나다. 외부 모델 API·키·유료 fallback을 사용하지 않는다. 서버 자체의 계산 자원과 전력은 소비한다.

`ax-round3-ollama`, `ax-round3-shop`, `ax-round3-buyer`가 현재 실행 대상이다. 이전 유료 API 서비스 세 개는 중지·비활성 상태다. 재부팅 자동 실행은 승인 검토에서 거부됐으므로 비활성 상태를 유지하고 재시도하지 않았다. 현재 실행 중인 서비스의 장애 복구는 유지한다.

## 검증과 관찰

- 오프라인 검증: 등급별 이익 하한, 현금·재고·식품 자본 상한, 공급 창, 급등·만료, SKU 숫자의 가격 오인 방지, 보증 노출 및 취소 제한.
- 실제 무료 모델 loopback: 원가 6,000짜리를 7,800에 체결, 서명·예산·A등급·6시간 보증 확인. 실제 시장 거래는 만들지 않았다.
- 라이브 검증: 새 정책으로 정산된 4건의 원가 대비 차익 합계 39,780을 확인했다. 시장 Book도 39,780이었다. 원장은 `3120330`, `3122074`, `3122273`, `3122307`이다. 확인 시점 전체 매출 270,459, 판매 8건, ALL 0.058, 재고 29개·15 SKU, 재고 원가 596,844, 현금 4,442,936이었다. 등급 표시는 4건 모두 정직하게 기록됐다. 초기 비교 중 일부 추가 판매는 이전 정책에서 발생했으므로 매출 증가 전체를 새 정책의 성과로 해석하지 않는다. A등급 보증 상품의 환불과 보관료는 이후 Book에 영향을 줄 수 있다.
- 관찰된 새 견적 처리 중앙값은 약 0.05초였다. 짧은 표본이며 장기 부하 성능 보장은 아니다.

공개 수요 신호와 성과 지표는 실행 중 약 4분마다 갱신한다. 판단 기준은 Book/시간, 정산 매출/시간, 실제 평점·환불, 검색 포함 여부다. 품질을 낮추거나 원가 밑으로 팔아 거래 수만 늘리는 정책으로 전환하지 않는다. 다음 공급 창에서 새 수요 기반 매입과 실제 소진을 검증한다. 첫 단계는 현재 자금 한도를 유지한다. 새 정책의 정산 20건과 6시간 이상을 관찰한 뒤 Book/시간이 양수이고 환불·품질 문제가 안정적일 때, 이익으로 확보한 자금 안에서 재고 상한 확대를 검토한다. 이익이 악화되면 재고 확대보다 가격·품질·품절 원인을 먼저 조사한다.

검토 자료는 `logs/strategy-demand-summary.json`, `strategy-data-provenance.json`, `strategy-plan-preview.json`, `strategy-evaluation.json`이다. 공개 API와 로컬 로그는 시점이 달라 잠깐 어긋날 수 있다. 실행 중 원본 로그는 서버에 보존하고, 커밋에는 검토용 고정 표본을 남긴다.

공식 v4 `market_kit.py`와 Round 3 starter의 A2A·서명 구조를 기반으로 가격·품질·재고 정책을 추가한 구현이다. 완성된 중간과제 REPORT나 독창성·성적을 주장하는 결과물은 아니다.

주요 파일: `seller_r3.py`(흥정·서명), `shop_strategy.py`(가격·품질·보증·수요·자금), `restock.py`(키트 보충 hook), `run_shop.py`(공식 터널 복구), `market_buyer.py`와 `buyer.py`(기존 buyer). 테스트는 `tests/`에 있다. 기존 Week 7 Python 가상환경을 의존성으로 사용한다.

현재 주소는 `.market/public-url`에서 확인한다. 상태 확인은 `systemctl --user status ax-round3-ollama ax-round3-shop ax-round3-buyer`, 중지는 `systemctl --user stop ax-round3-buyer ax-round3-shop ax-round3-ollama`다. 키·환경 파일·`.market/`·`runtime/`는 커밋하지 않는다.
