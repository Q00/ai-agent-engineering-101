기존 seller.py, buyer.py, agent.json은 수정하지 않습니다.

## 추가 파일

- catalog.json: 생성된 상품 3,000개. 이름, 설명, 하한가와 검증용 속성 포함.
- make_catalog.py: 동일한 카탈로그를 재생성하는 코드. API 호출 없음.
- seller_catalog.py: 도전 1용 A2A 판매자. Groq가 상품과 가격을 선택.
- run_challenge1.py: 서버를 자동 실행하고 설명 기반 구매 3건을 검사하는 고정 구매자.

## 실행

Groq 키가 설정된 아나콘다 프롬프트에서:

```cmd
cd /d "C:\Users\bhj72\ai-agent-engineering-101\submissions\26512076\week-06"
python run_challenge1.py
```

새 프롬프트라면 먼저 `set "GROQ_API_KEY=실제키"`로 키를 설정합니다.
기존 설치 패키지를 그대로 사용합니다. 기본 모델은 openai/gpt-oss-20b입니다.
GROQ_MODEL 환경변수를 설정하면 모델을 바꿀 수 있습니다.

성공 시 `3/3 cases passed -> PASS`가 출력됩니다.
실제 모델 호출은 사용자의 Groq 계정으로 실행됩니다.

## 검색과 판단

전체 카탈로그는 코드에만 있습니다. 첫 요청을 토큰화하고 영문 동의어를
정규화한 다음, 희귀 단어에 높은 가중치를 주는 검색으로 상위 16개를 고릅니다.
Groq는 후보의 설명과 속성을 읽고 사용자 조건을 만족하는 상품을 선택합니다.
이후 턴에는 선택한 상품 1개와 해당 협상의 대화 기록만 전달합니다.

검색은 단순한 어휘 기반이므로 어떤 표현에서나 적합한 후보를 찾는다고
보장하지 않습니다. 후보에 적합한 상품이 없으면 거절하도록 지시합니다.

## 검사

상품명이 아닌 재질·크기·용도·기능 설명으로 책 보관 가구, 조명, 좌석을 찾습니다.
검사기는 선택한 SKU의 카탈로그 속성이 요구 조건을 만족하는지 확인합니다.
첫 호가부터 매 호가의 하한가, 동일 SKU 유지, 영수증 가격도 검사합니다.
첫 호가 다음에 하한가 미만의 제안을 한 번 보내고 이후 호가를 수락합니다.
이 실험의 구매자는 규칙 기반이며 판매자 선택과 협상 판단은 Groq가 합니다.

## 로그

매 실행은 `logs/challenge-1/<UTC 실행시각>/`에 저장되어 이전 시도를 보존합니다.

- buyer.log: 설명 요청, A2A 응답, 검사 결과.
