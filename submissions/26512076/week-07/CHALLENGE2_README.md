분당 토큰 한도, 통신 시간 초과, 일시적인 서버 오류는 최신 seller_catalog.py의

성공 시 마지막에 `3/3 items; total .../800 -> PASS`가 표시됩니다.
실제 결과는 실행 후 만들어지며 제공 파일에 통과 결과를 미리 넣지 않습니다.

## 구성

- make_shops.py: 재현 가능한 가게 설정과 상품 카탈로그를 생성합니다. API 호출 없음.
- shops.json: 20개 가게 설정. 실제 서버 URL은 실행할 때 빈 포트로 정합니다.
- shop_catalogs/: 가게별 상품과 하한가. 가게마다 상품 분야와 가격이 다릅니다.
- shopping_list.json: lamp, chair, bookshelf 각 1개와 총예산 800.
- serve_shops.py: 20개 URL의 A2A v1.0 가게. 실제 협상 판단은 각 가게의 Groq 루프가 수행합니다.
- buyer_multi.py: 디렉터리를 읽고 가게와 예산을 선택하여 동시 협상을 진행하는 구매자.
- run_challenge2.py: 실행과 검증, 로그 보관.

## 큰 컨텍스트 처리와 판단

1. 모든 가게의 실제 Agent Card를 HTTP로 읽고 원본을 로그에 남깁니다.
2. 카드의 이름과 skill을 5개씩 Groq에 전달하여 품목별 후보를 고릅니다.
   전체 카드 20개의 원문을 한 번에 프롬프트에 넣지 않습니다.
3. 후보와 공개 가격 안내를 보고 Groq가 품목별 가게와 지출 한도를 정합니다.
4. 코드가 품목 누락·중복, 없는 가게 선택, 품목별 한도 합계 > 총예산을 막습니다.
5. asyncio.gather로 여러 가게와의 협상을 동시에 진행합니다. 각 거래의 taskId를 유지합니다.
6. 모델에는 품목, 지출 한도, 현재 호가, 최근 판매자 메시지, 이전 제안, 진행 상태,
   턴 번호만 전달합니다. 전체 대화 기록과 다른 가게의 대화를 반복 전달하지 않습니다.
7. 가격 제안과 포기는 구매자 Groq가 결정합니다. 합법적인 범위 내 결정만 전송합니다.
8. 품목별 예산을 미리 분리하고 품목 잠금·공유 원장으로 중복과 총예산 초과를 방지합니다.

복수 협상은 겹쳐 진행하지만 같은 프로세스의 판매자 모델 호출은 순서대로 처리해
Groq 요청 폭주를 줄입니다. 구매자 모델 호출도 한 번에 하나씩 처리합니다.
이는 여러 HTTP 협상을 열어 둔 상태에서 응답을 교차 처리하는 방식입니다.

가게 카드의 공개 가격 안내는 참고 정보입니다. 숨겨진 reserve 자체를 구매자에
전달하지 않습니다. 총예산과 품목은 외부 메시지로 변경할 수 없습니다.

## 실제 결과 검증

품목 3개를 모두 샀는지, 총예산 800 이하인지, 중복 구매가 없는지 확인합니다.
구매자 원장뿐 아니라 판매자 실제 sold 이벤트의 개수와 SKU를 대조합니다.
영수증과 카탈로그로 판매자의 하한가 준수도 확인합니다.
카드 20개를 읽었는지와 동시에 열린 협상이 2개 이상인지도 확인합니다.
실제 API 판단이 적절하지 않거나 서비스 오류가 회복되지 않으면 FAIL로 기록합니다.
통과시키기 위해 코드가 가격을 정하거나 모델 응답을 지어내지 않습니다.

## 로그

실행마다 `logs/challenge-2/<UTC 실행시각>/` 아래에 새 폴더를 생성합니다.

- directory.json: 실행에 사용한 20개 실제 가게 URL.
- server_config.json: 실제 가게 설정과 카탈로그 경로.
- shopping_list.json: 실행에 사용한 목록과 총예산.
- sellers.log: 판매자별 상품 선택·호가·모델 입력·판매 이벤트.
- buyer.log: 카드 원본, 배치별 후보, 예산 배분, 협상 요약, 제안, 영수증.
- buyer-report.json: 구매자 원장과 실패 내역.
- report.json: 최종 검증 결과.
- runner-error.json: 보고서 생성 전에 실패한 경우의 실행 오류.

REPORT.md에는 directory_batch_*의 후보 선정, budget_reserved, negotiation_summary,
purchased 및 실제 실패 로그를 근거로 설명하세요. 이 설명서는 실제 보고서를
대신하지 않습니다. 키는 로그나 소스에 넣지 않습니다.

## 제공 전 검증

모든 Python 파일의 문법을 확인했습니다. 모의 모델 응답으로 실제 로컬 HTTP 서버
20개, 카드 배치 선택, 예산 배분, 3개 동시 협상, 영수증과 중복 판매 검사를 확인했습니다.
