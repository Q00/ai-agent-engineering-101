# v31 운영통제실 교정

v30 진행경과에서 확인한 공유 SQLite 경합과 Buyer 오류 관측 누락을 교정한다. 이번 변경은 Shop·Buyer의 경제 정책 버전과 품질 성숙 시계를 유지하며 실행 신뢰성을 개선하는 범위다.

## 원인과 변경

고객 메모리 정리는 매 방문/대화마다 쓰기 트랜잭션을 열고 `kind LIKE 'customer_%'`인 행을 삭제했다. 실제 운영 DB의 실행 계획은 `SCAN events`였다. `GLOB 'customer_*'`로 정확한 접두사를 검색하면 `SEARCH events USING INDEX event_kind (kind>? AND kind<?)`가 된다. 고객 키 검색도 같은 방식으로 기존 기본키 인덱스를 사용하게 한다. 결제·정산 이벤트는 정리 대상이 아니며 기존 고객 보존/아카이브 규칙은 유지한다.

`Journal.connect`는 매 연결의 WAL 모드 재설정을 없애고 Journal 초기화에서 설정한다. 영수증·정산·재고 예약·API 지출의 쓰기 방식은 유지한다.

비필수 prediction/decision/실행·선택 피드백은 `Journal.observe`를 사용한다. DB 쓰기가 50ms 내 완료되지 않으면 새 이벤트 ID와 원래 시각을 별도 `telemetry-pending` 파일에 원자적으로 보존한다. 배경 준비 루프가 DB에 합친 뒤에만 파일을 제거한다. 실패/중복 재생 시 기존 ID의 INSERT OR IGNORE가 중복 이벤트를 막는다. 예측 로그는 지연될 수 있지만 거래는 그 저장 완료를 기다리지 않는다. 결제·재고 예약 등 중요한 거래 데이터는 이 큐로 우회하지 않는다.

숫자 실행 경로의 prediction은 후보 ID·행동·가격·기대 변화·주문/상점/SKU/태스크 식별자와 다음 순위 문턱을 보존한다. 큰 메모리·전략·시장 컨텍스트의 반복 복사는 제외한다. 협상 경로 학습에 필요한 정확한 조인 키는 유지한다. 기존 로그를 편집하거나 삭제하지 않는다.

Buyer worker 오류는 예외 유형과 마지막 3개 발생 파일/함수/행 번호를 기록한다. 원문 예외 메시지, 소스 내용, 로컬 변수, 결제 정보는 전달하지 않는다. 부모의 오류 기록에도 안전한 원인 코드와 위치를 남기고, 이전처럼 늦은/다른 주문 응답을 거절하며 부모만 결제한다. 증거 없이 전체 타임아웃이나 재시도 횟수를 늘리지 않는다.

## 검증

- `logs/v31-query-plan-20261116.json`: 운영 DB에 읽기 전용 EXPLAIN으로 인덱스 사용 확인.
- `tests/test_contention_journal.py`: 강제 쓰기 잠금에서 진단 로그의 짧은 대기·보존·재생·중복 방지, 중요한 결제 기록의 정상 커밋 대기, 고객 접두사 정확성, 작은 prediction의 학습 식별자 보존, Buyer 오류에서 비밀 메시지 제외를 검증한다.
- 기존 고객 FIFO/아카이브·재생 방지·금융 예약·Buyer IPC·거래 프로토콜 회귀 검사를 함께 수행한다.

DB 경합이 모든 경로에서 사라진다거나 구매/별점/점수가 반드시 오른다는 주장은 하지 않는다. 재기동 뒤 거래 수, 오류율, 대기 파일 수, 모델 호출 수를 같은 런타임 구간으로 확인한다. 초반 실행 확인과 경제적 성과 검증은 구분한다.

## 실제 실행에서 발견한 추가 보증 경로 교정

첫 v31 재기동 후 서명 영수증에 보증 기간이 없는데 Buyer가 요청한 6시간을 기본값으로 채워 결제 단계까지 넘기는 사례를 확인했다. 부모는 올바르게 0시간으로 판단해 거절하고 다른 제안을 탐색했지만, 불필요한 결제 준비·복구 지연이 발생했다.

v31.1은 최종 서명 영수증의 누락/null 보증을 0으로 해석하고, 요청한 최소 기간에 미달하면 결제 요청 전 같은 주문의 다음 제안으로 넘어간다. 조건부로 탐색한 보증도 최종 영수증에서 만들어내지 않는다. 이미 약속한 기간은 그대로 요구한다. 보증이 명시된 정상 거래와 부모의 최종 검사는 유지한다. 누락/null/0/3시간을 포함한 실제 Buyer 실행 회귀 검사 및 정상 A2A 상호운용 검사를 수행했다.

## 최종 배포 확인

전체 631개 검사 통과: `logs/v311-full-regression-20261116-01.txt`. 기존 신원·정산 원장과 Shop·Buyer 품질 성숙 시계를 유지해 정상 종료 후 재기동했다. PID 20808, 실행 버전 `v31.1-contention-and-signed-warranty`. 공개 확인은 `logs/finalday-live-20261116T033535779473Z.json`의 Shop 카드 HTTP 200·등록 일치로 남겼다.

12:36 KST, 재기동 시작 약 206초(터널 준비 시간 포함) 관측에서 Shop 정산 4건·Buyer 구매 6건, 모델 호출·감독·분석·Buyer worker·통제 오류는 각각 0건이었다. 진단 대기 파일은 0개로 배경 재생이 진행된다. 실제 Buyer 실행에서 `quote_warranty_changed` 1건이 결제 요청 전에 거절된 기록도 확인했다. 거래 실패 전체가 없어졌다는 뜻은 아니며 no_agreement 1건, ambiguous_ask 1건도 남아 있다.

새 prediction 83개의 평균 크기는 약 1,882자다. 수치 선택기 내부 시간의 중앙값은 Shop 약 0.063초, Buyer 약 0.047초로 측정됐다. 이 시간은 후보 사전 계산·네트워크·결제를 포함한 전체 거래 지연이 아니다. 초기의 짧은 구간이므로 장기 오류율 감소나 점수 개선의 통계적 입증으로 해석하지 않는다.

최종 소스 해시는 `logs/v311-release-20261116.json`과 일치하며, 실행 근거는 `logs/v31-runtime-20261116T033611965952Z.json`에 있다.
