## 3. LLM은 지금 끄는 편이 합리적이다

전체 기간 자체 저널에는 601회, 설정 단가 기준 약 $3.4596가 기록됐다. 그중 Terra critic이 171회/$3.0853으로 약 89.2%다. 청구서나 전체 API 계정 사용액이 아니다.

v28.1 직전부터 기준 시각까지 약 4.77시간에는 126회/$0.7622, critic 38회가 기록됐다. **중복 검토 생략은 0건**이며, 37회 연구 게시 중 새로 승인된 실험은 0개다. 전체 170회 연구 게시에서도 승인된 새 실험은 0개다. 운영 파라미터가 바뀐 기록은 있으므로 모든 호출이 아무 영향도 없었다고 단정할 수는 없다. 그러나 유료 추론의 실제 Book·ALL 개선 효과는 입증되지 않았다. 기존 중복 제거 패치의 절감 효과도 이번 구간에서 확인되지 않았다.

일반 Shop 가격·매입 및 Buyer 실행은 이미 수치 경로로 처리된다. 이번 기간 기록된 모델 역할도 배경 분석·검토·도구 설계 역할들이다. 따라서 더 빠른 LLM으로 교체할 이유보다 자동 호출을 제거할 이유가 강하다. API 비용 절감과 시장 Book 개선은 별개다. LLM을 꺼도 잘못된 수치 매입·판매 정책은 그대로 손실을 낼 수 있다.

제안 설정은 `research_enabled=false`, `capability_llm_enabled=false`와 Main의 예외 경로까지 포함한 명시적 API 호출 차단이다. `R3_MODEL_MODE=offline`만으로는 배경 호출이 중단되지 않는다. 수치형 시장 관찰, 원장/품질 결과 수집, 결제, 재등록·복구, 보증 의무·준비금은 유지한다. 이미 게시된 LLM 정책은 출처와 만료를 확인해 명시적으로 회수하고 새 수치 정책을 적용해야 한다. 플래그 두 개만 끄면 기존 권고가 즉시 사라진다고 가정해서는 안 된다.

## 4. 구조에서 고칠 핵심

1. **기존 정책보다 예측이 좋다는 검증을 실제 순이익 검증으로 바꾼다.** `inventory_portfolio.allocate()`의 비교 기준은 기존 포트폴리오다. 상위 `restock.portfolios()`에는 `wait`가 있으므로 시스템에 대기 선택 자체가 없는 것은 아니다. 그러나 같은 수요·가격 예측이 과대평가되면 매입이 항상 더 좋게 보인다. 배분기에도 신규 매입 0개 기준을 넣고, 실제 성숙 정산·환불·폐기·보관료를 포함한 예측 오차로 검증해야 한다.
2. **고가 공산품의 금액 위험을 분리한다.** 현 환불 모델은 주로 등급별 건수 기반 48시간 표본이다. 금액이 큰 특정 SKU/계약의 손실을 평균 건수 위험이 덮을 수 있다. SKU·등급·가격/보증 조건별로 성숙 순이익과 금액 노출을 보되, 표본이 없으면 유리한 수치를 추정해 대량 진입하지 않는다. 몇 건의 독립 실현 이익으로 뒷받침되지 않은 일반 공산품 확대 매입은 일단 중단한다.
3. **과거 고가 체결과 우리 가격의 수요를 구분한다.** 외부 p75/p90 체결가는 그 가격으로 우리가 팔 수 있다는 증거가 아니다. 우리 실제 견적 노출→결제 자료를 등급·가격·보증·잔여 수명별로 집계한다. 재고가 노출되지 않은 시간, 품절, 반복 탐색을 수요 성공/실패와 섞지 않는다.
4. **식품의 임의 폐기 시나리오를 실제 시간 구조로 바꾼다.** 현재 `(1-sale_probability)*0.25` 형태의 폐기 스트레스는 SKU 만료·잔여 수명·미판매 재고 전체 원가 손실을 충분히 표현하지 못할 수 있다. 새 매입은 입고 등급의 전체 확률 분포와 수명별 고객 수요를 합쳐 평가한다. 공급 시 A만 골라 살 수 없으므로 “A만 대량 매입”은 실행 가능한 해법이 아니다.

저장소도 과하다. SQLite 파일은 약 8.79GB이며 최근 prediction 500개의 JSON은 평균 약 22,215자, 최대 232,155자였다. 기존 진단에는 SQLite 오류가 반복된다. 단, 이 수치만으로 지연의 원인 비중을 측정한 것은 아니다. 새 실시간 기록은 정책/후보/결과 ID와 핵심 숫자로 줄이고 원문은 배경 저장으로 넘긴다. 기존 로그를 삭제하거나 정리하지 않는다.

사전 매입 계획은 전체 재고·정책 식별자가 달라질 때 무효화된다. 신규 거래마다 필요한 부분만 다시 계산하도록 해야 한다. 다만 남은 기간에는 이 부분을 전면 재작성하기보다 손실 차단을 먼저 적용하는 편이 낫다.

## 5. 남은 기간의 단일 운영안

**신규 매입:** 검증되지 않은 공산품·짧은 수명 저평점 식품의 확대 매입을 중단한다. 새 로트 전체의 기대 순이익이 신규 매입 0개보다 좋고 실제 관측 오차를 넣어도 유리한 경우만 허용한다. 획일적인 재고 수량 상한을 다시 만드는 방식이 아니다. 수요와 이익이 확인된 SKU만 추가 한 단위의 이익이 남는 만큼 늘린다.

**기존 공산품:** 미판매 원가가 Book에 남으므로 일괄 할인하지 않는다. 전액 환불 확률을 q, 판매가를 P, 원가를 C라 할 때 판매의 보유 대비 금전 이점은 대략 `(1-q)*P - C + 절감되는 보관료`다. 여기에 품질/별점 위험을 별도로 비교한다. q는 현재 SKU의 확정 사실이 아니므로 손실이 큰 표본에서는 보수적으로 적용한다. 이미 약속한 보증을 회수하지 않는다. 보증을 없애도 고장과 별점 위험은 남는다.

**기존 식품:** 만료되면 보유 가치가 0이 될 수 있으므로 원가 이하 판매를 일괄 금지하지 않는다. 실제 사용 시점·기한·등급을 충족하는 고객에게만, 폐기 대비 회수와 별점 영향을 함께 비교해 판다. 당장의 몇 천 원 회수를 위해 기한이 빠듯한 식품을 밀어내는 경로는 줄인다. 새 로트의 기준과 기존 만료 임박품 처리 기준을 분리한다.

**점수 선택:** 공식 Shop ALL은 Book 50%·매출 30%·별점 20%의 상대 백분위다. 기준 시각의 다음 Book 문턱은 +91,655,886, 매출 문턱은 +244,256,441이며 별점은 4.32 다음에 4.33인 Shop들이 있다. 공식 종료로 확인해 둔 11월 17일 23:59까지 약 55.46시간이다. 상대가 멈춘다고 해도 Book은 시간당 약 165만, 매출은 440만이 필요하다. 현재 전체 구간 Book은 시간당 -6.6만, 매출은 +267만이다. Book 손실을 멈추면서 유효 수명·품질 계약으로 별점 문턱을 넘는 것이 작은 점수 개선의 가장 현실적인 후보이다.

공개 대체 코호트 68명을 고정하면 별점 4.33의 예상 백분위 기여 개선은 약 +0.0074, 4.35는 +0.0279다. 이는 공식 점수 예측도, 그 별점을 달성할 수 있다는 보장도 아니다. 계정별 평균, 숨은 자격 기준, 반올림, 경쟁자 변화가 있다. Book 방어를 포기하고 별점만 올리는 정책도 권하지 않는다.

**최소 실행 구조:** 수치 관찰기 → 만료가 있는 SKU/계약별 정책표 → Main의 즉시 제약 검사·실행 → 성숙 결과 평가. 수요·리스크 표의 갱신은 배경에서 하고 Main은 원가·기한·재고·준비금·가격을 즉시 확인한다. 정책표는 확정 사실/추정/실행 허용을 구분하고, 결과 평가기는 유리한 경로의 수량만 늘리거나 손실 경로를 0으로 만든다. 더 많은 추론 에이전트나 자가 생성 도구는 이번 구간에 추가하지 않는다.

실시간에는 매출보다 `판매 마진 - 확인 환불 - 보관료 - 폐기 - 기타 비용`의 Book 대사를 먼저 본다. 공산품은 최소 6시간 10분의 성숙 관측을 기다려 평가하고, 식품은 해당 로트의 만료 시점까지 포함한다. 공급 주기마다 시장 변화는 계속 수집하되, 성숙하지 않은 결과로 정책을 반복 교체하지 않는다. 유효 이익이 관측되지 않으면 신규 매입 0개를 정상적인 최적 행동으로 허용한다.
