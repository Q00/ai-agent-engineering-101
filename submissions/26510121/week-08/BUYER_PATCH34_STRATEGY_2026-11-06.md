# Buyer v8 — Patch 3.4 Saved 전략과 배포 기록

사용자는 새 시장 규칙을 활용한 buyer 전략 교정과 시장 적용을 승인했다. 공식 근거는 [3.4 규칙](https://market.ourolabs.ai/rules), [기술 규칙](https://market.ourolabs.ai/agent.md)이며 배포 전 원문은 `logs/patch-rules-source-20261106T042804958612Z.json`에 보존했다.

## 바뀐 판단

이전 내부 모델은 누적 surplus를 최대화했지만 3.4의 50% 요소는 Saved다. 거래가 정상적으로 가치를 제공하면 기여는 `1 - price/list_price`, 미사용·보증 없는 고장 거래는 -1, 전액 환불 고장은 0이다. 누적 기여를 거래 수+100으로 나누므로, 이미 Saved가 S인 상태에서 기여 r의 거래가 하나 성사될 때 변화는 `(r-S)/(deals+101)`이다. 완료 확률은 이 변화에 곱한다. 금액이 큰 상품에 추가 점수를 주지 않는다.

상품 고장 확률 시나리오 f와 보증 내 고장·환불 확률 하한 c를 쓰면 기대 기여는 `(1-f)*(1-price/list_price) - (f-c)`다. 단순히 절약률만 비교하거나 환불 거래를 성공 절약으로 세지 않는다. 현재 Saved보다 .002 높은 기대 기여를 목표로 가격 상한을 계산하고, 예산·서명·등급·보증·유통기한·정산 검사는 유지한다. .002와 완료 확률은 운영 가정이며 최적값이 입증된 것은 아니다. 고장 위험은 기존 성숙 품질 자료의 보수적 경계를 사용한다.

Buyer ALL 후보 비교는 Saved 50%, forum 30%, deals 10%, posts 10%를 사용한다. 학생의 Class 순위를 목표로 각 학생 계정에서 시장이 선택한 buyer 하나씩을 비교하며, 반영 가능한 class 정보가 없으면 기존 cohort로 돌아간다. 순위 변화 계산은 계획용 백분위 근사이며 공식 점수 예측 보장이 아니다.

## 실행과 관측

- 숫자로 확정 가능한 Saved 후보·가격 비교는 API 대기 없이 계산하고 별도 `buyer_saved_execution` 이벤트로 기록한다. API 모델과 키는 바꾸지 않았다.
- 식품을 절대 금액이 작다는 이유로 낮게 평가하지 않는다. 식품도 병렬 견적 두 곳을 비교할 수 있고, 공산품에는 6시간 보증을 선호한다고 요청하되 실제 경제성과 검증된 계약으로 판단한다.
- HTTP 요청마다 남은 협상 시간을 적용한다. 기존 식품 18초, 공산품은 60초를 사용하며 실제 결제를 위한 시간은 별도로 남긴다.
- 결제 전 확인된 품절 unit은 짧게 기억한다. 유통기한 거절은 실제 남은 시간에 맞춰 기억하므로 더 짧은 사용 요구를 가진 다음 주문까지 부당하게 차단하지 않는다. 결제 불확실성 뒤에는 재결제하지 않는다.
- Buyer 포럼은 역할별 공식 최소 간격인 300초를 지킨다. 동일 등급·보증의 실제 정산 비교나 unit과 원장으로 확인된 고장·환불만 게시하며 동일 근거를 반복하지 않는다. 일반 구매 메모의 과거 대기열은 운영 큐에서 retired로 보존하고 감사 이벤트를 남긴다. 원본 로그·재무 이력은 지우지 않는다.
- 자동 투표나 유료 dislike는 추가하지 않았다. 새로운 작성자에 대한 dislike는 shop book을 감소시키므로 순위 전략을 지출 공격으로 바꾸지 않는다.
- 규칙을 5분마다 다시 확인한다. buyer 가중치·Saved 분모·실패 기여가 지원하는 규칙과 다르면 buyer 매입을 보류한다. 과거처럼 shop 규칙 문구만 확인하지 않는다.

## 전략 이력과 검증

`buyer-v8-patch34-saved`는 buyer만 새 관측 시각과 전략 버전으로 전환한다. 과거 절대 surplus 기준으로 조정한 buyer 패치는 감사 이력에 보존하고 초기화한다. shop 전략, 키, 재고, 원장과 기존 성숙 품질 자료는 유지한다. 공산품의 새 품질 성과는 6시간 성숙을 기다려 평가해야 한다.

최종 전체 171개 테스트 통과: `logs/buyer34-ship-tests-20261106T0410.txt`. Saved의 가격 독립성, 실패 -1·환불 0, 현재 평균보다 낮은 거래의 점수 희석, 높은 Saved·고장 확률 경계, 학생 cohort, 반복 품절·유통기한의 범위, 요청 기한, 실제 A2A HTTP·서명·거래 성립, 게시판 참조·중복·주기, 미래 규칙 불일치 탐지를 포함한다.

실패 시도도 별도 보존했다. 첫 부동소수점 경계, 품질 자료 부족으로 거래 가능한 가격대가 겹치지 않았던 합성 시장, 새 Saved 모드에 맞지 않던 보증·전략 번호·기존 포럼 형식 단정은 `logs/buyer34-first-tests-20261106T0345.txt`, `logs/buyer34-full-tests-20261106T0348.txt`, `logs/buyer34-feasible-tests-20261106T0350.txt`, `logs/buyer34-release-tests-20261106T0400.txt`에 남겼다. 위험·검증 조건을 느슨하게 바꿔 통과시키지 않았다.
