# 재고·현금·규칙 변경 권한 검토 — 2026-11-11

이 문서는 읽기 전용 관측과 코드 분석이다. v14 구현·성능 검증·정책 배포를 수행하지 않았다. 별도의 Shop 연결 복구는 기존 주소와 키의 재등록으로 처리했다.

## 1. 현재 관측과 현금 해석

10:01:12 KST에 수집한 로컬 재고 파일은 10:01:07 갱신본이다. 보드는 10:00:42, 자금 제어는 09:57:31 관측으로 서로 시각이 다르다. 실시간 시장 API나 모델을 호출하지 않고 읽기 전용 SQLite transaction과 파일을 사용했다.

|---|---:|---:|
| 현금 | 728,487,820 | 722,846,608 |

| 재고 원가 | 20,814,903 | 42,272,989 |

현금은 약 564만 감소했지만 재고 원가는 약 2,146만, Book은 약 1,582만 증가했다. 현금 잔액만 보면 자산 증가를 놓칠 수 있다. 매입은 현금을 재고로 바꾸며, 판매 후 원가·환불·추가 비용을 차감한 기여가 자산 증가로 이어진다. 전후 차이가 전부 특정 정책의 인과 효과라는 뜻은 아니다.

최근 자금 제어의 사용 가능액은 563,846,728, 실제 보증 관련 준비금은 13,346,293, 현금 하한은 144,507,288, 보관비 준비는 836,129다. 이 수치는 재고 파일과 시각이 달라 동시 자산 항등식으로 쓰지 않는다.

최근 여섯 시간 정산 204건의 원가 확인은 204건이며, 매출 44,266,248, 사후 환불·보관·폐기 전 매출총이익은 6,900,065다. 동일 조건 대조가 아니므로 특정 매입 정책의 효과를 확정할 수 없다.

## 2. 코드에서 확인한 수량 제약

`r3/economy.py:300`의 매입 후보 생성과 `r3/shop_growth.py`의 배분이 실제 수량을 결정한다.

1. **SKU별 목표가 먼저 작동한다.** `target_stock()`은 기본 20분 공급 주기의 도착률 시나리오를 사용한다. 관측된 양의 마진 판매가 3건 미만이면 수요가 커도 목표는 최대 2개다. `probe_sku`는 이후 추가로 매입량 1개 제한을 받는다.
2. **추정 수요와 비용·보증 모델이 후보를 제거한다.** 기존 보유량을 차감한 필요량, 양의 예상 Book 기여, 공급 할증, 등급/보증별 판매 조건, 최악 매입 비용의 감당 가능성 등을 검사한다. 이 추정이 지나치게 보수적인지 실제 근거로 따져야 한다.
3. **짧은 공급 창과 제어 중단이 실행량을 줄인다.** `restock.py`는 남은 시간으로 실행 가능한 품목 수를 정하고, 발견 불가·오래된 자료·접근 불안정 시 보충을 막는다. 여섯 시간 동안 발견 불가로 인한 계획 차단 4회, 최신 자금/제어 검사에 의한 공급 차단 9회가 기록됐다. 발생 횟수는 장애 시간이나 손실액이 아니다.
4. **전체 재고 상한은 현재 180개다.** 현재 77개이므로 전체 상한 자체가 현 관측 수량을 제한하는 상황은 아니다. 단순히 이 상한을 올려도 위 후보 제한을 해결하지 않는다.

09:44:59 계획은 사용 가능액 약 5.635억 중 약 524만을 약정하고 8 SKU·8개를 선택했다. 09:25:41은 약 568만·8 SKU·10개였다. 계획은 실제 구매 완료와 다르지만, 이 시점의 현금 부족만으로 작은 계획을 설명할 수는 없다.

**확인된 것은 제약 경로다.** 전체 후보의 단계별 탈락을 재구성하지 않았으므로, 각각이 놓친 매출이나 이익에 얼마나 기여했는지는 아직 순위를 매길 수 없다. 현재 62 SKU·77개는 넓지만 얕은 구성이다. 추가 다양화와 인기 계약의 수량 확대 중 어느 쪽이 유리한지 노출·품절·실제 정산으로 비교해야 한다.

## 3. 현행 자동 조정의 범위와 무효 조정

현행 `r3/adaptive.py`는 정해진 필드의 제한된 실험만 수행한다. Shop 허용 필드는 `inventory_target_units`, `category_weights`, `assortment_coverage_fraction`, `shop_margin_fraction`이다. 원본 `policy.json`을 스스로 고쳐 새 규칙을 만드는 기능은 아니다.

관측된 Shop adaptive version은 19이고, 가구/침구>가구>침대/매트리스 가중치 1.1 및 커버리지 비중 0.4의 trial 상태다. 이는 개선이 검증·승격됐다는 뜻이 아니다.

중요한 중첩이 있다. adaptive가 허용하는 재고 목표 10~90보다 활성 championship 상한 180이 우선한다. 순수 함수 비교에서 목표 60, 65, 90은 모두 유효 상한 180을 반환했다. 따라서 이 매개변수의 조정이 현재 활성 경로의 수량 상한을 바꾸지 않는다. 모든 자동 조정이 무효라는 주장은 아니며, 가중치와 다른 경로는 따로 평가해야 한다.

`target_stock()`의 양의 마진 판매 횟수 문턱, 목표 서비스 수준, 새 SKU 매입량 제한 등은 현행 조정 허용 목록에 없다. 제한된 수치 자동 조정과 규칙 구조의 자율 재설계를 구분해야 한다.

## 4. v14에 필요한 권한과 검증

새 설계는 하위 분석 역할이 전략 규칙 변경 후보까지 제안하도록 명확히 했다. 순서는 다음이다.

1. SKU/등급/보증/가격대별 노출과 품절·정산을 연결한다.
2. 각 매입 후보가 수요, 수익, 현금, 품목 수, 공급 시간 중 어디에서 막혔는지 기록한다.
3. 무작정 상한을 올리는 대신 서비스 수준·확대 매입 문턱·탐색 배분 등 해당 원인의 변경 후보를 만든다.
4. 최종 유효 설정과 실제 선택이 달라지는지 확인해 무효 조정을 탈락시킨다.
5. 지연·실패·비용·정확성·실제 경제적 효과의 검증을 통과한 범위만 적용한다. 자료가 부족하면 현행 유지다.

Main에는 사전에 계산된 제한된 정책 패킷만 전달한다. 의미 해석·도구 생성은 백그라운드에서 수행하고 자원·DB 경합을 측정한다. 기존 수치 경로는 이미 빠르므로 하위 Agent 수 증가 자체가 거래 속도 향상을 보장하지 않는다. 외부 시장 장애나 공급 창 제약도 프레임워크만으로 제거되지 않는다.

공식 규칙과 이미 약속한 보증, 실제 환불 의무, 서명·SKU·중복 결제 보호는 자율 변경 대상이 아니다. 현금 완충 비율의 연구와 실제 의무의 임의 축소는 다르다.
