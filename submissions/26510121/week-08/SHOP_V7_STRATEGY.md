# Shop v7: 외부 주문·자금 회전·빠른 결제로 순위 추격

사용자는 2026-11-05 shop의 1위 추격 전략 구현과 시장 구조의 기회 조사를 승인했다. 기존 v6는 이익이 나는 판매와 연결 복구를 확인했지만, 상위 가게의 book·매출 증가 속도에 미치지 못했다. v7은 추가 현금을 가정하지 않고 현재 자본의 회전과 주문 커버리지를 개선한다. 1등을 보장하는 전략이나 시장의 보안 취약점을 입증한 것은 아니다.

## 공식 규칙에서 찾은 기회

공식 원문과 공개 board·shops·공급 할증은 `logs/shop-edge-source-20261105T065205948907Z.json`에 보존했다. 공개 웹 검색에서는 과거 Round 2 분석도 발견했으나, 현재 설계의 근거는 최신 Round 3 공식 원문과 실제 데이터로 제한했다. 공유 `scripts/market_kit.py`는 읽기만 했다.

1. 공급은 20분마다 약 3분 열리고 호출은 10초에 한 번이지만, 한 호출의 수량은 1~20개다. 기존 SKU별 최대 6개를 수요와 관계없이 늘리지는 않는다. 실제 가용 시간 안에서 원가 이상으로 반복 판매된 SKU는 최대 12개 범위의 묶음 매입 대상으로 삼는다. 공산품 최대 공급 원가와 보관 비용은 계속 전액 예약한다.
2. Shop ALL은 book 50%·매출 30%·별점 20%의 백분위다. 순위 문턱을 넘는 예상 기여를 자금과 보유 시간으로 나누어 매입 후보를 비교한다. 작은 단가의 탐색 상품이 공급 호출을 독점하지 않도록 호출당 자본 기회비용과 탐색·품목·카테고리 제한을 둔다.
3. 공급 등급의 비중은 공개되어 있고, 원장은 등급과 보증 조건을 보여 준다. 모든 공산품에 일괄 15% 환불 비용을 붙이는 대신 A/B/C 공급 비중과 동일 등급·보증의 관측 체결가를 연결한다. 무보증 판매에는 환불 비용을 지어내지 않는다. 보증 판매에는 성숙한 품질 표본의 보수적 위험 또는 기존 미확인 위험을 반영한다. 관측이 부족한 등급은 혼합 조건의 기존 보수 가정으로 남긴다.
4. 규칙상 필요한 서명·인증·ACP/AP2 검사는 유지하면서, 숫자로 정해지는 일반 견적·수락과 전액 예산이 확보된 매입 계획은 모델 대기 없이 결정한다. 큰 개별 판매의 비평 검토는 유지한다. 실제 기존 모델 대기는 shop actor 평균 2.40초, critic 평균 3.94초였다. 반복 협상에서는 이 시간이 누적된다.
5. 이미 제시한 가격 이상을 고객이 제안하면 기존 가격으로 즉시 수락할 수 있다. 불필요한 추가 counter를 없앴다. 희소한 가격 표본에서 모든 가격의 전환율이 같다고 가정해 최고가만 고르는 문제에는, 공개 체결가를 기준으로 한 명시적인 가격 반응 가정을 사용한다. 이는 관측된 인과 탄력성이 아니다.

공식 출처: https://market.ourolabs.ai/agent.md, https://market.ourolabs.ai/api/board, https://market.ourolabs.ai/api/shops, https://market.ourolabs.ai/api/supply-prices.

## 매입 모델

`r3/shop_growth.py`는 가용 시간으로 보정한 실제 이익 판매 빈도, 외부 체결 수요, 공급까지의 시간으로 목표 수량을 계산한다. 큰 묶음은 실제 양의 이익 판매 3건 이상이 있어야 가능하다. 방문이나 게시판 문구만으로는 그 조건을 채울 수 없다. 미관측 탐색 SKU는 한 개와 탐색 예산 안에서만 산다.

추가 한 개가 팔릴 가능성은 포아송 수요 가정의 꼬리 확률로 계산한다. 이미 가진 수량과 새로 선택한 수량이 늘면 그 다음 한 개의 판매 가능성은 낮아진다. 이는 투명한 시나리오이며 실제 수요 분포를 확인했다는 뜻이 아니다. 추가 수량의 예상 book이 음수가 되면 매입을 중단한다.

매입 호출 수를 실행 가능한 시간 안에서 먼저 정한 뒤 그 안에 자금을 배분한다. 계획을 만든 다음 잘라서 예산이 남는 경로를 제거했다. 실행 직전에는 현재 잔액과 공급 창을 다시 확인한다. 공급의 10초 호출 제한은 그대로 지킨다.

## 관측·교정

- 기존 buyer 모델·API 모델·승인된 키·실행 기한은 유지한다. shop의 새 버전만 별도로 기록하여 buyer의 성숙 대기 시계를 다시 시작하지 않는다.
- 과거 버전의 원가 이하 판매가 새 버전의 마진 인상 신호로 반복 사용되지 않도록, 현재 shop 버전 이후의 원가 확인 판매를 별도로 평가한다.
- 보증 의무 전액 준비금, 현금 하한, 최대 공급 할증, 재고 집중과 탐색 한도, book 하락 시 냉각·제한 복구를 유지한다.
- 시장 종료 시각을 새로 가정하지 않는다. 실제 거래와 단기 운영 지표는 공급 주기마다 관찰하고, 공산품 품질과 전략 실험 채택에는 성숙한 표본을 요구한다.
- 신규 주문·결제·매입에는 실제 서버 결과만 성과로 기록한다. 리플레이 수익과 시나리오 수량은 성과로 합산하지 않는다.

## 검증 기록

변경 전 동결 입력의 `replay_shop_growth.py`는 읽기 전용 SQLite와 메모리 캐시만 사용한다. 시장 주문과 모델 API를 호출하지 않는다.

## 시장 공통 장애 관측

16:14 KST에 공개 board의 81개 shop이 모두 alive=false이고, 공개 `/api/shops`가 HTTP 200으로 빈 목록을 반환했다. 동시에 우리 가게와 상위 가게 등 여섯 곳의 agent card는 이 PC에서 HTTP 200으로 응답했다. buyer 46개는 online이었다. 근거는 `logs/market-connectivity-20261105T071427077375Z.json`이다. 이는 가게가 모두 종료되었다는 증거가 아니라 시장의 shop 판정·탐색 경로나 시장 서버와 가게 사이의 통신 문제를 시사한다. 서버 내부 로그가 없어 원인은 확정하지 않았다. 런타임의 정상 공개 경로를 불필요하게 재등록하거나 교체하지 않고 복구를 관찰한다.

이후 같은 공개 주소에 대해 기존 소유자 claim과 shop 키로 재등록했을 때 시장이 `cannot read an agent card ... (TimeoutError)`를 반환했다. 이 PC에서의 HTTP 200과 시장 서버에서의 접속 성공은 다르다는 것을 확인했다. 최초 소유자 claim을 빠뜨린 거절과 이후 시장 측 timeout은 `logs/shop-reregistration-attempts-20261105T0724.json`에 도구 응답의 요약으로 기록했다. 사용자가 이후 등록 복구를 알렸으며, 이 일시적인 장애의 서버 내부 원인은 여전히 확정하지 않았다.

새 감독 로직은 30초마다 시장 검색 목록을 확인한다. 시장 목록이 통째로 비면 재등록을 반복하지 않고, 우리 가게만 두 차례 누락되면 기존 소유자·키·주소로 재등록한다. 같은 경로의 등록이 두 번 실패하면 대체 터널을 준비한다. 기존 경로는 새 등록이 끝날 때까지 보존한다. 시작 단계에서 시장이 agent card를 읽지 못해 종료된 경우에도 다음 시도는 다른 공급자를 우선한다.

localhost.run SSH 경로도 예비 경로로 추가했다. 공식 문서의 `nokey` 계정을 사용하며 개인 SSH 키·에이전트를 사용하지 않는다. 최초 호스트 키는 작업 폴더에 기록하고 이후 변경은 거절한다. 실제 연결 수립은 확인했지만, 이 예비 주소로 시장 거래를 검증한 것은 아니다. 이 공급자는 무료 도메인이 주기적으로 바뀌므로 감독 로직의 재등록이 필요하다. 근거: https://localhost.run/docs/faq, https://localhost.run/docs/cli.

정상 노출이 두 차례 연속 확인되면 `deploy_shop_when_ready.py`가 기존 런타임의 임대를 정상 해제한 뒤 새 watcher를 시작한다. 준비 중 소스가 바뀌면 해당 배포를 취소하며, 기존 신원과 저널은 유지한다. 배포 후 공개 접속과 역할별 전략 버전을 검증한다. 전체 장애 중 새 매입은 중단한다.

최종 전체 **134개 통과**: `logs/shop-v7-deploy-tests-20261105T0736.txt`. 전체 장애에서 재등록 폭주를 피하는 경우, 우리 가게만 누락된 경우, 재등록 대기 중 전체 시장이 다시 사라진 경우, 시작 단계의 터널 실패 후 다른 경로를 선택하는 경우를 포함한다.

거래 수 자체가 목적은 아니다. 평가할 것은 실현 book 증가, 매출, 미판매 재고의 체류 시간, 품절로 놓친 외부 주문, 환불·품질 결과와 같은 기간 경쟁자 대비 변화다. 낮은 가격으로 매출만 만들기, 같은 소유자끼리 거래하기, 근거 없는 별점·투표, 환불을 뒤로 미뤄 일시적으로 점수를 보이는 방식은 이 설계의 성장 경로로 삼지 않는다.
