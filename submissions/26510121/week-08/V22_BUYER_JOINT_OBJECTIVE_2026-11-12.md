# Buyer v22: 패치 3.6과 전체 목적함수

목표는 공식 Buyer ALL의 기대 증가율이다. Saved 순위 0.5, Forum 원점수 0.3, Deal 순위 0.1, Post 순위 0.1을 함께 평가한다. 현재 Saved 평균을 유지하는 가격을 강제하면 거래와 정보 생산의 기회를 잘라내므로, 그 가격은 비교용으로만 남겼다.

## 구현

- 공식 규칙의 분모까지 판별한다. 3.6 정상 거래는 `min(1, (L-P)/(L-C))`이다. 미제공·고장 -1과 확인된 전액 환불 0은 유지한다. 모르는 점수식은 호환된 것으로 표시하지 않는다.
- 주문 예산·실제 품질·유통기한·인증·서명·보증·결제 검사는 유지한다. 현재 평균 Saved에서 도출한 가격은 구매를 금지하지 않는다.
- Main은 구매, 추가 협상, 탐색 지속을 비교한다. Saved가 낮아지는 거래도 Deal 순위 이득이 더 크면 선택한다. 전체 기대 점수가 불리하면 다른 거래를 찾는다. 즉시 완료되는 서명된 제안도 같은 검사를 받는다.
- 매 60초의 `buyer_cost_observer`가 실제 우리 Shop 정산의 원가 표본을 등급·종류별로 집계한다. Main에는 최대 9개 숫자로 된 원가 시나리오를 전달한다. 선택된 판매 표본이라는 편향과 다른 판매자의 할증 차이를 명시하며, 적은 표본은 공개 공급 범위 시나리오로 축소한다. 180초 경과·규칙 변경 시 오래된 추정을 사용하지 않는다.
- 원가 최저값 하나를 기대값으로 사용하지 않는다. 각 원가 시나리오의 점수를 각각 계산한 뒤 평균한다. 이는 확률이 검증된 정확한 원가 예측이 아니다. 공급 원가가 정가 이상일 때의 공식 점수 처리도 공개 문서만으로 확정하지 않는다.
- 이전 점수식의 가격 거절 기록·경로 실패·실험 보상을 새 점수식과 섞지 않는다. 기술적 장애와 유통기한·품절 사실은 필요한 범위에서 유지한다. 기존 원시 이력은 삭제하지 않는다.
- 원가가 비공개인 정상 구매를 정확한 Saved 보상으로 기록하지 않는다. 초기 예상, 성숙한 품질 사실, 확정된 점수를 구분한다. 같은 단위의 확정 보상이 없으면 자동 실험 우월성을 주장하지 않는다.
- 기존 시장 연구·반대 검토·게시판 관측 에이전트는 네 항목과 경쟁자 추세를 함께 보도록 컨텍스트를 갱신한다. 거래에 임의의 좋아요·게시물 보상을 붙이지 않는다. 게시판은 실제 전송·관측된 평가 결과로 별도 개선한다.
- Main 계산에는 새 LLM 호출을 넣지 않는다. 기존 모델 구성, Astra 제외, 일일 비용 상한 없음, Shop 수요·현금 안전장치는 유지한다.
