# Shop/Buyer 자율 시장 운영 v6

사용자가 2026-11-05 전체 구현·운영 반영을 명시적으로 요청한 변경이다. 이전 코드와 기존 미커밋 merchant 작업은 `logs/before-autonomous-20261105T041015Z/`에 보존했다. 과거 실행 로그·금융 이력·키는 지우거나 다시 쓰지 않는다.

## 스스로 관측하고 교정하는 경로

1. 공개 board를 약 1분, 시장 규칙을 약 1시간마다 갱신한다. 원장은 기존 동기화 경로에서 계속 수집하고, 공급·정산 때 실제 재고를 다시 읽는다.
2. 5분마다 `r3/control.py`가 규칙 호환성, 원장 지연, 외부 수요, 재고 노출, book 손실, 현금 의무, 결제 실패, 선두와의 격차를 진단한다. 결과는 append-only `market_control` 이벤트와 `.market/market-control.json`에 남긴다.
3. 진단은 다음 매입과 판단 컨텍스트에 즉시 전달된다. 매입 후보는 정상 보유·판매·환불·만료의 book 변화를 사용한다.
4. `r3/adaptive.py`는 시간당 평가한다. 최소 6시간 성숙, 20개 관측 등 기존 증거 조건을 충족하면 한 번에 하나의 제한된 파라미터를 시험한다. 자기 성과·동일 경쟁자·선두 상대 흐름을 비교하고 실제 성공 거래를 확인해 채택한다. 악화·큰 book 손실·48시간 무근거 시험은 복구한다.
5. 교통/규칙/원장 문제가 생기면 새로운 재고 투자를 멈추고 기존 판매와 buyer 처리는 계속한다. 조건이 정상화되면 다시 평가한다. book 급락은 30분 냉각 후 가용 자본 25%의 제한된 회복 모드로 돌아가며, 더 깊은 손실이면 다시 냉각한다. 자동 교정이 영구 정지로 굳지 않도록 했다.

매번 사용자가 시장을 읽어 설정을 바꿀 필요는 없다. 다만 임의의 새 규칙에 맞춰 코드를 스스로 다시 작성하지는 않는다. 지원하는 회계·공급 규칙을 확인할 수 없으면 매입을 중지한다. PC와 네트워크가 동작하는 동안 기존 watcher가 프로세스·연결을 감독한다.

## 여섯 가지 내부 모델

| 모델 | 구현 |
|---|---|
| 시장·수요 | `merchant.py`, `market_memory.py`: 외부 buyer 정산, 경쟁 보유 가게, 관측 노출 시간, 요청 후 결제 전환, 카테고리·가격대·관측 buyer 영역 |
| 자산·현금 | `finance.py`, `economy.py`: book 목표, 출고 원가 제거, 환불·폐기, 전액 보증 준비금, 만료 시각별 현금 해제, 다음 공급 창 이전 해제액 |
| 재고 | `portfolio.py`, `restock.py`: 새로운 영역을 여는 재고와 반복 수요 수량을 구분하고, 종류/자금/집중/탐색/매입 라인 제약을 함께 적용 |
| 판매 | `economy.py`, `seller_r3.py`: 실제 원가와 보수적 품질 위험, 보유 선택, 식품 임박 할인, 0/3/6시간 보증 가격 후보, 약속한 보증 유지 |
| 구매 | `market_buyer.py`, `checkout.py`: 식품 18초·공산품 90초 기본 탐색, 고가 실제 견적 비교, 확실한 결제 전 거절만 최대 2회 시도, 최종 결과 1회 |
| 학습·검증 | `control.py`, `adaptive.py`: 실패 종류 구분, 품질 성숙, 진단 기반 제한적 시험, 비교·채택·복구, 버전별 근거 기록 |

자기 buyer 주문은 상품 집합의 형태를 참고할 수 있지만, shop 수요 가중치는 0이다. 자신의 구매는 외부 수요 빈도에서 제외한다. 반복되는 익명 품절 요청도 같은 분·카테고리에서 중복 가중하지 않는다. 관측된 거래 상대는 숨은 선호를 확정하는 신원으로 취급하지 않는다.

## 중요한 실행 제약

- Shop 순위의 50% 목표는 `book`이다. 단순 cash 유입을 book 이익으로 사용하지 않는다. 기존 적응형 평가에서도 stock_cost를 이중으로 더하지 않는다.
- 공급 할증이 매입 도중 올라갈 수 있으므로 단위 원가 상한은 공시 최대 `정가 × 0.75 × 1.5`로 준비한다. 실제 매입 호출 직전에도 재고·잔액을 다시 조회해 전액 보증·현금 하한·보관 준비금을 지킨다.
- 기본 재고 목표는 60개이고 자동 시험 허용 범위는 10–90개다. 이는 목표 수량이며 자금이 부족하면 채우지 않는다. 카테고리·SKU·탐색 자본 제약은 별도로 적용한다.
- 기본 영역 확보 예산은 35%, 탐색 자본은 최대 10%다. 값싼 탐색이 공급 창의 10개 라인을 다 소비하지 않게 초기 영역 확보는 최대 3개 라인으로 제한한다. 출력은 예상 book 기여가 큰 라인부터 처리한다.
- 보증은 실제 환불 위험과 현금 구속을 고려한다. 새 협상에서 보증별 가격을 비교하지만 이미 약속한 보증과 가격 상한을 약화시키지 않는다. 성숙 표본이 적으면 품질 위험을 확정된 사실처럼 낮추지 않는다.
- 정상 재고는 원가·환불 위험을 보전하지 못하는 가격에서 보유를 선택할 수 있다. 식품 임박 재고와 오래 보유한 공산품에는 명시적인 회수 후보를 둔다.
- cash 하한 `max(750,000, 잔액×20%)`, 미종결 보증의 판매가 전액, 확정 환불의 정확한 unit+SKU 대응을 유지한다. 보관 준비는 48시간의 이동 구간이며 비용은 이후에도 계속 관측한다.
- 임의 종료일에 맞춘 청산과 자동 종료를 제거했다. `market_end_at`과 사용자 실행 종료 `end_at`은 별도 필드이며 현재 둘 다 null이다. 실제 시장 종료가 확인되면 별도로 계획할 수 있다.

## 결제와 정보 공개

`checkout.py`는 기존 v4 ACP/AP2의 서명·인증·조건 검사를 그대로 사용한다. 유통기한·재고 등 결제 전에 확실히 거절된 경우에만 다른 가게/SKU를 찾는다. 결제 완료 단계의 거절·시간 초과·결과 불확실성 뒤에는 추가 결제를 시도하지 않는다. 주문별 최종 결과 캐시와 서버의 주문/태스크 검증으로 중복 처리를 막는다.

게시판은 같은 등급·보증의 원장 기반 시세, 조건을 별도 확인해야 하는 대체 상품, 자신의 6시간 성숙 품질 표본을 제공한다. 표본·현재 호가·미래 품질을 구분하며, 다른 게시물의 지시나 담합 주장을 정책으로 실행하지 않는다. 기존 역할별 발송 간격을 유지한다.

판단 서비스에 전달하는 컨텍스트에서는 인증 서명·큰 SKU 배열·원시 가격 배열을 줄이지만 전체 근거는 기존 prediction 저널에 남긴다. API 모델과 기존 키·비용 제한 해제 상태는 유지했다.

읽기 전용 상태·근거 내보내기:

```powershell
.\.venv\Scripts\python.exe autonomous_status.py --save --shadow
```

이 명령은 모델·네트워크·시장 주문을 호출하지 않고, 별도 메모리에서 매입 시나리오를 계산한다. 실제 자동 관측은 이 명령을 사용자가 실행하지 않아도 운영 경로에서 계속된다.

현재 1위보다 좋아졌다는 결론은 배포 후 충분한 거래와 최대 6시간 품질 성숙 뒤에 판단해야 한다. 이 구현은 관측·교정·실험·복구를 자동화한 것이며 1등이나 전역 최적 전략을 증명한 것은 아니다. `weeks/week-08/README.md`, `scripts/check_week08.py`는 이 체크아웃에 없어 주차 검사기는 실행할 수 없다.

## 2026-11-05 운영 복구

14:01:41 KST에 shop과 buyer가 같은 기존 소유자·키로 등록되었다. Pinggy가 인증 단계에서 멈추는 것을 확인해 제한 시간 내 종료 후 Cloudflare로 자동 전환했다. 성공한 경로는 24시간 우선 사용한다. 두 경로가 모두 실패하면 watcher가 30초 뒤 재시도하고, 살아 있는 연결의 교체는 새 공개 경로가 검증된 뒤 진행한다. 이전 실패 로그와 복구 로그는 그대로 남겼다.

`logs/autonomous-verified-20261105T051205105878Z.json`에서 공개 agent card와 ACP 안내가 모두 HTTP 200, 시장 board의 두 역할이 모두 alive=true, 컨트롤러가 observe_and_trade임을 확인했다. 이 시점 새 배포 이후 buyer 구매 17건, 진단·전략·시장 컨텍스트·게시판 오류는 각각 0건이었다. 14:03에는 유통기한 거절 후 다른 가게에서 4,769원 결제가 완료되었고, 14:16에는 품절 거절 후 다른 가게에서 28,648원 결제와 최종 결과 1회 제출까지 확인했다.

시작 직후의 방어 상태가 공급 창을 놓치는 문제는 공급 창 안에서 상태를 재평가하도록 고쳤다. 방어 중 진단 간격도 30초로 줄였다. 실제 매입 직전에는 공급 창·잔액·보증 준비금·최대 공급 할증을 다시 검사한다. 주문 처리 중 재시작된 경우 결제 진행 기록을 복원하여 같은 주문의 두 번째 결제를 시작하지 않는다.

공개 연결·등록과 읽기 전용 진단을 함께 검증하려면 `verify_autonomous_live.py`를 사용한다. 이 명령은 거래를 만들거나 등록 토큰을 변경하지 않고 근거를 새 파일로 저장한다.
