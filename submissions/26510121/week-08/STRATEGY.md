# Round 3 준비와 memory-v1 전략

HTML 대응: SETUP STEP 1–3은 연결 준비, R3는 키트의 결제 흐름,
HW의 ‘값 다시 정하기’는 아래 정책을 비교할 후속 실험이다.
이번 변경으로 과제 결과나 최적 전략이 입증됐다고 주장하지 않는다.

## 적용한 정책

| 역할 | 기존 정책 | memory-v1 |
| --- | --- | --- |
| Shop | 항상 하한가를 첫 호가로 제시 | LLM이 품목별 실제 호가·합의·정산·취소 기록을 보고 호가와 수락을 판단 |
| Buyer | 예산 안의 첫 호가는 대체로 즉시 수락 | 신뢰할 만한 구매 완료를 우선하면서 자신의 실제 구매가를 참고해 유용한 반대 제안 여부 판단 |
| 가게 선택 | 최근 개인 경험과 약한 공개 후기 | 기존 기준에 평생 개인 거래 요약을 제한된 가중치로 보완; 일정한 탐색 유지 |
| Round 3 성공 | 영수증과 결제의 구분 필요 | 시장 검증과 mandate 정산 증거가 있는 거래만 성공 경험으로 인정 |

가격은 여전히 실제 OpenAI 모델이 결정한다. 코드는 하한가·예산·품목·서명·실제 제안과
수락가의 일치를 검증하며, 공식 키트가 checkout과 mandate를 처리한다.
가게 카드의 ‘항상 최소 가격’ 표시는 바뀐 정책과 일치하도록 명확한 호가·서명·결제 지원 설명으로 바꿨다.

Buyer는 완료 가능성이 비슷하면 가격과 속도를 비교한다. 작은 할인 때문에 구매 전체를 잃지 않고,
직접 경험이 충분하지 않은 가게도 제한적으로 탐색한다. 자기 모델 장애를 상대의 잘못으로 평가하지 않는다.
Shop은 높은 가격으로 성공한 한 건보다, 팔리지 않은 기회까지 포함한 이익을 본다.
다른 buyer의 비공개 예산은 메모리 입력으로 제공하지 않는다.

## 메모리

- 운영 DB: `../week-07/.market/experience.sqlite3` (Git 제외). SQLite WAL로 seller와 buyer가 동시에 기록한다.
- 이벤트 식별자로 중복을 막고, 재시작해도 기록이 유지된다. 원본 JSONL 로그는 편집하지 않는다.
- buyer는 상대·품목별 전체 관찰, 실제 시장 검증 구매, Round 3 정산, 가격·소요 시간을 조회한다.
- seller는 품목·Round별 호가 기회, 합의, 정산, 취소, 미확정 상태를 따로 조회한다.
- 영수증 발급은 정산이 아니다. 응답 없는 협상도 거절로 단정하지 않는다.
- 기록은 계속 보존하고, seller 모델 입력은 최근 2,000개 판단에서 요약한 최대 12개 가격 그룹으로 제한한다.
- 외부 리뷰·상대의 자유 문장·모델의 요약 문장은 신뢰 사실로 DB에 승격하지 않는다.
- 공식 테스트는 `MARKET_LIVE=0`과 별도 buyer JSONL을 사용해 운영 DB에 합성 거래를 넣지 않는다.

보존된 stash와 실제 로그에서 buyer 관찰 517건, 시장 피드백 246건,
seller 판단 1,491건을 처음 복원했다. 이후 실제 거래가 추가된다.
이 수치는 전 시장의 거래 수가 아니라 복원한 개인 기록 수다.
오래된 자료의 Round/정책 버전 한계와 읽은 소스는 `logs/memory-bootstrap-*.json`에 남겼다.

복구/재구축 명령 (원본 읽기만 수행, 같은 이벤트 재수입은 중복되지 않음):

```powershell
.\.venv\Scripts\python.exe submissions/26510121/week-08/bootstrap_memory.py --history-ref 'stash@{0}'
```

## 경쟁 전략과 측정 한계

정상 서명 거래의 집중은 담합을 입증하지 않는다. 최근 6,000개 이벤트는 전체 시장 기록이 아니다.
편중 분석은 보조 자료이며, 이번 구간에서 기준을 충족한 상호구매 쌍은 0이었다.
자동 신고나 허위 후기를 생성하지 않고, 확인된 개인 경험·가격·결제 신뢰로 재방문을 얻는 방향을 사용한다.

가게 선택의 80:20 혼합 가중치와 7회당 탐색은 시작 가설이다. 최적이라고 측정된 값이 아니다.
다음 비교에서는 같은 품목·Round 안에서 정산 성공률, 기회당 정산 마진, 거래가,
소요 시간, 모델 호출 수를 함께 봐야 한다. 이전 데이터의 정책 정보가 없는 행을
고정 하한가 대조군이라고 임의로 분류하지 않는다. 시장 구성 변화가 있어 단순 전후 비교는 인과 증명이 아니다.

## 운영과 다음 단계

두 역할은 기존 `../week-07` 에이전트·이름·서명 키로 실행한다.

```powershell
& .\submissions\26510121\week-07\agent-market\join.ps1 -BuyerOnly
& .\submissions\26510121\week-07\agent-market\join.ps1 -ShopOnly -TunnelProvider pinggy
```

claim code는 ignored `.market/owner.env`에서, 승인된 기존 OpenAI 키는 week-06의
로컬 환경 파일에서 프로세스 환경으로만 읽는다. 명령·문서·Git에 값을 넣지 않는다.

현재 키트는 Round 2에서도 계속 거래한다. 새 주문이 Round 3이면 키트가
open mandate → ACP checkout → closed mandate → `/api/settle`을 처리한다.
수동 브랜치 변경이나 재실행 없이 새 Round의 주문을 처리하고 메모리의 Round도 갱신한다.

개장 후 할 일은 HTML **LAB STEP 1**의 `[acp] paid`·`verified True`·`[acp] settled`와
**LAB STEP 2**의 `budget_commitment`·`settle` 기록을 실제 한 건에서 확인하는 것이다.
HW의 거래 수·비교 보고서는 그 다음이다. 개장 전에는 실제 R3 정산 성공이라고 표시하지 않는다.

2026-10-27 20:34 KST 공식 `scripts/market_test_week07.py`가 **25/25 통과**했다.
실행 기록은 `logs/market-test-20261027T113145Z/console.log`에 있다.
이 테스트는 기존 A2A·하한가·예산·영수증·후기 선택 계약의 검증이며,
아직 열리지 않은 실제 Round 3에서 결제를 마쳤다는 뜻은 아니다.

준비 상태를 다시 읽는 명령:

```powershell

```

연속 3회 실패하면 종료하고 로그를 남긴다. PC 재부팅 뒤 자동 시작하는 OS 작업은 만들지 않았다.

```powershell
& .\submissions\26510121\week-07\agent-market\stop.ps1 -ShopOnly
```
