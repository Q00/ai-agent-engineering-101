# Shop v33: 재고 보충 실행 복구

목표는 마지막 공급 기회를 놓치지 않고, 예상 추가 Book이 양수인 신선 재고를 실제로 확보하여 매출·서비스 기회를 회복하는 것이다. Buyer 정책은 변경하지 않는다. 순위나 점수 상승을 보장하는 전략은 아니다.

## 확인한 원인

v32의 20:00~21:44 관측에서는 자유 현금이 충분했지만 공급 실행이 0건이었다. 분석 함수가 시작 시각을 유지한 채 작업 중 갱신된 공개 정산 피드 시각과 비교하여, 정상적인 갱신을 미래 데이터로 판정하고 빈 보충안을 반환하는 경로를 재현했다. 이는 재고 부족의 확인된 원인이며, 모든 미매입의 유일한 원인이라고 단정하지 않는다.

근거: `logs/v32-progress-freshness-repro-20261116-01.txt`, `V32_PROGRESS_2026-11-16_2144.md`.

## 실행 구조

- **회계·리스크실**: 성숙 매출과 실제 환불을 연결한다. 공산품은 검증된 순이익 조건을 유지한다.
- **조달실**: 분석 시작 시각과 검증 시각을 분리한다. 단조 시계로 후보 생성·회계 계산의 경과 시간을 누적하여 피드 신선도를 판단한다. 180초를 넘긴 분석, 오래되거나 실제로 미래인 피드는 계속 거절하고 원인을 기록한다.
- **조달실**: 경과 시간만큼 남은 판매 예측 기간을 줄인다. 추가 단위마다 판매 확률·원가·환불·보관/미판매 비용을 차감하여 양의 예상 Book만 매입한다. 인위적인 수량·자본 상한은 재도입하지 않는다.
- **실행실**: 계산 후 공급 창의 잔여 시간을 다시 확인하여 실행할 수 있는 품목 수만 반환한다. 실제 POST 전에는 기존의 최신 현금·보증 의무·공급 창 검사와 중복 결제 방지를 유지한다.
- **계획실**: 기술적 실패로 나온 빈 후보를 정상적인 매입 보류 계획으로 저장하지 않는다. 유효한 계산에서 나온 매입 보류는 그대로 허용한다.
- **서비스실**: 기존 v32의 고객 조건을 만족하는 품질 우선 출고와 검증된 저평점 집단 회피를 유지한다. 근거 없는 일괄 등급 금지는 추가하지 않는다.

유료 LLM 호출은 계속 비활성화한다. Buyer 전략·성숙도 관측 시계와 금융 원장은 보존한다.

## 검증과 한계

신규 검사는 분석 중 피드 갱신, 회계 계산 지연, 실제 미래/오래된 피드와 만료 분석 차단, 후보 생성에서 검증 시각 전달, 실패 결과의 매입 보류 오인 방지, 공급 종료 직전 실행 수 축소를 다룬다. 회귀 결과는 `logs/v33-full-regression-20261116-01.txt`와 릴리스 명세에 보존한다.

시장 반영은 기존 구매자의 결제 전 안전 지점에서 재시작하고, 공개 카드·등록 상태·실행 코드 해시·실제 공급 완료를 확인한다. `verify_shop_replenishment.py`는 원장을 읽기 전용으로 조회해 별도 시각의 증거 파일을 남긴다. 공급 완료는 매입 성공의 증거이며 이후의 판매·환불·상대 순위까지 개선되었다는 증거는 아니다.
