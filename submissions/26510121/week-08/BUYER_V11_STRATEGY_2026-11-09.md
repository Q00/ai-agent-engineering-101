# Buyer v11: 실제 계약 조건과 성숙한 품질 기록으로 Saved 개선

## 확인한 병목

14:27 KST 종합 검토에서 새 구매 71건은 전부 식품이었다. 공산품 주문 38개는 전부 실패했고, 수집한 공산품 견적 42개도 기존 상한을 넘었다. 이 중 38개는 등급을 읽지 못해 미상 위험 30%가 적용됐다. 다만 고장을 0으로 놓아도 29개 견적은 가격이 맞지 않았다. 따라서 위험 가정을 낮추는 것만으로 해결할 수 없다.

## 적용하는 내부 모델

1. **계약 조건 해석**: metadata, 직접 data, offer/quote/offer_terms, grade_now/claim을 읽는다. 명시된 가격·등급·보증과 서로 충돌하는 구조 필드는 거절한다. 상대의 문구는 선언이며 시장 인증서가 아니다. 등급·보증이 빠진 공산품 제안에는 같은 거래에서 한 번만 조건을 확인한다.
2. **품질 시나리오**: 최근 48시간 공개 정산 중 6시간과 추가 10분이 지난 상품만 exact unit의 고장 기록과 연결한다. 최대 60,000개 정산을 조회한다. 판매자+SKU+등급 20건, SKU+등급 50건, 카테고리+등급 150건 순으로 사용하며, 99% Wilson 상한에 각각 2/3/5%p의 분포 변화 여유를 둔다. 성숙한 자기 구매 기록과 판매자 카테고리의 나쁜 결과도 상한 교차 검증에 반영한다. 공개 피드가 180초 이상 오래됐거나 표본이 부족하면 기존 위험 모델로 돌아간다.
3. **Saved 가격 상한**: 현재 Saved + 0.002를 목표 기여로 삼아 고장, 실제 보증, 가격을 함께 계산한다. 표본이 좋아지면 가능한 거래가 늘 수 있고, C등급처럼 결과가 나쁘면 상한이 더 낮아질 수 있다. 공개 집단은 관측 시나리오이며 개별 상품의 인과적 고장 확률이 아니다.
4. **조건부 제안과 최종 계약**: 미상 등급은 인증 A, 미상 보증은 최소 6시간을 조건으로 계산한다. 실제 최종 계약이 나오면 가격 상한을 다시 계산한다. 명시적으로 약속한 등급·보증이 나빠지면 거절하고, 처음부터 미상이었던 조건은 실제 조건으로 재평가해 통과한 경우만 진행한다. 서명된 가격이 더 낮아지면 실제 양보로 인정한다. SKU·서명·시장 인증 등급·보증·유통기한·중복 결제 검증은 결제 전에 적용한다.
5. **탐색과 협상**: 같은 가게의 같은 SKU·등급·보증에 해당하는 실제 정산 가격을 경로 선택의 과거 근거로 쓴다. 최근 15분의 기술적 실패는 짧게 감점하고 가격 거절과 구분한다. 같은 가게에서 실제 결제한 task ID가 있을 때만 재구매 할인 가능성을 묻는다. 견적 수집은 최대 두 가게 병렬, 총 세 가게이며, 공산품 시간은 주문당 45초, 협상은 세 단계로 제한한다. 주문 시간이 남고 결제 전 거절이 확실한 경우의 기존 복구만 유지한다.

공개 거래 가격은 현재 재고나 할인 약속이 아니다. 실제 제안이 가격 상한보다 높으면 거래를 강제하지 않는다. API 모델은 변경하지 않는다.

## 검증과 적용 방식

`validate_buyer_v11.py`는 제안 정책을 테스트 프로세스에만 합쳐 검증한다. 실제 로컬 HTTP A2A/ACP/AP2, Ed25519 서명, 인증 A등급 공산품 정산, 이중 결제 차단을 포함한다. 별도 테스트로 최종 등급·보증 변경, 조건부 계약 재평가, 가격 인상 거절, 성숙 시간과 피드 신선도를 확인한다. 실패한 첫 검증 기록도 보존했다.

`apply_buyer_v11.py`는 Buyer 관련 다섯 정책 필드만 원자적으로 교체한다. 실행 중인 Shop 프로세스·URL·키·재고·Shop 전략을 재시작하지 않는다. 다음 새 Buyer 주문에서 새 revision이 활성화된다. `inspect_buyer_v11.py`와 `verify_autonomous_live.py`로 적용 버전, 실제 거래와 온라인 상태를 확인한다.

초기 정산과 테스트 통과는 장기 순위 상승의 증명이 아니다. 새 공산품의 유효 기여는 최소 6시간 후 고장·환불까지 성숙한 결과로 판단해야 한다. 현재 raw forum 규칙과 Saved 목표는 기존 Patch 3.5 교정에 맞춰 유지한다.
