# Shop 고객 행동 메모리와 FIFO

2026-11-03 구현. 원문 대화 대신 요청 SKU·카테고리, 숫자 제안 가격, 인증·보증·신선도 언급, 협상 차수, 실제 결제 결과를 구조화해 저장한다. 단순 합의는 결제로 세지 않는다. 모델에는 현재 협상과 관련 카테고리의 요약만 전달한다.

고객 작업 메모리는 최근 방문 1,000건과 고객 이벤트 최대 8,000개를 보관한다. 방문 순서가 FIFO 기준이며, 오래된 고객의 추가 발언이 보관 순서를 갱신하지 않는다. 방문 삭제 시 관련 행동 이벤트·방문 KV·결제자 연결·고객용 ledger 연결도 삭제한다. 같은 방문에서 발언이 많으면 오래된 행동부터 삭제한다. 결제·환불·보증 부채를 관리하는 재무 기록과 원본 실행 로그는 이 FIFO 대상이 아니다. 이는 전체 프로세스 메모리나 모든 로그의 크기를 제한한다는 뜻은 아니다.

익명 방문은 카테고리 행동으로만 집계한다. 시장이 확인한 결제자 이름은 라운드 내 관측 이력을 연결한다. 재방문자를 결제 전에 알아보려면 선택적인 Ed25519 서명 메타데이터가 필요하다. 이름을 주장하는 일반 문자열로 고객을 합치지 않는다.

선택적 `buyer_memory_proof`는 `pubkey`, 정수 UTC 초 `ts`, base64 `sig`를 담는다. 서명 본문은 `r3.protocol.canon`으로 직렬화한 다음 객체다. `shop_pubkey`는 대상 가게 공개키이고 `text`는 실제 전달한 메시지다.

```json
{"scope":"shopper-memory-v1:Seochanit Shop","shop_pubkey":"<shop key>","message_id":"<message id>","text":"<text>","ts":1793706000}
```

증명은 ±300초만 유효하며 다른 가게나 다른 작업으로 옮겨 쓸 수 없다. 살아 있는 재사용 방지 기록 4,000개가 차면 새 증명을 익명으로 처리하고, 만료 전 기록을 강제 삭제하지 않는다. A2A SDK의 protobuf Struct 숫자가 실수로 변환되는 경우도 정수 시각으로 정규화한다.

검증: `logs/verification-20261103T113052154144Z.txt`에 실제 A2A 메타데이터 타입 관련 실패를 보존했다. 수정 후 `logs/verification-20261103T114103959219Z.txt`에서 55개 테스트가 통과했다. FIFO, 재시작, 중복 결제 알림, 익명 분리, 서명 재사용 거부, 실제 A2A 요약 전달을 포함한다.

참가: `logs/manual-join-20261103T113949232913Z.txt`에서 kit 4와 양쪽 `seochanit` 등록을 확인했다. 등록 당시 서버 라운드는 2였으며 Round 3 주문을 기다렸다. 등록은 Round 3 정산 실적을 뜻하지 않는다.
