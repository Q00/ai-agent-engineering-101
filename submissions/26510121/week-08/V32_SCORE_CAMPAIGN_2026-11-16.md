# v32 ALL 문턱 캠페인

목표는 기존 수치 실행·DB 경합 교정을 유지하면서 실제 후보 생성에 ALL +.01~.02 경로를 넣는 것이다. 경쟁자 변화와 품질 결과 때문에 점수 상승은 보장할 수 없다.

## 점수전략실과 Buyer

`r3/score_campaign.py`가 배경에서 공식 보드의 Saved 백분위 문턱을 계산한다. 가장 가까운 문턱과 +.01/+ .02에 해당하는 문턱을 골라 최근 시간당 구매량으로 4시간/8시간 안에 도달하려면 필요한 신규 거래의 평균 기여도를 역산한다. 정적 코호트 계산은 공식 ALL의 정확한 재현이라고 표시하지 않는다.

15분 간격 보드 앵커로 상대 Saved의 변화 속도를 관측한다. 상승하는 문턱은 시나리오 목표를 높여 반영하고, 하락이 계속될 것이라고 낙관적으로 목표를 낮추지 않는다. 불가능한 평균(1 이상)을 요구하는 계획은 입찰 후보로 만들지 않는다. 속도 0, 낡은 보드·정책, 해시 불일치 때는 기존 안전 경로를 사용한다.

`departments.buyer_score_department → market_memory.buyer_assessment → buyer_price_actions`에 숫자 목표가 전달된다. 목표는 입찰 후보를 늘리는 값이며 새로운 구매 상한이 아니다. 기존 전체 목적함수/시간·실제 영수증·가격·보증·인증·사용기한 검사는 유지한다.

모든 비용 시나리오에서 현재 가격의 Saved 기여가 가격 0의 최대 기여와 같으면 추가 가격 인하가 Saved를 더 높일 수 없다. 이때 추가 흥정 후보를 만들지 않고 가능한 즉시 수락 후보를 낸다. 최종 구매·외부 대안 판단은 기존 Main이 수행한다. 타 Shop 원가를 정확히 안다고 가정하지 않으며, 비용 범위·고장·환불은 기존 조건부 시나리오를 사용한다.

## 품질·고객실과 Shop

공식 거래 리뷰를 원장 ID로 연결해 등급×종류별 평가 계정 평균을 집계한다. 한 계정의 반복 평가가 다수 고객의 요구처럼 취급되지 않도록 계정별 평균을 사용한다. 최소 20개 리뷰/5계정과 보수적인 상방 시나리오가 현재 점수용 별점보다 낮을 때만 '지원되는 하방'으로 표시한다. 이 기준은 인과 모델이나 다음 리뷰 보장이 아니다.

해당 근거가 있는 C등급 식품은 사용기한과 C 허용이 모두 명시된 주문에만 선택한다. 근거가 없으면 임의로 C 전체를 막지 않는다. 실제 준비 시점 표본에서는 이 통계 조건을 만족하는 셀이 없었으므로 하방 게이트의 즉시 대량 거절을 주장하지 않는다. 가상 부정 코호트를 넣은 실제 Seller 예약 테스트로 코드 연결은 확인한다.

등급 허용 범위 안에서 품질을 먼저 선택하고, 사용 시점이 불명확하면 같은 등급의 더 신선한 재고를 우선한다. 명시된 사용 조건에는 기존 수요 보존도 함께 고려한다. 협상 중 등급이 내려간 재고는 다시 검사한다. 가격을 임의로 원가 아래로 내리거나 검증 실패한 별점 모델에 긍정적 점수 보너스를 주지 않는다. 이로 인해 기존 재고 만료·가격·전환의 절충이 생길 수 있으므로 성숙한 실제 Book과 리뷰 결과를 추적해야 한다.

## 시장정보실과 Forum

최근 15분의 다른 Buyer가 공개한 Wanted 관측과 같은 카테고리인 기존 증거 기반 비교 글을 우선한다. 공개 수요 관련 표시만 추가하고, 기존 정산/등급/보증/기한·대체품 근거를 유지한다. 공개 요청은 정보 관련성 힌트이며 거래 실행 명령으로 해석하지 않는다. 같은 게시 간격을 유지하고 새 LLM 호출이나 투표·평가 교환 기능은 넣지 않는다.

## 검증과 관측

새 테스트는 다중 Saved 문턱, 상승하는 경쟁자, 포화 후 수락, 단일 계정의 반복 저평가 방지, 실제 Seller의 C식품 계약 게이트, 신선도 우선순위, 공개 수요의 오래된/자체 글 제외를 검증한다. 기존 전체 회귀 검사도 함께 수행한다.

실제 배포 후에는 `score-campaign:v32`, `score_campaign_prepared`, 수치 입찰 후보, `quality_contract` 거절, 실제 정산·리뷰·Book·Saved·Forum 및 비필수 로그 큐를 관측한다. 초기 거래 확인을 +.01~.02 실현 검증으로 표현하지 않는다. 새 역할별 전략 버전은 새로운 평가 구간을 구분하며 과거 원장·보증 의무를 지우지 않는다.
