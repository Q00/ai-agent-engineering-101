# Week 01: 정산 결과 기록 도구 실험

## 현재 상태와 기록 원칙

2026-09-07: 구현 전 설계 기록이다. 아래 선택 이유와 실험 계획은 사용자와 AI 코딩 도우미의 논의를 바탕으로 작성했다. 아직 기준 실행이나 세 번째 도구 구현을 하지 않았다. 예상은 관찰 결과가 아니며, 실행 후 실제 로그를 근거로 결과를 추가한다. 검토만 한 대안을 구현 후 실패한 시도로 표현하지 않는다. 실패를 의도적으로 만들거나 로그를 수정하지 않는다.

## 문제와 선택

모임 비용 자료에서 총지출과 1인당 부담액을 계산하고, 근거와 결과를 파일로 보관한다. 기존 read_file은 원본을 읽고 calculator는 계산한다. 세 번째 도구로 write_note를 선택해 전달받은 텍스트를 작업 폴더 내 허용된 기록 파일에 추가하려 한다. 이 도구 자체는 계산하거나 요약하지 않는다. 기존 내용은 유지하며 성공 또는 실패를 반환하도록 설계할 예정이다.

결과 보관이라는 용도가 명확하고 기존 도구와 역할이 겹치지 않는다. 로컬 입력과 출력으로 검증할 수 있어 외부 데이터 변화도 줄일 수 있다. 도구 호출 순서를 프로그램에 고정하지 않고 모델이 설명과 목표를 보고 선택하도록 한다.

## 설계 단계에서 제외한 대안

| 후보 | 검토 이유 | 이번 실험에서 제외한 이유 |
| --- | --- | --- |
| clock | 기록에 시각을 붙일 수 있다. | 시각 조회만으로 정산 결과 보관을 해결하지 못한다. |
| fetch | 외부 가격 또는 환율을 조회할 수 있다. | 이번 입력에 필요한 값이 모두 있고 네트워크 변수가 추가된다. |
| split_bill | 정산을 전용 함수로 처리할 수 있다. | calculator와 역할이 겹치고 모델이 도구를 연결하는 관찰 범위가 줄어든다. |

위 대안은 구현하거나 실행한 것이 아니다.

## 실행 조건과 요청

- 제공자: OpenRouter
- 사용할 모델 ID: nvidia/nemotron-3.5-lightning:free
- API 주소: https://openrouter.ai/api/v1
- 모델은 AGENT_MODEL 환경 변수로 지정한다. 모델의 현재 사용 가능 여부와 도구 호출 동작은 첫 실행에서 확인한다.
- 키는 OPENAI_API_KEY 환경 변수로만 전달한다. 값은 문서, 코드, 로그에 기록하지 않는다.
- 실행 폴더: submissions/26510121/week-01
- 입력: notes.txt. 설명 비교 중에는 입력을 유지한다.
- starter의 최대 반복 횟수는 8이며 별도의 temperature 설정은 없다.
- 실행 전 Python과 openai 패키지 버전을 기록한다. 실행 로그는 매번 고유한 파일명으로 저장한다.

저장 요청이 있는 공통 프롬프트:

> Read notes.txt. Calculate the total expense and the equal per-person share using the listed expenses and participant count. Record the expense breakdown, calculation, and results in settlement.txt, then report whether the file was actually saved.

저장 요청이 없는 비교 프롬프트:

> Read notes.txt. Calculate the total expense and the equal per-person share using the listed expenses and participant count. Only report the answer; do not save a file.

## 실험 계획과 가설

1. 기존 두 도구로 공통 프롬프트를 실행한다. 읽기와 계산을 하는지, 저장 도구가 없을 때 무엇이라고 응답하는지 기록한다. 파일을 만들었다는 답변과 실제 파일 존재 여부를 구분한다.
2. write_note를 구현하고 같은 요청을 실행한다. 실제 호출과 파일 내용, 계산 결과, 최종 답변을 비교한다.
3. 구현과 입력, 요청, 모델을 유지하며 설명만 비교한다. A는 '텍스트 파일에 메모를 추가한다.', B는 '사용자가 결과의 저장이나 기록을 요청했을 때 사용한다. 작업 폴더 내 텍스트 파일 끝에 내용을 추가하며, 기존 내용은 유지한다.'이다. 구현 시 실제 제약과 설명을 일치시킨다.
4. A와 B 각각에 저장 요청이 없는 프롬프트도 적용해 불필요한 쓰기 여부를 관찰한다.
5. 차이가 없거나 호출이 실패한 결과도 기록한다. 소수 실행만으로 설명의 효과를 단정하지 않는다.

가설: 구체적인 설명은 사용 조건을 더 명확히 전달할 수 있다. 아직 검증되지 않았다. 각 실행 전 settlement.txt의 존재 여부와 기존 내용을 확인하고, 기존 출력은 삭제하지 않고 별도 보관해 누적 기록과 새 실행 결과가 혼동되지 않게 한다.

## 향후 결과 기록

### 세 도구 첫 실행: 설명 A (2026-09-07)

- 원본 로그: logs/three-tools-20260907-131227-429906.txt. 실제 출력 파일: settlement.txt.
- 동일한 저장 요청과 동일 모델로 실행했다. 종료 코드 0, 실제 파일 존재 True이며 로그에 캡처된 파일 내용과 현재 파일 내용이 일치한다.
- 실제 호출 순서는 read_file → write_note이다. calculator는 호출하지 않았다. 최종 답변에 계산식이 있더라도 계산 도구를 사용했다는 증거로 해석하지 않는다.
- 저장된 총액 77600원과 1인당 19400원은 정확하다. 다만 파일에는 비용 항목과 결과만 있고 합산·나눗셈 계산식은 없다. 최종 답변에는 계산식이 있으나, '계산 과정까지 파일에 기록'한다는 요청은 완전히 충족하지 못했다.
- 기준 실행에서는 계산 도구를 두 번 호출했지만 저장하지 못했다. 이번에는 저장에 성공했으나 계산 도구를 생략했다. 도구가 늘었다고 모든 도구를 사용하는 것은 아니다. 단일 실행의 차이를 도구 추가의 확정적인 인과 효과로 단정하지 않는다.
- UTF-8 직접 캡처에서 U+202F 등 최종 답변의 문자가 정상적으로 보존되었다. 이전 로그는 수정하지 않았다.
- 다음 비교에서는 설명 B에 저장 요청 조건과 계산 근거 포함을 명확히 표현할지 검토한다. 설명만 변경하고 입력·요청·모델을 유지한다. 계산 도구 호출을 강제하는 요청 변경은 별도의 실험으로 구분한다. 저장 요청이 없는 비교도 아직 수행하지 않았다.

### 구현 단계

- 문자 깨짐을 방지하기 위해 capture_run.py를 추가했다. 자식 Python 프로세스의 UTF-8 출력을 PowerShell 파이프 없이 로그 파일로 직접 저장한다. 이전 로그는 변환하지 않았다.
- write_note는 경로 인자 없이 제출 폴더의 settlement.txt만 대상으로 삼는다. 빈 입력과 심볼릭 링크를 거부하고, 기존 내용에 UTF-8 텍스트를 추가한다. 계산 로직은 넣지 않았다.
- 설명 A는 실제 고정 경로 설계에 맞춰 `Append a note to settlement.txt.`로 구체화했다. 설명 B 및 비교 결과는 아직 없다.
- 현재 AI 도우미 프로세스에는 OPENAI_API_KEY가 없다. 도구를 추가한 실제 모델 실행은 사용자의 키가 설정된 PowerShell에서 `python capture_run.py three-tools`로 수행해야 한다. 이 단계는 아직 완료되지 않았다.
- 로컬 검증: 설치된 Python 3.9.13의 절대 경로로 verify_local.py 실행 통과. 빈 입력 거부, 기존 내용 유지, 한글과 U+202F의 UTF-8 파일 저장 및 직접 출력 캡처 보존을 확인했다. API를 호출하지 않은 오프라인 검증이다.
- 공식 scripts/check_week01.py 검사 통과: 구문, 세 도구 등록, TOOLS.md, 기존 로그 존재. 이는 새 도구의 모델 실행 성공을 증명하지 않는다. 수업이 안내한 Python 3.10 이상과 현재 실행 버전 차이는 남아 있다.
