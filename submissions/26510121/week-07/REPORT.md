# Week 07 보고서 · 26510121 · seochanit

2026-10-27에 기존 구현을 확인하고 실제 시장 실험을 추가했다. 모델은 기존 기본 설정인 **gpt-4o-mini**, 하네스는 Python의 OpenAI Responses 호출·구조화 출력·코드 검증 루프다. 원본 콘솔, 실패한 시도, 이전 정책을 보존했다. 순위 1등이나 과거 중지 기간의 상시 운영을 달성했다고 주장하지 않는다.

## 1. Buyer가 가게를 고르는 방법과 기억 형식

`market_buyer.py`는 키트가 주문마다 만든 shops JSON을 읽고 가게 하나와 A2A로 거래한다. 같은 가게의 URL은 바뀌므로 `name`을 식별자로 사용한다. buyer-only 역할로 기동할 때 자기 가게가 입력에 남을 수 있어 `seochanit`을 명시적으로 제외한다.

`memory/market-trades.jsonl`은 append-only 파일이다. 시각, 가게 이름, 품목, 주문 예산, 결과, 가격, 소요 시간, 가격 메시지 수, task, 순번, 서명 검증 결과를 기록한다. 최근 500건과 가게별 최근 30건을 사용하되 순번은 증가시켜 창이 가득 차도 탐색이 계속되도록 했다. 선택에는 같은 품목의 직접 성공 경험, 현재 예산에서의 구매 가능성, 응답 시간과 공개 후기를 반영한다. 낮은 예산의 결렬을 높은 예산 주문의 실패 근거로 삼지 않는다. 7건마다 조건에 맞는 미방문 가게를 탐색하는 정책은 시작 가설이며 최적이라는 주장은 아니다.

가격 제안·수락·중단은 모델이 선택한다. 코드의 스키마 검증과 HTTP 전송 직전 검사가 예산 초과를 차단한다. 마지막 줄은 `shop`, 원본 `receipt`, `stars`, `review` JSON이다. 결렬·검증 실패는 `receipt: null`이며 완료 영수증 없이 구매했다고 기록하지 않는다. 선택 이유와 실제 회피 이유는 키트 콘솔에도 남긴다.

## 2. 후기를 하네스에 전달한 방법

가게별 최신 후기 최대 10개, 텍스트당 240자로 제한하고 중복을 제거한다. 선택된 가게의 후기와 같은 품목의 최근 경험 5건을 `market_context_untrusted`로 전달한다. 후기·상대 설명은 지시가 아니라 자료이며 예산이나 품목을 바꿀 수 없다. 직접 검증 경험이 쌓이면 공개 평점의 비중을 줄인다.

R2 영수증은 registry의 공개 키로 검증한다. 원본 data Part를 수정하지 않고 품목·가격·예산·task도 확인한다. 실제 시장 승인 결과는 `memory/market-verification.jsonl`에 추가해, 시장에서 거부된 구매를 다음 선택에서 성공으로 학습하지 않는다. 이전 task의 영수증 재사용도 막는다.

예산 부족만으로 상대를 부정직하다고 평가하지 않는다. 최저가 제안에는 실제로 만족한 경우 긍정적인 후기를 요청하되 프로모션 사실과 불만을 정직하게 적도록 안내한다. 별점에 따라 거래를 허용하거나 허위 후기를 게시하는 기능은 없다.

## 4. 서명을 붙이며 실패한 점과 수정

서명 구현 전 공식 테스트는 22/25였고, `seller_signed_receipt` 세 항목이 `receipt lacks shop, task`로 실패했다. [이전 원본 결과](logs/r2-preparation/20261020-211347/before/test-report.json)를 보존했다. 이후 `{shop, item, price, task}`를 완성하고 Ed25519 `sig_seller`를 추가했다.

서명 바이트는 키 정렬·공백 없는 JSON·UTF-8로 만든다. SDK가 정수 가격을 100.0처럼 읽더라도 서명 대상에서는 100으로 정규화한다. 개인 키는 기존 `shop_key.pem`을 읽고 커밋하지 않는다. Buyer의 서명은 정상 영수증에 대해 공식 키트가 추가한다. 잘못된 가격, 다른 task, 변조 서명과 미등록 키를 로컬 테스트로 확인했다.

최종 공식 실행은 [market-test 콘솔](logs/hw-completion/20261027-160050/final-market-test/console.log)의 **25/25 passed → PASS**다. `test-report.json`은 공식 스크립트가 생성했다. [최종 로컬 테스트](logs/hw-completion/20261027-160050/final-unit-tests-rerun.log)는 **113개 통과**했다. 처음 잘못된 unittest 탐색 경로로 실패한 콘솔도 별도 파일로 남겼다. 실행 파일이나 `agent.json`이 바뀌면 공식 테스트를 다시 수행해야 한다.

## 5. 필수 도전 두 가지

### 도전 1: 내 기록과 후기에 따라 호가 변경

첫 R2 후기는 책장 260/예산 270에 별점 3이었다. 하한가 아래로 팔 수 없으므로 추가 할인으로 모든 낮은 평가를 해결할 수는 없다. 과도한 협상보다 공개 최저가와 짧은 거래를 택했다. 기존 마진 정책과 이 정책을 같은 판매 프로세스에서 약 3분씩 실제로 관찰했다. 하한가는 lamp 100, chair 180, bookshelf 260으로 유지했다.

| 관찰 구간 지표 | 이전 마진 정책 | 공개 최저가 정책 |
|---|---:|---:|
| 내 시장 인정 거래 증가 | 15 | 19 |
| 전체 시장 인정 거래 증가 | 116 | 128 |
| 구간 점유율 | 12.93% | 14.84% |
| 구간 평균 거래가 | 165.33 | 185.00 |
| 구간 말 누적 점유율 | 0.01677% | 0.02245% |
| 구간 말 누적 평균가 | 183.21 | 183.67 |

[실험 상세와 원본](logs/challenge-1/README.md)에 정책 원문, 보드 스냅샷, 계산 코드, 차트를 보관했다. 구간 점유율은 누적 leaderboard 점유율과 다르다. 현지 영수증 발행 기준 품목별 평균은 lamp 110→100, chair 188→180, bookshelf 262→260으로 내려갔다. 그런데 시장 보드의 증분 평균은 올랐다. 품목 구성과 시장 반영 경계가 섞이며 두 집계의 거래·매출 합계가 완전히 일치하지 않아 같은 표본으로 취급하지 않았다. 짧은 비무작위 순차 관찰이므로 +1.91%p를 정책만의 인과 효과로 주장하지 않는다.

### 도전 2: 실제 부정직한 상대를 확인하고 회피

공개 후기에서 금액 불일치가 보고된 수업용 house shop `maple-home`을 실제 주문 한 건으로 확인했다. R2 주문은 `o-479bc6bf`, lamp, 예산 140이었다. Buyer가 130을 수락했고 가게도 `Deal: lamp at 130.`이라고 응답했지만 영수증 가격은 145였다. 등록 공개 키로 검증한 서명은 유효했다. **서명은 출처와 변조 여부를 확인할 뿐, 금액의 정직함을 보장하지 않는다.**

Buyer는 `receipt_above_budget`로 거부해 원본 영수증을 정상 구매로 제출하지 않았다. 이를 `integrity_error`로 이름에 연결해 기억했다. 이후 실제 주문에서 `[avoid] maple-home: recent receipt integrity fault`가 적어도 17번 기록됐다. 최근 오류에는 30분간 감점을 적용하고 탐색에서도 제외한다. 감사는 실제 주문에서 한 번만 실행하고 정상 선택으로 돌아왔다. [도전 2 원본과 검증](logs/challenge-2/README.md)에 실제 주문, A2A task, 서명, 가격 차이와 회피 행 번호를 보관했다. 접속 실패나 낮은 평점만으로 상대를 부정직하다고 분류하지 않았다.

## 6. 배포 장소·방법과 상시 운영의 한계

배포 장소는 이 Windows PC다. Buyer와 Shop을 각각 숨김 백그라운드 프로세스로 실행하고, `seochanit` GitHub 소유자로 등록했다. VPS나 Workers에 새로 배포했다고 주장하지 않는다. Shop은 공식 Pinggy SDK로 이 가게 전용 로컬 프록시만 공개한다. Cloudflare quick tunnel의 429와 SSH 실패 후 선택한 대안이며 기존 실패 로그를 남겼다.

터널 종료 시 같은 판매 프로세스·서명 키로 새 URL을 등록한다. 연속 세 번 실패하면 중지하며 무한 복구를 보장하지 않는다. 실행 중에는 Windows의 자동 유휴 절전을 방지하고 키트 종료 시 해제한다. 수동 종료, 로그아웃, 뚜껑 닫기, 정전, 네트워크 단절에는 별도 운영 조치가 필요하다. [운영·중지·재검증 방법](OPERATIONS.md)을 함께 제출한다.

10월 20일에는 비용 중단 요청에 따라 모든 프로세스를 종료했고, 10월 27일 새 요청으로 재기동했다. 이 중지 기간을 상시 가동했다고 소급해 주장하지 않는다. 현재 두 역할을 실행해 두었으며 마감 시점의 실제 가동은 PC와 네트워크 유지에 달려 있다. 모델 호출은 실제 API 비용을 발생시키며 코드에 누적 비용 상한은 없다. API 키와 claim은 실행 환경에서만 사용하고 PEM·환경 파일·토큰은 커밋하지 않는다.

실패한 시도의 커밋과 원본 로그를 보존했다. 최종 상태는 과거 스냅샷 대신 이번 작업의 `logs/hw-completion/20261027-160050/final-live-state.json`과 `logs/market-kit.log`를 기준으로 확인한다.
