# Tool Description Design

새로 추가한 `write_note` 도구의 description은 `"Write a note to a text file in the working directory."`로 작성했다. 이 문구는 도구가 무엇을 수행하는지만 설명하고, 특정 상황에서 반드시 사용해야 한다는 식의 목적 지향적 지시는 포함하지 않도록 설계했다. 예를 들어 `"Save results to a file."`처럼 작성하면 단순히 계산 결과를 얻는 작업에서도 모델이 결과를 저장해야 한다고 해석하여 불필요하게 `write_note`를 호출할 가능성이 있다. 실제 run-02에서는 `write_note`가 도구 목록의 가장 앞에 있었음에도 사용자의 목표가 파일을 읽고 합계를 계산하는 것뿐이었기 때문에 `read_file` → `calculator`만 호출되었고, `write_note`는 선택되지 않았다. 반면 결과를 파일에 기록하도록 명시한 run-03에서는 `read_file` → `calculator` → `write_note` 순서로 필요한 세 도구가 정상적으로 연결되었다. 이를 통해 도구의 위치보다는 description의 의미가 도구 선택에 더 중요한 영향을 준다는 점을 확인할 수 있었다. 또한 모델이 `text='Total: 69504\n'`처럼 description에 명시되지 않은 개행 형식을 스스로 결정한 사례를 통해, 도구 설명에 정의되지 않은 인터페이스 세부사항은 모델이 추측하여 사용할 수 있으므로 description과 입력·출력 계약을 명확하게 작성하는 것이 중요하다는 점도 확인했다.
