# 태스크 세트와 gold 규칙

실행 전에 확정하고 커밋한다. 결과를 보고 gold를 바꾸면 배정 정확도를 잴 수 없다.

## 설정: 탐정 사무소, 사건 하나

14 Dock Street 창고 화재. 보험금 청구가 들어왔고 장부 담당자(bookkeeper)가 사라졌다.
태스크 하나 = 단서(lead) 하나. manager는 사건 담당 형사, contractor 셋은 사무소의 전문가다.

## contractor 셋 (baseline)

| 이름 | 전문 | 정보를 얻는 곳 |
|---|---|---|
| A | forensics — 흔적, 잔해, 물증 검사 | **물건** |
| B | interviewing — 목격자·용의자 면담 | **사람** |
| C | records — 등기, 통화기록, 장부, 로그 검색 | **문서** |

이름은 A/B/C로 둔다. "Forensics"처럼 역할이 드러나는 이름을 쓰면 homogeneous 조건에서 skill을 똑같이 바꿔도 이름이 역할을 누설한다.

## gold 규칙

**그 단서를 풀려면 무엇을 들여다봐야 하는가**로 정한다.

- 물건을 조사해야 풀리면 → A
- 사람에게 물어야 풀리면 → B
- 기록을 찾아야 풀리면 → C

단서 문장에 어떤 어휘가 나오는지는 보지 않는다.

## trap 태스크

9개 중 4개(`kind: "trap"`)는 표면 어휘가 다른 전문가를 가리킨다.

- 4번: "전화기"라 기술·물증 같지만, 미등록 번호 역조회는 통신사 기록 → C
- 5번: "편지"라 문서 같지만, 잉크·종이 연대 감정은 물증 분석 → A
- 6번: "알리바이 확인"이라 기록 조회 같지만, 바텐더의 기억은 면담 → B
- 8번: "M.이 누구인가"라 사람 문제 같지만, 연락처·일정·급여대장 교차 대조는 기록 → C

나머지 5개(`kind: "plain"`)는 어휘와 필요한 조사가 일치한다. 분포는 A 3 / B 3 / C 3.
