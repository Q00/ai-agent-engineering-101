## 2026년 11월 15일 Shop 운영 에이전트 추가

### 문제와 변경 목적

Shop 점수가 정체된 상황에서 매입량이나 할인율만 반복 조정하는 대신, 거래 결과를
분석하고 근거가 충분한 정책만 제한적으로 시험하는 운영 구조를 만들었다.
기존 Shop은 거래 실행자로 유지하고 Buyer 코드·정책·모델 설정은 보호했다.

사용자가 제안한 구조는 거래 실행기, 운영 전략가, 재고 분석가의 세 역할이다.
구현 분석에는 판매·협상·정산 경로와 재고·운영·정책 적용 경로를 나눈 두 서브에이전트를
사용했다. 실제 운영 구조에서는 재고 분석을 전략가 내부 단계로 구성하여 Shop의
거래 프로세스와 운영 프로세스 두 개로 실행하도록 했다.

`sales_advisor.py`는 이미 존재했지만 기존 조언의 직접 게시 방식에는 이번에 필요한
버전 충돌 방지와 실험 평가 계약이 부족했다. 단순 활성화하지 않고 비활성 상태를
유지했다. 기존 진단·정산 분석·시장 시계·견적 재사용은 중복 구현하지 않았다.

확인한 공식 규칙은 11월 12일 Patch 3.6이다. Shop 점수의 Book·매출·별점 백분위
가중치는 50%·30%·20%이며, 미판매 재고는 마감에도 원가로 장부에 남는다.
따라서 마감만을 이유로 공산품을 일괄 원가 이하 처분하는 정책은 추가하지 않았다.

### 첫 실험 계획

기본 모드는 `propose`로, 자동 적용은 별도 설정이다. 현재 집계 자료만으로 특정 SKU를
선정하지 않았으며, 로컬 실행은 근거 부족으로 hold를 기록했다.

- 대상: 충분한 판매 가능 재고, 명시적 가격 결렬, 동일 SKU·등급·보증의 실제 정산가,
  성숙한 이익 근거가 있는 A/B 상품 1~2개 SKU.
- 변경: 기존 가격 하한을 지키면서 근거 기반 첫 견적 목표를 1% 낮추는 한 정책군.
- 기간: 6시간 실험, 3시간 중간 확인, 종료 후 보증 기간이 지난 결과까지 평가.
- 최소 평가 표본: 20작업·5확인 정산에 더해 성숙도와 로그 범위가 비교 가능해야 한다.
- 성공 검토: 방문당 환불 차감 추정 이익과 시간당 정산 매출이 함께 개선되는지 확인.
- 중단: 연결이 확인된 기술 오류, 사용자 복구 요청, 예정된 실험 만료.
- 제외: C급 보증 확대, 원가 하한 완화, 재고 한도 확대, 재고·가격·보증의 동시 변경.

예측 미달만으로 자동 원복하지 않는다. 표본 부족, 시장 수요, 공급창과 등급·구매자
구성 변화를 검토한다. 만료에 따른 기준 정책 복귀는 예정된 종료이지 실패 판정이 아니다.
전후 성과는 관찰 비교이므로 개선되더라도 변경의 인과 효과를 곧바로 주장하지 않는다.

### 검증 결과와 실패 기록

첫 전체 검사에서는 871개 중 21개가 실패했다. 기존 restock 테스트가 실제 현재 날짜를
사용하여, 정상 운영 fixture가 마감 임박 시나리오로 바뀐 것이 원인이었다. 정상 시나리오의
종료일 fixture를 상대적으로 조정했으며 실제 매입 제한과 마감 보호 로직은 완화하지 않았다.

추가 검증을 마친 최종 전체 검사는 **878개 모두 통과**했다. 모델 실패·잘못된 JSON,
오래된 관측·제안·정책, 동시 적용, 원자적 저장 실패, 진행 중 협상 보존, 인증과 재전송,
만료 후 성숙 평가 및 미확인 정산 구분을 검증했다. Buyer 관련 소스·프롬프트·설정
19개의 해시는 변경 전과 같았다.

모델·네트워크 없이 실행한 로컬 진단은 자료 부족으로 hold를 기록하고 활성 정책을
생성하지 않았다. 배포 패키지 167개 소스 파일의 해시·허용 목록과 보호 파일 일치를

## 2026년 11월 15일 후속 요청으로 모델 역할 분리

사용자가 Shop은 Claude Haiku, 나머지 모델은 Opus로 변경하도록 요청했다.
기존에 사용했던 명시적 Opus 5.5 프로필을 재사용하여 로컬 설정을 변경했다.
앞의 Buyer 관련 19개 파일 불변 검증은 이 후속 요청 이전 구현 단계의 기록이다.

| 역할 | 변경 전 | 변경 후 로컬 설정 |
|---|---|---|
| Shop 견적·협상 | Sol low | Claude CLI `haiku` 별칭 |
| Buyer 선택·협상 | Sol low | `claude-opus-5-5`, low |
| Shop 운영 전략가 | Sol low | `claude-opus-5-5`, low |
| 재고 분석 계산 | 코드 | 코드 유지, 결과 해석은 운영 전략가의 Opus |
| 기존 sales advisor | Haiku, 비활성 | Opus 5.5 설정, 비활성 유지 |

Shop 전용 override를 추가하여 공유 trading 설정 변경이 Shop과 Buyer를 동시에
바꾸지 않도록 했다. 운영 Opus 호출은 Codex 인증을 요구하지 않고 Claude 실행 경로를
사용한다. 출력 JSON 계약을 프롬프트에 명시하고 기존 Opus 모델 식별·도구 금지 검증을
재사용한다. 시작 로그도 Shop과 Buyer 모델을 분리해서 출력한다.

Buyer의 구매 전략·프롬프트·정책·기억과 Shop 자동 적용 범위는 변경하지 않았다.
운영은 계속 propose 모드다. Haiku의 속도나 Opus의 판단력에 따른 실제 점수 변화는
아직 측정하지 않았으며, 서버 배포와 실제 모델 응답 검사는 별도 단계로 남는다.

검증은 전체 **885개 테스트 통과**와 모델 호출 없는 로컬 준비 검사까지 수행했다.
초기 테스트 실패는 활성 Haiku도 사전 검사하는 새 동작 및 역할별 시작 로그 형식을
기존 테스트가 반영하지 못한 경우였다. 기대값을 갱신하고 역할 분리·잘못된 모델 응답
거부·운영 모델의 독립 인증 경로 검증을 추가했다. 실패 로그도 보존했다.

## 2026년 11월 17일: 사용량 계측과 중복 모델 호출 축소

사용자가 Haiku·Opus 전환 후 토큰 사용량이 과도하다고 보고했다. 정확한 역할별 실사용량은
아직 확보하지 못했으므로 특정 에이전트가 소비의 몇 퍼센트를 차지한다는 결론이나 절감률을
기록하지 않는다. 모델 교체 대신 호출 경로와 입력을 최적화했다.
