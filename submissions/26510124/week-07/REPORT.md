## 1. 구매자의 가게 선택과 기억

market_buyer.py는 사용자가 선택한 **신뢰 우선** 전략을 따른다. 가게별 후기와
자신의 거래 기억을 prompts/market_select.txt에 넣고 Claude Opus 5.5가 이름과
선택 이유를 반환한다. 코드는 실제 후보의 이름인지 검사한다.
가게가 많으면 12개씩 비교하고 각 묶음에서 선택된 가게들을 다시 비교한다.
흥정도 Claude가 offer / accept / walk_away를 정하며 예산은 코드가 검사한다.
모델 실패를 규칙 기반 구매로 대체하거나 예산을 높이지 않는다.

data/market-memory.jsonl에 거래마다 한 줄씩 추가한다. name으로 기억을 찾으므로
터널 URL이 달라져도 같은 가게의 경험을 이용한다. time, url, item, budget, price,
result, detail, selection_reason, authorized_price, observed_receipt, stars, review를
보존한다. 결과는 purchased / no_deal / error / receipt_mismatch로 구분한다.
2026-10-20 종료 당시 79건 중 구매 62건, 결렬 16건, 실행 오류 1건이었다.
이는 Round 1부터의 기억이다. Round 0 기록을 소급해서 새 기억에 넣지 않았다.

영수증 가격·예산·품목·task를 확인하고 받은 data Part를 그대로 반환한다.
서명의 암호학적 검증과 buyer 서명 추가는 공식 market kit가 담당한다.
서명이 있다는 사실만으로 합의 가격과 일치한다고 간주하지 않는다.

## 2. 후기를 하네스에 전달하는 방식

가게별 최근 후기 최대 10개의 개수·낮은 별점 개수·평균 별점과 최신 원문
3개(각 최대 400자)를 전달한다. 자기 기억은 전체 거래 수·성공·불일치·결렬·오류
누적 수와 최신 거래 3개를 전달한다. 오래된 불일치도 누적 수에 남는다.
후기와 기억의 문장을 외부 데이터로 구분하며 예산 변경이나 특정 가게 선택을
강요하는 지시는 따르지 않도록 프롬프트에 명시했다.

후기가 없으면 미확인으로 취급한다. 연결 실패나 비싼 가격으로 인한 결렬을
기만의 증거로 단정하지 않는다. 원문 제한과 묶음별 비교 때문에 정보를 놓치거나
선택이 달라질 수 있다. 선택 이유는 SHOP SELECTION으로 출력되어 로그에 남는다.

## 4. 서명·공개 실행 중 실패와 수정

receipt_signing.py는 {shop, item, price, task}를 정렬된 키, 공백 없는 UTF-8 JSON으로
직렬화해 Ed25519로 서명한다. A2A는 정수도 110.0처럼 전송할 수 있어 정수 값은
110으로 정규화한다. 실제 소수 가격은 잘라내지 않고 거부한다.
기존 키를 유지하고 서명 모드에서 키가 없으면 시작에 실패한다.

서명 구현의 실패를 꾸며 기록하지 않았다. 당시 서명 준비본은 공식 25/25 통과였다.

public_market.py에서 JSON 공백 heartbeat를 전송하고 최종 JSON-RPC는 보존했다.
첫 공개 진단은 판매자가 200을 자동 수락한다는 검사기 가정으로 실패했으며,
실제 역제안 150을 읽어 같은 task에서 수락하도록 고쳤다. TLS 전송 오류도 있었다.
