# R3 시도 2의 강화학습 틀

시도 2는 강화학습 틀 안에서 LLM 운영자가 맥락 안 강화학습(in-context RL)으로 정책을 고쳐 나가는 구조임. 사람은 목표와 안전선만 정하고 전략은 넣지 않음. 목적은 시장이 바뀌어도 운영자가 스스로 적응하게 하는 것임 (성수님 결정 2026-11-17)

- 메모리, 컨텍스트, 메타하네스의 자세한 설계는 DESIGN.md 7절, 8절, 14절에 있음
- 이 문서는 MDP 요소가 코드의 어디에 대응하는지만 적음

## 2. 맥락 안 강화학습이 일어나는 곳

- 정책 평가: 커널이 실험(전후 비교, 동시 비교, 묶음)으로 행동의 효과를 재고 숫자만 알려 줌. 되돌리거나 채택하는 결정은 운영자 몫임
  - 잡음보다 큰 차이만 뚜렷한 판정으로 침. 묶음은 묶인 키의 범위 판매로 잼 (11-13)
- 정책 개선: 운영자가 판정, 상태 카드, 기억을 보고 다음 정책 값을 정함. 학습은 가중치가 아니라 프롬프트에 쌓인 경험으로 일어남
- 경험 기록: 모든 행동과 결과가 a2/trajectory.jsonl에 남고, 실험 원장이 a2/experiments.json에 남음

## 3. 컨텍스트 관리 (토큰 절약)

- 깨어날 때마다 새 대화로 시작하고, 상태 카드는 압축판을 씀
- 한 번 깨어남 안의 도구 결과는 최신 것부터 40,000자까지 그대로, 그다음 20,000자까지 잘라서 보여 줌
- 그 이상 쌓이면 대화를 간추린 요약이 대신함 (COMPACT_AT 60,000자)
- 근거와 세부 값: DESIGN.md 8절, 14.2절

## 4. 장기 기억

- memd: mem0 기반 기억 서버. 같은 사실은 새로 쌓지 않고 고쳐 씀
- memfeed: 5분마다 결과와 깨어남 요약을 기억으로 넘김
- 운영자는 상태 카드의 기억 절과 기억 검색 도구로 꺼내 봄
- 근거: DESIGN.md 7절

## 5. 메타하네스

운영자가 무엇을 정하는지가 아니라 어떻게 일하는지를 보고 고침. 정책 값은 건드리지 않음

- 감사자(kernel/auditor.py): 운영자가 깨어날 때 함께 돌며 감사 수치(kernel/audit.py), 도구 표, 실험 원장, 최근 깨어남을 읽고 일하는 방식 지침과 도구 목록(숨김, 보임, 설명, 추천)을 고침
  - 지침에 정책 키의 숫자가 들어가면 거절함
  - 지침 버전마다 깨어남당 실수 수를 전후로 비교해 뚜렷이 나빠지면 이전 지침으로 되돌림 (DESIGN.md 14.5절)
- 조사원(kernel/analyst.py): 운영자의 조사 질문을 여러 단계로 파고들어 결과를 남김. 가게는 바꾸지 않음
- 수정 검증: 훅 코드 수정은 시험을 통과해야 들어감 (kernel/code_edit.py, DESIGN.md 14.4절)
- 하네스 버전과 되돌리기: 운영자가 고친 하네스는 버전으로 남고, 고장 나면 되돌림 (kernel/versions.py)

## 6. 운영 인프라

판단은 하지 않고 위 고리가 끊기지 않게 받치는 아래층임 (2026-11-17)

- 루프 감시자: 2분마다 죽은 시도 2 프로세스와 순위표 저장 창을 다시 띄움. 아무것도 끄지 않고, 배포하는 동안은 쉼 (live/watchdog.sh)
- 자동 시작: 정전이나 WSL 재부팅 뒤 시장, 순위표 저장, 시도 2, 감시자를 다시 켬 (week-09/.market/start-labpc.sh)
- 정책 쓰기 잠금: policy.json은 잠금 파일을 잡은 쓰기만 바꿈 (kernel/policy_edit.py)
- 순위표 저장: 30분마다 공개 순위표를 받아 상태 카드에 넣음 (week-09/.market/boardsnap-loop.sh)
