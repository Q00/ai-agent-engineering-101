## 2. 강화학습 틀

- 안쪽 고리(맥락 안 강화학습): 운영자가 상태 카드를 읽고 정책 값을 고치고, 커널이 실험으로 효과를 재서 숫자만 알려 줌. 학습은 가중치가 아니라 프롬프트에 쌓인 경험으로 일어남
- 바깥 고리(메타하네스): 운영자가 일하는 방식(지침, 도구, 카드, 조사 질문)을 고침. 정책 값은 건드리지 않음
- MDP 요소

## 3. 구성 요소

### 3.1 운영자와 커널

- 운영자(kernel/operator.py): 깨어날 때마다 새 대화로 시작해 카드를 읽고 도구를 쓰고 행동을 정함
- 실험 원장(kernel/experiments.py): 전후 비교, 동시 비교, 묶음 실험. 잡음보다 큰 차이만 뚜렷한 판정으로 침
  - 묶음 실험은 묶인 키의 범위 판매로만 잼 (11-13 수정, 전에는 가게 전체 잡음에 묻혀 판정이 안 났음)
  - 진행 중 실험은 지금 차이가 필요한 차이의 몇 %인지 보여 주고, 표본이 얇으면 숨김
- 정책 쓰기(kernel/policy_edit.py): 운영자의 수정을 시도 1의 policy.json에 씀. a2/LIVE 스위치는 꺼져 있어 거래는 시도 1 훅이 처리함
- 상태 카드의 키 왕복 줄: 2시간 안에 방향을 2번 이상 바꾼 키를 사실로만 보여 줌. 그만 바꾸라는 지시는 넣지 않음

### 3.2 컨텍스트 관리

- 깨어남마다 새 대화, 카드는 사실만 담은 압축판
- 도구 결과는 최신부터 40,000자 그대로, 다음 20,000자는 잘라서, 60,000자를 넘으면 요약으로 바꿈
- 도구는 요약을 먼저 주고 세부는 요청할 때만 줌

### 3.4 메타하네스

- 감사자(kernel/auditor.py): 감사 수치, 도구 표, 실험 원장, 최근 깨어남을 읽고 지침과 도구 목록을 고침
  - 정책 키에 숫자를 붙인 지침은 거절함
  - 지침 버전마다 깨어남당 실수 수를 전후로 비교해 나빠지면 되돌림
- 도구 수명 관리 (23:40 배포): 만든 q_ 도구마다 만든 주체, 쓴 횟수, 마지막 사용을 감사자에게 보여 주고, 48시간 넘게 안 쓴 도구를 표시함. 같은 analyze 코드를 24시간에 3번 이상 돌리면 q_ 도구 후보로 보여 줌
  - 감사자는 숨김(hide), 삭제(remove), 조사원에게 도구 제작 맡김(ask)으로 처리함
  - 마감 시점 만든 도구 14개, 모두 조사원이 만듦, 사용 합계 364번 (11-06 이후 기록)
- 조사원(kernel/analyst.py): 운영자의 질문을 여러 단계로 조사하고, 필요하면 읽기 전용 q_ 도구를 만들어 저장함
- 수정 안전장치: 훅 코드 수정은 시험 통과 뒤에만 들어감(kernel/code_edit.py), 하네스는 버전으로 관리하고 고장 나면 되돌림(kernel/versions.py), 모델이 쓴 코드는 격리 실행(kernel/sandbox.py), 결정마다 시장 규칙 확인(kernel/rules.py)
