# TOOLS.md

## get_exchange_rate

세 번째 도구 `get_exchange_rate`의 설명은 `"Look up the official daily exchange rate from a currency to Korean won (KRW). Give a 3-letter ISO currency code such as USD, EUR or JPY, and a date (YYYY-MM-DD) to get that day's rate, or omit the date for the latest published rate. Call it once per currency."` 로 적었습니다. 목표 통화를 KRW로 고정하고 일반적인 fetch나 임의 통화쌍 조회로 만들지 않은 것은, 이 에이전트의 정체성이 외화 목록을 원화 총액으로 바꾸는 일 하나이기 때문이고, 목표 통화가 설명에 박혀 있으면 모델이 채워 넣어야 할 인자가 하나 줄어들어 없는 통화쌍을 지어낼 여지도 함께 줄어듭니다. 같은 맥락에서 요청 주소도 코드 안에 고정해 두었는데, read_file이 작업 디렉터리 밖 경로를 막는 것과 똑같이 모델이 만들어 낸 URL을 그대로 믿지 않겠다는 원칙입니다. 날짜를 선택 인자로 두고 "omit the date for the latest published rate"라고 적은 것은, 날짜를 못 박으면 같은 입력에서 같은 총액이 나와 재현이 되고 날짜를 비우면 최신 환율로 그때그때 쓸 수 있기 때문이며, 무료 공개 API는 하루 한 번 고시하므로 여기서 실시간이라는 말이 사실은 오늘자 기준환율이라는 점을 설명에 daily라고 미리 밝혀 두었습니다. "Call it once per currency."를 넣은 것은 아직 가설인데, 이 문장이 없으면 모델이 한 통화만 조회하고 나머지는 자기가 기억하는 환율로 지어내거나 반대로 줄마다 한 번씩 불러 호출을 낭비할 수 있다고 예상했습니다. 이 가설이 맞는지는 아래 실행 관찰에서 확인합니다. "such as USD, EUR or JPY"라는 예시와 파라미터 설명 "3-letter ISO currency code, e.g. USD"를 같이 넣은 것은 모델이 dollar나 US$ 같은 자유로운 표기를 보내는 것을 미리 막기 위해서이고, 날짜 쪽도 "YYYY-MM-DD; omit for the latest published rate"라고 형식을 못 박아 yesterday 같은 말이 들어오지 않게 했습니다. 마지막으로 잘못된 코드나 조회 실패를 예외로 던지지 않고 "error: ..."로 시작하는 문자열로 돌려주는 이유는, 예외가 나면 에이전트 루프가 그 자리에서 죽어 버리지만 문자열로 주면 모델이 그것을 관찰 결과로 읽고 인자를 고쳐 다시 부를 수 있기 때문입니다.

## 버린 도구: write_note

처음에는 세 번째 도구로 아무 파일에나 한 줄을 덧붙이는 `write_note`를 만들어 두었고, 그 구현과 실행 기록은 커밋 히스토리에 그대로 남아 있습니다. 그런데 이 도구는 계산기, 파일 읽기와 묶어 놓아도 세 도구가 함께 풀어야 할 하나의 일이 생기지 않아서, 에이전트가 무엇을 하는 물건인지 설명하기 어려웠습니다. 그래서 외화 목록을 읽어 원화 총액을 내는 쪽으로 과제를 바꾸고 `get_exchange_rate`로 교체했으며, 이렇게 하니 세 도구가 읽기, 환율 조회, 합산이라는 한 줄기 흐름으로 이어집니다.

## 실행 관찰

실행 로그는 logs/ 아래에 순서대로 있고, 아래 관찰은 그 로그를 그대로 읽은 것입니다.

- 모델 교체 (run-00a, run-00b): 처음 지정한 z-ai/glm-5.2:free는 2026-09-02에 모든 호출이 업스트림 429(공유 풀 초과)로 실패했습니다. 그래서 같은 OpenRouter 무료 모델 중 도구 호출을 지원하는 nvidia/nemotron-3-super-120b-a12b:free로 바꾸고, 이후 실행은 모두 이 모델입니다.
- 도구가 2개일 때 (run-01, 환율 도구 없음): 모델은 fees.txt를 읽은 뒤 환율이 필요하다고 판단하고 read_file("exchange_rates.txt")를 불렀습니다. 존재하지 않는 파일명을 지어낸 것입니다. 없는 능력을 "못 한다"고 말하는 대신 있는 도구를 그 용도에 끼워 맞추려 했습니다. 그리고 스타터의 read_file은 파일이 없을 때 예외를 던지기 때문에 루프가 그 자리에서 죽었습니다. 경로가 폴더 밖일 때는 문자열로 거부하는데 파일이 없을 때는 예외인 것이 비대칭이고, 이 부분은 이번 과제 범위 밖이라 고치지 않고 기록만 남깁니다.
- 도구가 3개일 때 (run-02, run-03): 도구 선택은 설명에 적은 대로였습니다. get_exchange_rate를 통화마다 한 번씩 정확히 네 번 불렀고, 목표에 "파일에 적힌 날짜"라고 하면 파일에서 2026-09-01을 읽어 date 인자로 넘겼으며, "오늘 환율"이라고 하면 date를 생략했습니다. 그다음 항목마다 calculator를 불렀습니다. 다만 모델은 한 턴에 도구를 하나씩만 요청했고(병렬 호출 없음), 그 결과 읽기 1회, 환율 4회, 곱셈 3회에서 스타터의 max_steps=8이 소진되어 합산과 답을 내지 못하고 "stopped: max steps exceeded"로 끝났습니다. 도구를 하나 추가하면 필요한 턴 수도 늘어나므로 안전장치 예산을 같이 손봐야 한다는 것을 배웠습니다.
- 수정 (커밋 e8dd275): max_steps 기본값을 8에서 16으로 올렸습니다. 통화 4개 태스크는 읽기 1, 환율 4, 곱셈 4, 합산 1, 답 1로 최소 11턴이 필요합니다.
- 수정 후 (run-05, 날짜 고정): 완주했습니다. 총액 3,976,531.5 KRW. 중간에 모델이 1200 AUD를 12000으로 잘못 넣어 곱한 뒤 스스로 1200으로 다시 부르고, 마지막에는 네 항목의 곱과 합을 한 식으로 다시 계산해 답을 냈습니다. 도구 결과를 보고 자기 오류를 고치는 반응성이 로그에 그대로 보입니다.
- 수정 후 (run-06, 최신 환율): 완주했습니다. 2026-09-02 고시환율로 총액 3,943,375 KRW. JPY 항목에서 512255.99999999994 같은 부동소수 꼬리가 나왔는데 계산기가 float 곱셈을 그대로 돌려주기 때문이고 결과에는 영향이 없습니다.
- 파일이 필요 없는 요청 (run-04): "850 USD는 2026-09-01에 얼마인가"에는 read_file을 건너뛰고 환율 조회와 곱셈 두 번으로 정확히 답했습니다. 파일 도구가 있어도 반사적으로 읽지는 않습니다.
- 가설 확인 범위: 설명의 "Call it once per currency."가 있는 상태에서는 통화별 1회 호출이 매번 관찰되었습니다. 이 문장을 뺀 비교 실행은 하지 않았으므로, 문장이 없을 때 어떻게 되는지는 이번 제출에서 말할 수 없습니다.
- 재현 방법: OPENAI_BASE_URL=https://openrouter.ai/api/v1, OPENAI_API_KEY=(OpenRouter 키), 모델은 코드 기본값인 nvidia/nemotron-3-super-120b-a12b:free를 그대로 두고 `uv run --with openai python first_agent.py`를 실행하면 run-05와 같은 태스크가 돌아갑니다. 날짜가 고정된 기본 태스크는 ECB 과거 환율이 바뀌지 않으므로 같은 총액 3,976,531.5 KRW가 나와야 하고, 무료 모델이라 도구 호출 순서나 중간 오타는 실행마다 다를 수 있습니다.
