# TOOLS.md — Why `write_note`?

I added `write_note(path, content)` as the third tool so the agent can close the loop end-to-end: it already had `read_file` to observe the world and `calculator` to compute, but without a way to act on the result, it could only report the answer in chat instead of persisting it. The description — "Write text content to a file in the working directory. Creates or overwrites the file." — deliberately states two things the model needs to make a correct tool call: *what* it does (write text content to a file) and *the side effect* (creates or overwrites), so the model knows the file need not exist beforehand and that calling it twice on the same path replaces rather than appends. I kept the parameter names `path` and `content` short and generic to match the existing `read_file` schema, and I reuse the same working-directory guard as `read_file` so the agent cannot write outside the sandbox — the description promises "in the working directory" because the implementation enforces it, not because I merely hoped the model would comply.
