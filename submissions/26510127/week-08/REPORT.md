### 1.3 툴 (내 코드)

| 파일 | 역할 | 핵심 규칙 |
|---|---|---|
| `seller.py` | A2A 가게 | 요청한 SKU만 판다(대체 판매 금지). 하한은 원가+10%, 3번째 메시지부터 하한 이상이면 수락. 정직한 등급 주장. A/B 물건에 72시간 보증. 오래된 재고는 24/48/96시간마다 단계 할인하되 원가 아래는 금지. 재구매 코드(1개 5%, 2개 이상 10%) |
| `market_buyer.py` | buyer | 신뢰 필터 → 모델 순위 → 최대 3곳 견적(1곳은 처음 가는 가게) → **정가 대비 할인율**로 비교 → 목표가(시장 중앙값×0.95)로 흥정 → 목표가에서 막혀도 정가 97% 이하면 구매 → accept 조건 |
| `restock.py` | 재고 훅 + 원장 분석기 | 원장 인기 SKU(마진 있는 것), 내 판매, 못 판 요청으로 구매. 현금 150만 원 유지, 재고 ≤ (잔고+재고)의 40%, SKU당 5개. 입고 창 밖이거나 급등 1.05배 이상이면 건너뜀 |
| `review.py` | 리뷰 훅 | 정산 기록만으로 별점 (등급 주장 불일치 1점, 가치 0이면 2점 등) |
| `forum.py` | 게시판 작성기 | `[구매 기록]`, `[시세]`(10분), `[재고]`(60분). 원장 번호를 `refs`로 첨부. 인젝션 글에만 무료 나빠요, 유료 표는 비용을 계산해서 거절 |

## 2. 아키텍처: 키트 기본과 무엇이 다른가

그림: `architecture.pdf` (원본 `architecture.tex`, 영어로 작성, `pdflatex architecture.tex`로 빌드). 그림 아래에 피드백 루프, 키트 기본과의 차이, 한계를 함께 적었다.

| | 키트 기본 (`starter --round3`) | 내 구조 |
|---|---|---|
| 재고 | 무작위 SKU를 조금씩 (`default_restock`) | 원장, 내 판매, 못 판 요청 → 재고 훅 |
| 가격 | 모델이 매 수를 정하고 원가만 막음 | 코드가 하한과 첫 제시가를 정하고, 성사율과 재고 나이로 조정. 모델은 그 사이 카운터만 |
| buyer | 없음 (LAB 1에서 직접 작성) | 견적 비교, 목표가, accept, 신뢰 필터 |
| 게시판 | 없음 | 사실 기반 글과 원장 근거, 인젝션 방어 |
| 메모리 | 없음 | 위 7개 파일 |

**피드백 루프 여섯 개** (그림의 빨간 번호)

1. 공개 원장의 정산 → 무엇을 살지
2. 못 판 요청 → 다음 입고 1순위
3. 견적 후 이탈률 → 카테고리 첫 제시가 인하
4. SKU별 시장 중앙값 → buyer 목표가
5. 결제 실패 30% 이상, 고장 → 견적 대상에서 제외
6. 원장 → `[시세]` 글, 정산 → `[구매 기록]` 글

9주차의 약한 에이전시로 정리하면 이렇다. **자율성**은 코드 가드, **반응성**은 seller와 buyer, **사회성**은 A2A와 게시판, **선제성**은 주문 전에 움직이는 restock과 `[시세]` 글이다.

### 3.4 Round 3이 막지 못한 것

- **담합과 동맹 투표**: 서명과 결제가 모두 정상인 거래와 좋아요는 검사를 통과한다. Patch 3.4가 "계정당 작성자 하나에 입장 하나"로 투표 폭탄은 막았지만, 패치 노트 스스로 "동맹 지원은 여전히 통한다(Funding allies still works)"고 적었다.
- **허위 지적과 프롬프트 인젝션**: 게시판에는 내용 규칙이 없다. 내 가게에 대한 지적(#3829)은 사실이었지만, 사실이 아닌 지적도 같은 형식으로 올라올 수 있다. 원장 번호(`refs`)를 근거로 다는 것이 유일한 신뢰 신호였다.
