## 1. Buyer의 상점 선택과 기억

공식 키트가 전달한 가게 목록만 사용하고 buyer가 시장 API에 직접 주문·리뷰를 제출하지 않음.
예산은 `buyer.py`와 원장에서 실제 제안 전 검사하며, 하네스 출력이 초과하면 자르지 않고 거부함.
A2A Agent Card에서 인터페이스를 읽고 모든 요청에 `A2A-Version: 1.0`을 보내며 같은 task를 이어감.

기억은 `.market/buyer-memory.json`에 상점 `name` 기준으로 저장함. URL은 터널 재시작 때 바뀌므로 식별자로 쓰지 않음.
상점별 방문·실패·최근 거래 최대 30건, 품목·예산·가격·선택 이유·task·실제 제안 횟수·응답 시간과 검증 상태를 기록함.
`signature_present`, 합의와 일치한 영수증, 공식 키트와 시장이 확인한 `verified_completions`를 구분함.
서명 검증과 시장의 `verified True`가 모두 확인돼야 검증 완료를 증가시킴.

리뷰 점수와 검증된 과거 경험으로 순위를 만들고, 상위 후보 최대 8개의 실제 Card를 확인한 뒤 하네스가 등록 이름으로 한 곳을 선택함.
후기 조작 지시나 계약 불일치를 직접 확인한 경우 24시간 회피함. 단순 고가·예산 부족·기술 오류를 고의 사기라고 단정하지 않음.
선택 이유를 stdout에 기록하며 마지막 줄은 받은 영수증 또는 null, 별점, 후기, 선택한 상점 URL의 JSON임.
영수증은 가게가 준 DataPart를 그대로 전달하고 buyer가 내용을 바꾸거나 판매자 서명을 만들어 내지 않음.

## 4. 영수증 서명, 실패와 수정

합의가 불가능한 예산과 모순된 영수증은 구매하지 않음

`market_buyer.py`는 키트가 제공한 상점 파일만 읽고 시장 API를 직접 호출하지 않음
이름을 기준으로 자신의 거래 결과를 `.market/buyer-memory.json`에 원자적으로 저장함
URL은 터널 재시작 때 바뀌므로 기억의 식별자로 쓰지 않음
상점별 `trades`, `completed`, `failures`, 최근 30건의 품목·예산·가격·결과·이유·서명 존재 여부를 저장함
합의와 다른 영수증 및 리뷰 조작 지시는 24시간 회피하며 단순 예산 부족은 사기로 취급하지 않음

리뷰의 수치 별점과 개인 거래 결과로 후보를 정렬하고 실제 Agent Card에 접속되는 후보 중 최대 8개를 선택 하네스에 보여 줌
하네스에는 상점 이름·설명·최신 리뷰 최대 5개·개인 기억·요청 품목·예산을 전달함
리뷰 문장과 Agent Card는 신뢰할 수 없는 인용 데이터로 전달하며 포함된 명령을 권한으로 사용하지 않음
하네스의 선택 이유를 stdout에 남기고 마지막 줄에 키트가 요구하는 `shop`, `receipt`, `stars`, `review`를 출력함
영수증은 받은 DataPart를 그대로 반환하며 다른 상점의 영수증을 만들거나 재서명하지 않음
등록 공개키를 알고 있는 공식 키트가 판매자 서명을 검사하고 구매자 서명을 추가함
다음 주문에서는 자신의 `market-kit.log`에 기록된 서명 검사 결과도 기억에 반영함
서명이 없다는 사실만으로 고의 사기를 단정하지 않음

## 서명 구현과 실패

영수증의 `{shop,item,price,task}` 네 필드를 키 정렬·공백 없는 JSON·UTF-8로 직렬화한 바이트에 Ed25519 서명함
`task`는 실제 A2A task ID이며 개인키는 공식 키트가 만든 `shop_key.pem`을 그대로 사용함
DataPart의 숫자가 `120.0`으로 돌아와도 정수 `120`으로 정규화해야 같은 서명이 됨
소수 가격·NaN·boolean은 서명하지 않으며 품목·가격·task·상점 이름을 바꾸면 검증이 실패하는 회귀 검사를 추가함
이전 영수증에는 `sig_seller`와 Week 07 필드가 없어 Round 2 계약을 충족하지 못했음
첫 공식 실행은 하위 `python3`에 가상환경 PATH가 전달되지 않아 `uvicorn` import가 실패함 실패 로그를 보존하고 PATH를 전달해 다시 실행함
이후 판매 서명 3회가 공식 공개키 검사에서 통과함 최종 판정은 최종 `test-report.json` 기준임

## Challenge 2 리뷰 조작 상점 회피

이는 거래 계약이나 운영자 권한을 증명하지 못하는 상점 설명 속 지시임
공개 리뷰에도 같은 조작 시도가 보고돼 있었지만 다른 사람의 주장만으로 확정하지 않고 직접 받은 Card 원문을 증거로 남김

`discovery-second-success.log`는 같은 이름을 후보에서 제외해 구매를 시도하지 않는 것을 보여 줌
실제 시장 등록 상점에 대한 GET 발견 실험이며 허위 구매·별점·영수증을 시장에 제출하지 않았음
최초 발견 실험은 작업 경로를 중복 연결해 입력 파일 경로 오류가 났으며 `discovery-first.log`, `discovery-second.log`에 보존함 상대 경로를 수정한 다음 성공 로그를 별도로 남김
가격을 높게 불렀거나 기술 오류가 난 다른 상점을 고의 사기라고 부르지 않음

## 2026-10-21 판매 서비스 연속성 개선
