6주차 과제의 선택 항목에는 다른 하네스로 만든 친구의 가게와 거래해 보기가 있었다. 제출물 가운데 Cloudflare Workers에 배포된 가게가 둘 있었다. 한 수강생의 buyer(Claude Code, haiku)가 다른 수강생의 배포 가게(Workers AI, 제작자 설명으로는 Llama 3.3 70B, 하한가는 코드에서 강제)와 시나리오마다 세 번씩 거래했다. 두 수강생은 코드를 따로 만들었다.

가게는 card URL을 registry에 등록한다(0). 6주차에 본 FIPA의 Directory Facilitator가 하던 일이다. 시장은 buyer에게 주문을 낸다(1). 주문에는 품목, 예산, 만료 시각, 한 번만 쓰는 번호(nonce)가 들어 있다. 예산이 6주차 하한가보다 낮아서 어느 가게와도 거래가 안 되는 주문도 섞여 있다. A2A에는 얼마까지 써도 되는지 같은 위임 조건을 적을 칸이 없다. 이 시장에서는 그 조건이 주문이라는 데이터로 buyer에게 간다. buyer는 가게 목록을 받아(2) 한 곳을 골라 A2A로 흥정하고(3), 거래가 되면 영수증을 ledger에 내고(4), 후기를 남긴다(5).

    
시장은 거래를 막지 않는다. dashboard에는 ledger와 review board에 쌓인 것이 그대로 나온다.

    
시장에는 강사가 띄운 가게와 buyer도 섞여 있다. 참가자가 적을 때도 거래가 이어지도록 띄웠고, 그중 몇은 정직하지 않다. 어느 것인지는 알려 주지 않는다.

시장에 들어가기
    
내 가게와 buyer는 수업 키트 market_kit.py를 거쳐 시장과 통신한다. 그래서 가게와 buyer는 시장 주소도 시장의 요청 형식도 몰라도 된다. 6주차 trade test처럼 agent.json의 명령으로 가게와 buyer를 실행한다.

    
STEP 1준비
    
키트는 수업 레포의 scripts/에 있다. GitHub에서 내 포크의 Sync fork를 누른 뒤 git pull로 받는다. Python은 3.10 이상이어야 한다. macOS에 기본으로 들어 있는 python3는 3.9라서 pip install이 아래 오류로 끝난다. 그때는 brew install python@3.12로 설치하고 python3.12 -m venv .venv로 venv를 만든다.

source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install "a2a-sdk[http-server]" uvicorn httpx cryptography

python scripts/market_kit.py join --dir submissions/<학번>/week-07 \
    --market <시장 주소> --name <닉네임> --tunnel

시장 주소는 수업에서 알린다. --tunnel은 cloudflared로 내 가게에 공개 주소를 붙인다. 터널 주소는 출력된 직후에는 열리지 않는다. 그 주소로 카드가 열려야 가게가 등록되므로, 아래 연습 시장 로그에서는 [tunnel] 줄부터 [market] 등록 줄까지 75초가 걸렸다. 이미 배포한 가게는 --tunnel 대신 --deployed <URL>을 쓴다.
    
cloudflared의 이 터널은 Cloudflare 가입이나 로그인 없이 열린다. cloudflared를 쓸 수 없으면 아래 표대로 한다.

    
      
        
상황방법
        
설치가 안 된다ssh 터널을 쓴다. 아래 명령의 localhost.run은 가입 없이 ssh로 여는 무료 터널이고, 주소는 lhr.life로 끝난다. ssh는 macOS와 Windows 11에 기본으로 들어 있다. 아래처럼 터미널 두 개를 쓴다
        
터널이 열리지 않는다--tunnel 대신 --buyer-only로 buyer만 들어온다. 내 가게는 시장에 없지만 buyer는 다른 가게와 거래하고 후기를 남긴다. 과제의 가게는 배포한 뒤 --deployed로 등록한다
      
    
    터미널 2: ssh 터널

# 출력 가운데: ... tunneled with tls termination, https://72fcd1656a687c.lhr.life

    L1
시장이 돌아가는 조건
    
1970년 Akerlof는 중고차 시장을 예로 들었다. 사는 사람은 차가 좋은지 나쁜지(lemon) 구별할 수 없어서 평균 품질만큼만 값을 치른다. 그 값에서 손해를 보는 좋은 차의 주인은 시장을 떠난다. 남은 차의 평균 품질이 떨어지고, 값이 다시 내려간다. 품질에 대한 정보가 파는 쪽에만 있으면 나쁜 상품이 좋은 상품을 밀어낸다.

    
1945년 Hayek는 경제에 필요한 지식이 한 사람에게 모이지 않고 수많은 사람에게 흩어져 있다고 봤다. 가격은 그 지식을 숫자 하나로 줄여 전한다. 그의 예에서 주석(tin)을 쓰는 사람은 주석이 왜 귀해졌는지 몰라도 값이 오른 것만 보고 덜 쓰고, 그 반응이 시장 전체로 퍼진다. 이 시장에서 그 숫자는 dashboard의 품목별 거래가다.

    
Resnick 등(2000)은 eBay 같은 온라인 시장의 평판 시스템을 다뤘다. 평판이 작동하려면 거래 상대가 오래 남아 있어서 다음 거래를 기대할 수 있어야 하고, 지난 거래의 평가가 모여 공개되어야 하고, 사람들이 그 평가를 보고 상대를 골라야 한다.

수단만들 때확인할 때알 수 있는 것
        
해시 (SHA-256)내용만내용만내용이 바뀌지 않았다. 누가 만들었는지는 모른다
        
HMAC공유 비밀키같은 비밀키키를 가진 쪽이 만들었다. 키를 가진 쪽이 여럿이면 그중 누구인지는 모른다
        
전자서명 (Ed25519)개인키공개키그 개인키를 가진 쪽이 만들었다. 공개키만 있으면 누구나 확인한다
      
    

    
참가자가 수십이고 외부 참가자도 들어오는 시장에서는 비밀키를 나눠 줄 수 없다. 가게와 buyer가 각자 개인키를 갖고 공개키만 시장에 등록한다. Python에서는 cryptography 패키지의 Ed25519를 쓴다.

    sign_receipt.py
import json, hmac, hashlib, base64
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
from cryptography.exceptions import InvalidSignature

def canon(d):
    return json.dumps(d, sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode()

receipt = {"shop": "Lamp Shop", "item": "lamp", "price": 120, "task": "128a5f1a"}

print("sha256 ", hashlib.sha256(canon(receipt)).hexdigest()[:16])
print("hmac   ", hmac.new(b"class-shared-secret", canon(receipt), hashlib.sha256).hexdigest()[:16])

seller = Ed25519PrivateKey.generate()
sig = seller.sign(canon(receipt))
print("ed25519", base64.b64encode(sig).decode()[:16], len(sig), "bytes")
pub = seller.public_key()
pub.verify(sig, canon(receipt)); print("verify ok")
try:
    pub.verify(sig, canon(dict(receipt, price=200)))
except InvalidSignature:
    print("verify forged -> InvalidSignature")
    출력 (서명 값은 키마다 다르다)
sha256  295e9ea3360ba865
hmac    4ae1325a8b46390d
ed25519 qCya7WXA4a0un6hv 64 bytes
verify ok
verify forged -> InvalidSignature

    
서명하는 바이트는 양쪽에서 같아야 한다. JSON은 키 순서나 공백이 달라도 내용이 같을 수 있어서, 키를 정렬하고 공백을 없앤 형태(canon)로 바꾼 뒤 서명한다. 가격을 200으로 고친 영수증을 같은 서명으로 확인하면 InvalidSignature가 난다.

STEP 1서명 함수 붙여 넣기
    
아래 import 두 줄과 함수 둘을 seller.py의 import 줄들 아래에 붙여 넣는다. 서명에 쓰는 shop_key.pem은 SETUP STEP 4의 join에서 키트가 이미 만들었다. 이 파일은 커밋하지 않는다.
    seller.py에 붙여 넣을 부분
import json, base64
from cryptography.hazmat.primitives import serialization

def canon(d):
    return json.dumps(d, sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode()

def sign_receipt(receipt, key_path="shop_key.pem"):
    key = serialization.load_pem_private_key(open(key_path, "rb").read(), password=None)
    body = {k: receipt[k] for k in ("shop", "item", "price", "task")}
    receipt["sig_seller"] = base64.b64encode(key.sign(canon(body))).decode()
    return receipt

    
STEP 2영수증 만드는 줄 바꾸기
    
영수증 data Part를 {shop, item, price, task}로 만들고 sign_receipt를 한 번 부른다. 6주차의 seller 키는 shop으로 바꾸고, task에는 그 거래의 A2A task id를 넣는다. starter 가게에서는 거래가 성사될 때 영수증을 내는 두 줄을 세 줄로 바꾼다.
    seller.py, 바꾸기 전 (starter)
await up.add_artifact(parts=[new_data_part({"seller": "Harness Shop", "item": deal["item"], "price": price})],
                      name="receipt")
    seller.py, 바꾼 뒤 (들여쓰기는 원래 줄에 맞춘다)
receipt = sign_receipt({"shop": "Harness Shop", "item": deal["item"],
                        "price": int(price), "task": task.id})
await up.add_artifact(parts=[new_data_part(receipt)], name="receipt")
    
가격은 정수로 서명한다. A2A data Part는 숫자를 실수로 실어 보내서 120은 buyer에게 120.0으로 도착하고, canon 바이트가 달라진다. 키트와 시장은 받은 값을 정수로 되돌린 뒤 확인한다. 다른 언어로 만든 가게도 같은 규칙(키 정렬, 공백 없음, UTF-8)으로 같은 바이트를 만들어 서명한다.

가게registry에 등록한 card URL에서 응답한다. 하한가 아래로 부르지도 팔지도 않는다. 영수증에 sig_seller를 붙인다
        
buyer주문 예산을 넘지 않는다. 거래마다 결과 줄(영수증, 별점, 후기)을 출력하고, 가게를 고른 이유를 로그에 남긴다
        
시장마감 시각에 가게와 buyer가 내 GitHub 이름으로 시장에 떠 있고, buyer에게 Round 2로 인정된 거래가 하나 이상 있다
      
    

    
DEPLOY가게와 buyer 배포
    
노트북을 닫아도 에이전트가 시장에 남아 있어야 한다. buyer는 키트를 거쳐 주문을 받으므로, 키트를 꺼지지 않는 컴퓨터(VPS, 집에 켜 둔 PC 등)에서 띄운다.
    
      GitHubhttps://market.ourolabs.ai/join에서 로그인하고 claim code를 받는다. 이 코드로 join 한 가게와 buyer에 내 GitHub 이름이 붙는다
      가게6주차처럼 Workers나 VPS에 배포한다. --deployed로 등록할 때도 시장에는 shop_key.pem의 공개키가 등록되므로, 배포한 가게도 이 키로 서명한다. 개인키는 배포 서버의 비밀 값으로 넣고 커밋하지 않는다
      buyer꺼지지 않는 컴퓨터에서 아래 명령으로 키트를 띄운다. 가게도 그 컴퓨터에서 돌리면 --deployed 대신 --tunnel을 쓴다
    
    꺼지지 않는 컴퓨터에서
MARKET_OWNER=<claim code> python scripts/market_kit.py join --dir submissions/<학번>/week-07 \
    --market https://market.ourolabs.ai --name <닉네임> --deployed <가게 URL>
    
이 컴퓨터의 logs/market-kit.log를 제출물에 넣는다.
    market test
python scripts/market_test_week07.py submissions/<학번>/week-07
python scripts/check_week07.py submissions/<학번>/week-07
    
      
        
테스트통과 조건
        
6주차 가게 테스트 ×96주차와 같다. 하한가 아래로 부르거나 팔면 실패
        
seller_signed_receipt ×3영수증이 {shop, item, price, task}이고, task가 A2A task id이고, 가격이 정수이고, sig_seller가 shop_key.pem으로 확인된다
        
buyer_deal ×3테스트 가게 하나(lamp, 예산 120)와 거래하고, 마지막 줄에 그 가게와 받은 영수증, 별점, 후기가 있다
        
buyer_holds_budget ×3bookshelf, 예산 230(하한가 260). 거래 없이 예산 안의 값만 보내고 "receipt": null로 끝난다
        
buyer_protocol ×6모든 요청에 A2A-Version: 1.0, buyer_deal에서는 taskId로 거래를 이어 간다
        
buyer_reads_reviews똑같이 행동하는 가게 둘 가운데 첫째에만 나쁜 후기가 있다. 세 번 중 두 번 이상 나쁜 후기 가게에는 요청을 보내지 않고 다른 가게로 간다
      
    
    
모든 실행이 통과해야 한다. 참조 구현(Claude Code, haiku)은 25개를 모두 통과했고, 서명하지 않는 6주차 참조 가게는 seller_signed_receipt 세 번에서 실패했다. agent.json의 명령을 바꾸면 market test를 다시 돌린다.
    
check_week07.py가 market test 결과와 함께 확인하는 것.
    
      로그logs/market-kit.log에 시장에서 거래한 ledger 줄이 있다
      시장그 로그에 적힌 닉네임의 가게와 buyer가 시장에 내 GitHub 이름으로 등록돼 있다
      보고서REPORT.md가 600자 이상이다
      키커밋에 *.pem이 없다
    

    
      
가게: 값 바꾸기 (필수). 내 가게의 거래 기록과 후기를 읽고 호가를 스스로 바꾼다. 하한가는 그대로 지킨다. 바꾸기 전과 후의 점유율과 평균 거래가를 dashboard나 로그로 보인다.
      
buyer: 정직하지 않은 참가자 (필수). 시장에서 만난 정직하지 않은 가게나 buyer를 로그로 짚고, 내 buyer가 그 상대를 어떻게 피하게 됐는지 보인다.
