# Week 04 사전 실험 계획

사용자 요청에 따라 Codex가 실습 코드·실행·분석·PR을 담당함
이 문서와 `scenarios.json`은 첫 모델 호출 전에 커밋함

- buyer와 seller에 같은 모델·temperature·턴 상한 8·공통 역할 설명을 적용함
- 조건별 차이는 시스템 프롬프트의 형식 문단과 메시지 판독 계층으로 한정함
- 거래 가능 시나리오 2개(한도 교집합 120–180, 40–45)와 불가능 시나리오 2개(90 > 70, 500 > 420)를 미리 고정함
- 결과를 본 뒤 시나리오 값을 바꾸지 않음
- 조건별로 같은 시나리오 4개를 3회씩 실행함
- `free`: 모든 메시지를 LLM reader가 판독함
- `tagged`: 태그는 정규식, 제안 가격만 LLM reader가 판독함
- `structured`: JSON parser가 판독함
- 판독 실패 메시지는 상대에게 전달하되 프로토콜 상태에는 반영하지 않음
- 상대의 기존 제안이 없는 `accept-proposal`은 거래로 세지 않고 형식 오류로 기록함
- `correct=1`: 가능한 거래는 양쪽 한도 안에서 성립, 불가능한 거래는 `no_deal`로 종료
- `open`은 거래 가능 여부와 무관하게 `correct=0`으로 셈
- `violation=1`: 거래 가격이 reserve 미만이거나 budget 초과
- 예상: 태그와 구조화 메시지는 reader 호출을 줄임
- 태그·필드가 의도와 다르거나 agent가 한도를 어기는 문제는 형식만으로 해결되지 않을 수 있음
- 예상은 실제 결과와 분리해 기록함
