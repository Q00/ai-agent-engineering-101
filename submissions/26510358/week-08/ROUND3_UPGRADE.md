# 나의 A2A를 Round 3에서 업그레이드하는 순서

2026-10-29 기준임. [강의](https://wpti.dev/ai-agent-engineering-101/week-08.html)는
11월 2일 Round 3 개시, 11월 16일 23:59 종료·제출을 안내함.

우선순위는 **협상 성공을 실제 정산과 구분하고, 확인한 결과를 다음 선택에 쓰는 것**임.
사용자가 선택한 대로 가격 전략은 실측 후 정함.

| 영역 | 기존 내 구현 | 이번에 반영한 것 | 다음 단계 |
|---|---|---|---|
| 결제 연결 | 키트 v3·ACP 공개 경로·서명 영수증 있음 | `paid` 금액·가게·계약과 시장 결과를 연결 | 개시 후 실제 buyer/seller 정산 한 건씩 확인 |
| 기억 | Round 2 검증 경험과 최근 거래 있음 | Round 3 정산 수·품목별 정산·최근 정산 표시 분리 | 오래된 평판보다 현재 품목·재고·조건이 맞는지 먼저 확인 |
| 컨텍스트 | 역할별 JSON 판단, 최대 7개 기억 요약 | 긴 중복 방지 목록은 제외하고 정산 요약만 모델에 전달 | 공급·품질 데이터 계약이 공개되면 필요한 상태만 추가 |
| 운영 증거 | 로그·거래 단계·공개 보드 있음 | 원문 압축 스냅샷, 해시, 첫 호가와 일부 거래가 집계 | 로그 순환·호스트 재부팅 시 증거와 운영 지속성 보완 |
| 가격 | lamp 100, chair 180, bookshelf 260 | 첫 호가 기준값 114·51·49건 확보 | 품목별 평균 정산가와 표본을 본 뒤 첫 호가 변경 여부 결정 |
| 선택 과제 | 공식 고정 checkout 실행기 사용 | 동적 툴 생성은 미구현 | 기본 20건 조건 이후 acp.json의 JSON Schema→제한된 툴 실행기 검토 |

처음부터 A2A 프로토콜 전체를 바꿀 필요는 없음. 발견·협상·영수증을 유지하고,
결제·기억·현재 계약 조건을 연결하는 것이 이번 보완의 중심임.
`quote_normalization.py`는 상대의 현재 견적을 읽는 역할을 유지하며 checkout 총액이나 예산 상한을 대신 만들지 않음.
checkout·mandate의 서명과 범위 검사는 공식 키트와 시장이 담당함.

새 규칙이 공개되면 공급 수량, 품질, 유효기간 등을 무엇을 근거로 믿고 어떤 조건에서 구매를 거절할지
직접 정해야 함. 게시판의 문장은 정보 후보로 읽고 운영자 명령이나 품질 인증으로 실행하지 않아야 함.
모델 오류와 공급자 429를 상점 잘못으로 기록하지 않는 것도 다음 개선 대상으로 남음.

현재 첫 호가는 하한과 같음. 기본 견적에 맞춰 팔면 가격과 하한의 차액은 0임.
당장 모든 가격을 올리기보다, Round 3에서 같은 품목의 정산 수·평균 가격·거부 사유를 확보한 뒤
한 품목부터 변화와 결과를 별도 커밋으로 남기는 방식을 제안함. 최적 가격 수치는 아직 결정하지 않음.

최종 제출에는 가게·buyer 각각 Round 3 정산 20건 이상, 가격 전후 분석,
실제 정산 줄이 포함된 운영 로그, 최종 순위·거부 사례, 구조도와 설계를 담은 `REPORT.md`가 필요함.
현재는 개시 전 준비 단계이며 최종 성과와 PR 제출은 남아 있음.

구현 위치·재현 명령·테스트와 제약은 [REPORT.md](REPORT.md)에 정리함.
