# 첫 A/B 실험의 실행 전 조건

이 문서는 모델 실행 결과를 보기 전에 작성했다. 결과와 해석은 실험 후 별도로 기록한다.

- 제공자: OpenAI, 엔드포인트 `https://api.openai.com/v1`
- 모델: 사용자가 로컬 `.env`에 지정한 `gpt-5.6-luna`. 두 하네스가 동일하게 사용한다.
- 환경: Python 3.13.15, `requirements.txt`의 고정 의존성.
- 입력: starter의 `app.log` 원본. SHA-256: `e4020de6ccc11f6ac6d28eae021032cb9fed43adeba1d7ed9f96a6a2e1cc03b7`.
- 성공 기준: 이미 커밋한 `TASK.md`를 유지한다. 최종 답에 `14:00`이 포함되면 O, 아니면 X이다.
- 실행 순서: `python run_ab.py --runs 1`을 3번 실행해 ReAct → Plan-then-Execute를 세 쌍 기록한다.
  각 쌍의 결과를 커밋한다. 실패 행과 로그도 유지한다.
- 도구: 두 하네스 모두 `read_file(path)`, `count_pattern(path, pattern)`를 사용한다.
  원본 도구의 기능을 유지하고, 로컬 키 파일 및 작업 폴더 밖 접근 차단을 공통 적용했다.
- 프롬프트: 두 하네스의 starter 시스템 프롬프트를 유지한다.
- 모델 생성 옵션: starter처럼 OpenAI 호출에 temperature, seed, 출력 토큰 상한을 별도로 지정하지 않는다.

## 실행 전에 읽을 코드

ReAct는 한 대화에서 결과를 보고 다음 행동을 결정한다. 도구 호출이 없는 응답에서 종료하며
`max_steps=8`로 제한한다. Plan-then-Execute는 별도의 planner가 만든 단계 목록을 executor가
실행한다. `max_replan=1`, `max_tool_rounds=3`을 사용한다. 두 값은 ReAct의 전체 호출 상한과
다른 종류의 제한이며, Plan-then-Execute에는 전체 모델 호출 수를 8회로 맞추는 제한이 없다.

## 기록과 해석의 범위

- `tokens`: API가 보고한 입력·출력 토큰의 합.
- `iters`: `Meter.add()`까지 완료된 모델 호출 횟수. 계획 생성과 재계획 호출도 포함한다.
- `interventions`: 사람 승인·거부 개입 수. 현재 읽기 전용 도구에는 승인 단계가 없어 0이 예상된다.
- 실행 중 예외로 함수가 반환되지 못하면 starter runner는 그 실행의 토큰·반복 수를 빈칸으로 기록한다.
  빈칸은 0으로 바꾸지 않고 미측정으로 취급한다.
- 각 로그 첫 줄에 실제 제공자, 모델, 하네스와 실행 번호를 기록한다.
  starter에는 도구 출력 200자 및 일부 단계 출력 300자의 로그 표시 제한이 있다.
  따라서 로그에 없는 세부 내용을 관측했다고 주장하지 않는다.
- 실패율·토큰·반복 수를 함께 비교한다. 실패한 짧은 실행을 효율 향상으로 해석하지 않는다.
  각 3회는 탐색적 실험이며 모델 전반의 우열이나 통계적 유의성을 주장하지 않는다.
- 실행 전 `models.retrieve`로 인증과 모델 조회만 확인했다. 그 요청은 태스크 실행이 아니므로
  `results.csv`에 포함하지 않는다.
