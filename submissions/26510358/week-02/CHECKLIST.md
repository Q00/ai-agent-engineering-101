# Week 02 실습 체크리스트

필수 목표는 **같은 모델·문제·도구로 ReAct와 Plan-then-Execute를 각각 3회 이상 실행하고,
하네스 설계 차이가 측정값에 어떤 영향을 주었는지 로그를 근거로 설명하는 것**이다.
starter에 이미 두 하네스가 구현되어 있으므로 추가 코드 변경은 필수가 아니다.
하네스 개선은 기본 비교를 마친 뒤 선택할 수 있는 후속 실험이다.

근거: [공식 과제 명세](../../../weeks/week-02/README.md),
[강의 LAB](https://wpti.dev/ai-agent-engineering-101/week-02.html).

현재 단계: **6회 실행·측정·로그 확인 및 Draft PR 생성 완료. 학습자 해석 작성 후 최종 제출 상태로 전환한다.**
각 단계의 산출물을 확인하며 순서대로 진행한다. 학습자의 설명·예상·결과 해석은
학습자가 작성하고, 코딩 에이전트는 코드 탐색·환경 구성·측정 정리를 돕는다.

## 2. 코드 차이를 이해하고 예상 작성

- [ ] `harness_react.py`의 `run_react()`에서 모델 호출, 도구 실행, 종료 분기를 직접 찾는다.
- [ ] `harness_plan_execute.py`의 `run_plan_execute()`에서 계획 생성, 단계 실행, 재계획 분기를 직접 찾는다.
- [ ] 컨텍스트 관리·도구 단위·종료 조건·오류 복구·사람 개입 지점 중 같은 부분과 다른 부분을 자신의 말로 적는다.
- [x] 어느 하네스가 모델을 더 많이 호출할 것 같은지 실행 전에 선택한다: Plan-then-Execute.
- [x] 그렇게 예상한 이유를 코드에서 찾고 한 문장으로 적는다.

학습자 기록:

> 두 구조에서 내가 확인한 차이: 작성 예정
>
> 모델 호출 횟수에 대한 내 예상: "Plan-then-Execute 일것 같아"
>
> 그렇게 예상한 이유: "Plan-then-Execute는 계획하고 반복하기 때문에 모델 호출이 더 많을 것으로 예상한다."

예상은 실제 결과와 달라도 된다. 실행 후에는 이 예상을 지우거나 결과에 맞춰 바꾸지 않는다.
`Meter.iters`는 모델 호출 횟수이며, 계획 단계 수나 도구 함수 호출 수와 구분한다.

## 3. 실행 환경과 비교 조건 확정

- [x] Python 환경과 필요한 SDK를 준비하고 사용 버전을 기록한다.
- [x] 양쪽에서 사용할 제공자·정확한 모델명·모델 호출 옵션을 확정한다.
- [x] API 키는 로컬 환경변수로 준비한다. `.env` 로딩과 Git 제외를 확인한다.
- [x] API 연결 수정을 `tools_shared.py`에 공통 적용하고 변경 이유를 기록한다.
- [x] 시스템 프롬프트와 기본 제한을 기록한다: ReAct `max_steps=8`, Plan-then-Execute `max_replan=1`, `max_tool_rounds=3`.
- [x] 두 파일에서 같은 모델 설정·도구 정의를 사용하는지 확인한다.
- [x] 확정한 코드와 설정 설명을 실행 전에 커밋한다.

설정과 로컬 검사 범위는 [RUN_SETTINGS.md](RUN_SETTINGS.md)에 기록했다.
이 조건으로 실제 API 실험 6회를 완료했다. 결과와 검증 범위는 해당 문서의 완료 기록에 있다.

하네스마다 다른 계획·실행 프롬프트는 비교할 설계의 일부다. 각 프롬프트를 기록하고,
동일한 비교 묶음 안에서는 모델·입력·도구·각 하네스의 설정을 유지한다.
기본 도구에는 사람 승인이 없으므로 개입 횟수 0도 유효한 관측값이다.
