# write_note 설명을 이렇게 쓴 이유

세 번째 도구로 작업 폴더 안에만 파일을 쓰는 write_note를 추가했고, 설명은 "Write text content to a file in the working directory." 한 문장으로 뒀다. 처음에는 설명을 공들여 다듬어야 모델이 도구를 쓸 줄 알았는데 실험해 보니 반대였다. goal에 저장하라는 말이 없던 첫 실행(run-0902-1635)에서는 도구를 추가해 놔도 모델이 아예 건드리지 않았고, goal에 "결과를 result.txt에 저장하라"를 넣은 두 번째 실행(run-0902-1641)에서는 같은 설명 그대로인데도 read_file → calculator → write_note를 알아서 이어 불렀다. 도구를 쓸지 말지는 태스크가 거의 전부 결정하고, 설명이 하는 일은 그 순간 어떤 도구가 후보인지 알려주는 정도였다. 그런데도 "작업 폴더 안에서만"이라는 제약을 설명에 남긴 건 모델이 이 규칙을 모르면 엉뚱한 경로에 쓰려다 거부당하고 다시 시도하는 왕복이 생길 수 있어서고, 읽기 도구인 read_file과 같은 경로 규칙을 쓴다는 걸 맞춰두고 싶어서다. 성공 시 "wrote 5 chars to result.txt"처럼 뭘 어디에 썼는지 반환하게 고친 이유도 이어져 있다. 처음 버전은 성공해도 아무것도 반환하지 않아 모델에게 "None"이 전달됐는데, 반환 메시지를 넣자 모델이 최종 답변에서 result.txt에 저장했다고 정확히 보고했다. 도구의 반환값은 모델이 다음 행동과 최종 보고를 정하는 근거라서, 성공 메시지도 설명 못지않게 인터페이스의 일부라는 걸 이번 실험에서 확인했다.
