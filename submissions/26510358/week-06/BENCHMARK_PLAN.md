# 순차 개선과 A2A 가격 비교 계획

2026-10-15 사용자 요청: 관측 정규화 → 역할별 협상 목표 → 제한적 재계획 → 학습 환경 → 비교 평가 순서로 개선한다. 각 단계에 측정을 붙이고, 충분한 성능에 도달하면 다음 제품 개발을 생략한다. 비교 실행기는 개발 순서와 관계없이 먼저 준비한다.

## 변경과 기준 보존

- 개선 전 소스: `cf0ed87f22e08d5712aa4a7c00e645fffa63bf62`의 독립 실행 복사본.
- 상대: PR296/295/292/291/290/289/288의 고정 HEAD. 원본 소스의 SHA-256을 실행 전후 비교한다.
- 기존 사용자 demo/runtime 로그와 이전 공식·교차 거래 기록은 수정하지 않는다.
- 각 개선 단위와 실패를 별도 커밋하고 새 실행 폴더에 원본 관측·프롬프트·모델 출력·영수증을 보존한다.
- 구매/판매 가격 및 수락/거절은 실제 하네스가 결정한다. 실행기는 가격을 보정하거나 실패를 성공으로 대체하지 않는다.

## 두 가지 비교

1. 공통 상대: 각 buyer는 같은 공식 kit seller와, 각 seller는 같은 공식 kit buyer와 거래한다. 역할별 비교의 기준이다.
2. 양방향 교차 거래: 우리 buyer ↔ 상대 seller 및 상대 buyer ↔ 우리 seller. 호환성과 해당 상대에서의 가격을 확인한다. 한 거래의 가격만으로 양측의 독립적인 우월성을 판단하지 않는다.

기본 공통 시장은 lamp, 판매 최저 수락가 100, 구매 예산 120이다. 이미 100에 사는 상대보다 더 낮거나 120에 파는 상대보다 더 높은 유효 가격은 불가능하다. 따라서 최적 가격 동률을 인정하고 성사율·안전성·호출 비용을 함께 기록한다. 추가 품목은 chair(180/216), bookshelf(260/312)로 분리한다.

## 원본과 동일 모델 실험의 구분

- 원본 실행은 원래의 provider/model 설정을 유지한다. PR289의 기본 모델은 현재 사용자 설정을 상속하므로 과거 제출 시점의 완전 재현이라고 부르지 않는다.
- 현재 Claude 인증, Groq 키, 지정 Ollama 모델이 없어 일부 원본은 실행 불가다. 원본 미실행은 승패로 채우지 않는다.
- 동일 모델 통제 실험은 원본 프롬프트·상태·검증·fallback을 보존하고 추론 전송만 실제 Codex `gpt-6-sol`/`low`로 바꾼다. CLI/HTTP 요청과 변경한 실행 플래그를 모두 기록한다. 이것은 원래 Haiku/Groq/Qwen의 성능 비교가 아니다.
- PR288 공개 Workers/Llama 판매자는 로컬 Haiku와 별도 항목이다.
- 단계 3 이후 제품의 기본 추론 간격은 5초다. 앞선 비교와 같은 조건을 유지하도록 공통 상대·교차 비교에서는 `A2A_INFERENCE_GAP_SECONDS=10`을 명시한다. 장보기 회귀는 제품 기본 5초를 사용한다. 새 실행 manifest에는 간격 override를 남긴다. 공용 HTTP 전송도 같은 10초로 실행했고 교차 비교와 후보 점검이 끝난 뒤 종료했다.

## 단계별 판정과 조기 종료

- 먼저 독립 실행 1회로 각 경로를 점검한다. 공식 기록이나 과거 1회 거래를 새 측정으로 재사용하지 않는다.
- 유망한 후보는 새 task로 3회 이상 반복한다. 확인 실행과 최초 점검을 구분한다.
- 공통 시장에서 구매 100, 판매 120을 반복해 달성하고 성사율/한도/상품/영수증 검증이 유지되면 이 시장의 가격 개선 목표에 도달한 것으로 본다. 이후 재계획·RL 개발은 보류할 수 있다.
- 교차 거래는 별도 보고한다. 공통 시장의 최적 가격을 모든 LLM 상대에서 보장한다고 해석하지 않는다.
- 안전성 회귀가 관측되면 우월 판정을 중단한다. provider 오류, 프로토콜 오류, 미체결, timeout, disputed를 구분한다.
- 반복 수가 적은 결과는 탐색적 관측이다. 7개 원본 전체에 대한 통계적 우월성이나 일반적인 승률을 주장하지 않는다.

## 측정값

단계 4 후보는 환경 v2·seed 42·5,000회 합성 업데이트로 한 번 생성하고 기존 활성 정책은 유지한다. 같은 새 전략 문구에서 기존 활성 정책과 후보를 먼저 역할별 1회 점검한다. 유망한 후보만 새 task로 역할별 3회 확인한다. 승격은 가격 확인에서 구매 평균 101.67 이하·판매 평균 120 이상, 모든 거래 유효·안전성 위반 없음과 기존 실제 holdout·공격 검사·공식 21개 승격 조건을 모두 만족해야 한다. 101.67/120은 앞서 측정한 단계 3b 구매·3c 판매의 관측 기준이며 통계적 유의성이나 RL 단독 효과의 기준은 아니다. 후보가 이를 충족하지 않으면 학습 환경 수정과 후보는 보존하되 활성 정책을 교체하지 않는다. 최종 활성 구성도 별도로 반복 측정하고 7개 상대와 직접 비교한다.

직접 교차 거래에서 기존 활성 판매자가 PR296의 120 제안을 받고도 체결하지 못해, 같은 실패 조건을 env2 후보로 새 task에서 한 번 점검한다. 이는 이미 관측한 실패를 이용하는 개발용 진단이며 독립 holdout으로 부르지 않는다. 해당 점검이 성사되면 후보의 역할별 3회 고정 상대 확인을 진행하고 위 가격 기준을 그대로 적용한다. 기준 통과만으로 자동 승격하지 않으며 후보 전용 안전·공식 근거를 요구한다. 미달하면 기존 정책으로 최종 검사를 진행한다.

대화 중단으로 종료된 실행은 checkpoint의 완료 거래만 보존하고 미완료 거래를 새 폴더·새 task로 다시 실행한다. 완료·중단·재개 수를 명시한 별도 합본을 만들며, 원래 미완성 summary를 새로 꾸미거나 중단을 승패로 채우지 않는다.

시도 수, 유효 체결 수, 완료 가격 평균/범위, 구매 예산 대비 절약액, 판매 최저 수락가 대비 초과액, 시도당 역할별 잉여, A2A 왕복 수, 실제 추론 호출/재시도/시간, 예산·하한가·상품·중복 구매·영수증 위반을 기록한다. 미체결을 빼고 좋은 체결만 선택하지 않는다. 판매 최저 수락가는 실제 원가와 다르므로 초과액을 순이익으로 표현하지 않는다.

실행 가능한 원본과 동일 모델 실험의 결과를 각각 보고하고, 공식 21개 검사와 필수 챌린지 회귀도 최종 소스에서 확인한다.
