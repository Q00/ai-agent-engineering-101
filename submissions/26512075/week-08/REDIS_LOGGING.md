# Redis 앱 로그

현재 Upstash 연결에 대한 앱의 저장·조회·삭제 결과를 기록한다. Redis 서버 자체 로그가 아니다.

- seller를 새로 실행하면 `storage_selected`가 선택된 저장소(`redis` 또는 `memory`)를 기록한다. 이는 연결 성공 확인은 아니다.
- Redis 작업 완료 후 `redis_operation`에 성공 여부, 작업 종류, 협상 ID의 SHA-256 해시를 기록한다. task 저장에는 버전, 조회에는 `found`를 남긴다.
- 실패 시 예외 종류만 남기고 원래 예외를 다시 전달한다. URL, 비밀번호, 협상 본문, 예외 메시지는 기록하지 않는다.
- 출력 위치는 표준 오류와 이 파일 옆 `logs/redis-app/<세션>-<PID>.jsonl`이다. 파일은 추가 방식으로 기록하며 기존 로그를 수정하거나 자동 삭제하지 않는다. 파일 기록 실패는 표준 오류에 알리고 거래 처리는 유지한다.
- 배포 환경에서 로컬 파일이 영구 보관되지 않는 경우 호스팅 로그 수집기로 표준 오류를 보관한다. 장기 운영 시 로그 용량을 점검한다.

수정은 다음 seller 실행부터 적용된다. 이 변경 과정에서 운영 seller를 재시작하거나 운영 Redis 데이터를 변경하지 않는다.

재시작 전 저장 성공과 재시작 후 다른 세션의 동일 `task_ref` 조회(`found: true`)를 비교하면 상태를 다시 읽었는지 확인할 수 있다. 조회 성공만으로 협상 재개·결제 완료까지 입증되지는 않는다. task 종료 시 내부 트랜잭션에서 수행하는 deal 정리는 별도 delete 이벤트가 아니라 task 저장에 포함된다.

검증: `python -m unittest test_storage_audit test_storage_env`
