# Plan–Execute 및 ReAct 하네스 실험 리포트

## 0. 리포트 목적

이 리포트는 동일한 로그 집계 태스크를 실행하는 다음 하네스를 비교한다.

- `run_react`
- `run_plan_execute`

## 1. 태스크와 실험 조건

두 하네스에 동일한 질문을 주었다. `app.log`에서 `ERROR` 줄이 가장 많은
시간을 `HH:00`으로 답하는 작업이다. 성공 기준은 실행 전에 작성한
`TASK.md`의 `expected: 14:00`이며, 원본 `app.log`에서 14시의 ERROR는
6건으로 다른 시간대보다 많다. `run_ab.py`는 실행 시작 시 `TASK.md`를
읽고 매 실행의 최종 답변을 이 값으로 판정한다.

두 조건은 `tools_shared.py`의 동일한 `read_file(path)` 및
`count_pattern(path, pattern)` 도구, 모델 호출 래퍼와 토큰 계측기를
사용한다. 코드 설정은 OpenAI 호환 API(`https://api.meta.ai/v1`),
`AGENT_MODEL` 미설정 시 `muse-spark-1.3`, 인증 환경변수
`MODEL_API_KEY`다. 환경변수로 모델을 덮어썼다면 실제 실행 모델은
CSV만으로 확인할 수 없다는 재현성 한계가 있다.

| 하네스 설계 요소 | `react` | `plan_exec` |
| --- | --- | --- |
| 컨텍스트 | 한 대화의 전체 이력을 다음 단계에 전달 | 계획용 대화와 실행용 대화를 분리 |
| 도구 | 두 조건 모두 같은 공유 도구 | 두 조건 모두 같은 공유 도구 |
| 종료 | 모델의 도구 없는 답변 또는 `max_steps=8` | 최대 4단계 계획 실행 후 별도 최종 답변 호출 |
| 오류 복구 | 도구 오류를 관찰값으로 받고 다음 행동을 선택 | `OFF_PLAN`이면 최대 1회 재계획 |
| 사람 개입 | 읽기 전용 도구라 승인 대상 없음 | 읽기 전용 도구라 승인 대상 없음 |

## 3. 해석과 기록 출처

두 하네스 모두 정답을 맞혔다. 이 여섯 실행에서 Plan–then–Execute는
ReAct보다 평균 **6,903 tokens(71.6%)**와 **1.33회**의 모델 호출을 더
사용했다. 계획 생성과 별도 최종 답변 호출이 비용의 한 원인일 수 있다.
다만 프롬프트, 대화 관리, 종료 방식이 함께 달라졌고 각 실행이 실제로
확인한 시간대 범위도 이 표만으로는 같다고 보장할 수 없다. 따라서
토큰 차이 전체를 재계획 구조 하나의 효과로 돌릴 수 없다. 기본 실험의
`replans=0`은 세 실행에서 재계획이 일어나지 않았다는 뜻이다.

**이전 자료 보존:** 기존 84회 결과는 `results_old.csv`, 그 실행의 원본
콘솔 로그는 `logs_old/`, 당시의 상세 분석은 `REPORT_old.md`라는
`_old` 이름으로 별도 보존했다. 이전 실험에는 설정 오류로 실패한 실행,
변형 비교 및 edited Plan의 강제 `OFF_PLAN` 재계획 실험이 포함된다.
그 기록의 행이나 로그를 이번 공식 6회 측정값으로 바꾸거나 합산하지
않았다. 새 기본 실험은 `results.csv`와 `logs/`에서 대조한다.

`TASK.md`와 과거 84회 자료는 첫 커밋에 함께 들어갔지만, 이번 기본
6회는 이미 커밋되어 있던 동일한 `TASK.md`의 판정 기준으로 다시
실행했다. 이전 이력은 재작성하지 않았다.

재현 명령은 제출 폴더에서 `python run_ab.py --runs 3`이다.
