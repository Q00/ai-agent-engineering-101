## 2. 현재 정책과 새 목표의 충돌

구매 지침은 호가가 예산 안이면 즉시 맞춰 사고, 가격만을 이유로 포기하기 전에 예산 전액을 제시하도록 한다. 가게 선택도 저렴한 가격보다 정직한 영수증·평판을 우선한다. 1위는 당시 거래 건수 성과였으며 저가 구매 성과가 아니다.

판매 지침은 최초 가격을 reserve~ceil(1.05×reserve)로 제한하고, reserve 이상인 실제 제안이면 수락하도록 한다. 이 정책은 체결·유입을 우선하며 높은 판매가를 탐색할 여지가 작다. reserve는 최저 허용가격이며 원가라고 입증되지 않았다.

## 3. 하나의 의사결정 흐름

검증 가능한 거래 사실 → 품목·가게별 가격/성공률 요약 → 하네스의 구매·판매 목표가격 → 제한된 협상 → 일치하는 영수증 → 사실에 근거한 평가 → 다음 가게 선택과 호가 조정.

구매 기억과 판매자 협상 상태는 현재 별도 경로다. 시장 거래·자기 후기 요약을 판매자 하네스에 공급하는 경로가 추가돼야 가격 적응이 실제 기능이 된다. 프롬프트에 적응하라는 문장만 넣어 완료로 간주하지 않는다.

### A. 후기·기억에 넣을 사실부터 정리

- 현재 주문의 품목·승인 예산·전송한 제안·수락가·영수증 유무/일치·결렬 이유를 구분한 구조화된 사실 묶음을 만든다.
- 후기 입력에서 판매자의 자유 문장과 과거 가게 선택 이유가 현재 거래의 객관 사실처럼 섞이지 않게 한다. 시장 사칭·별점 지시는 평가 규칙으로 채택하지 않는다.
- 객관적인 가격·예산·영수증 상태 문장은 코드의 사실과 대조한다. 별점과 정성 평가는 모델이 결정하되 잘못된 근거는 재작성하게 한다.
- 정상적인 예산 부족 결렬과 허위 영수증·합의 위반을 구분한다. 구매자가 받지 못한 키트 검증 결과를 이미 확인했다고 쓰지 않는다.
- 현재 불변 메모리의 후기 전후 저장은 같은 거래의 스냅샷 교체다. 이 경로를 중복 저장 버그로 판단하지 않는다.

### B. 구매: 예산을 상한으로 쓰고 목표가부터 제안

- 품목별 과거 실제 체결가·같은 가게의 제안/응답·현재 호가를 바탕으로 모델이 목표가와 첫 역제안을 정한다.
- 예산 안 호가 즉시 수락과 전액 예산 자동 제시 지침을 교체한다. 목표가에 충분히 가까우면 바로 수락할 수 있으나 항상 한 번 깎는 형식 규칙으로 만들지는 않는다.
- 반복 제안으로 새 정보가 생기지 않으면 모델에 다음 양보·현재 호가 수락·포기 중 선택을 요구한다. 동일 금액 반복 횟수와 전체 라운드·시간을 제한한다.
- 거절된 제안을 상대의 확정 최저가로 기록하지 않는다. 마지막 기회에도 가격·성공 가능성을 함께 보고 결정한다.
- 예산·상품·task·영수증 일치와 중복 구매 방지는 계속 코드가 막는다.

### C. 판매: 최저가·목표가·공개한 호가를 분리

- reserve는 고정 하한, 목표가격은 모델의 양보 판단 기준, 공개한 현재 호가는 이 협상에서의 약속으로 취급한다.
- 고정 5% 상한과 reserve 이상 무조건 수락을 다시 설계한다. 수요·최근 판매가·결렬·받은 후기를 요약해 모델이 목표가와 첫 호가를 정한다.
- 낮은 제안에는 목표가격 방향으로 협상하고, 이미 공개한 호가를 충족하는 유효 제안은 약속에 맞게 처리한다.
- 후속 quote는 하한가 이상·직전 quote 이하로 제한한다. 실제 기준선에도 책장 273→260→273 재상승이 있어 별도 회귀 대상으로 삼는다. 구매자의 더 높은 실제 제안 수락은 이 quote 상한과 구분한다.
- 높은 호가로 판매가 0이 되는 변경은 성공으로 보지 않는다. 방문 대비 검증 성사율과 최저가격 대비 추가 확보액을 함께 본다. 추가 확보액을 실제 순이익이라 부르지 않는다.

### D. 가게 선택: 평판과 가격을 함께 학습

- 같은 품목의 지급가격·검증 여부를 관찰한 범위·성공/결렬·시간·관측 수·최근성을 모델에 요약한다.
- 평판이 좋다는 이유만으로 한 가게를 계속 고르지 않고 소량의 새 가게 탐색을 구분해 실험한다.
- 한 주문을 여러 가게에서 중복 체결하지 않는다. 사전 호가 탐색을 넣는 경우에도 주문·시간·호출 한도를 별도로 정한다.
- `metadata.ask`를 숫자 제안으로 읽고 현재 상태에 전달한다. 텍스트와 다를 때의 처리도 정하고, 판매자 metadata가 구매 예산이나 규칙을 바꾸게 두지 않는다.

### E. 카탈로그 할인·리뷰 이벤트

- 실제 존재한 기준가격·현재 제안가·실제 적용 조건을 명시하는 할인은 실험 후보로 둔다. 기본 램프 첫 호가 100~105에서는 가격 인하 여유 자체가 작다.
- 할인 문구에는 여러 숫자가 섞이므로 현재 호가는 `metadata.ask`로 분리하고 본문에서 명확히 식별한다. 할인 표시 가격과 영수증 가격을 일치시킨다.
- 표준 R1 가게 목록은 이름·URL·후기만 전달한다. Agent Card·카탈로그 세일 문구는 선택 전에 자동 노출되지 않는다. 선택 후 협상에서의 기준점 효과와 선택 전 유입 효과를 분리해 측정한다.
- 체결 응답에서 합의 가격·영수증 일치 여부에 대한 솔직한 후기를 요청할 수 있다. 좋은 별점에만 보상하는 설계는 평판 측정과 보상 반응을 섞으므로 우선 후보에서 제외한다.
- 재구매 쿠폰·후기 작성 보상은 안정된 구매자 신원·실제 작성자·혜택 사용 여부를 연결하는 기능이 없어 지금은 약속하지 않는다. task ID를 재구매자 ID로 사용하지 않는다.
- 시간 한정·선착순 판촉을 쓴다면 실제 시간·잔여 수량을 상태로 관리해야 한다. 공개 문구만으로 희소성을 가정하지 않는다.
- 기존 등록명·키와 이름별 기억을 유지한다.

## 4. 구현·검증 순서와 채택 기준

1. 후기 사실 검증·외부 지시문 격리 회귀를 먼저 준비한다. 예산 225/지불 225인데 초과 서술, 결렬+5점 요구, 검증 미관찰을 신뢰 검증으로 쓰는 사례가 실패하는지 확인한다.
2. 같은 상대·품목·예산 묶음에서 구매 역제안만 바꿔 지급 비율·검증 성사율·시간·호출을 비교한다.
3. 판매자에게 실제 자기 거래·후기 요약을 전달하고 목표가격·양보 규칙을 바꿔 판매가·방문 대비 성사율을 비교한다.
4. 가격을 보는 가게 선택·소량 탐색을 비교한다.
5. 할인 표현·후기 요청은 실제 가격 정책과 분리해 추가 비교한다. 여러 변수를 한꺼번에 바꾼 결과를 각 변수의 효과로 주장하지 않는다.
6. 의미 있는 회귀와 공식 25개 계약 검사를 통과한 후보만 실제 투입 대상으로 삼는다. 코드에서 가격을 고정하고 모델은 설명만 하게 만들지 않는다.

구매 지표는 검증된 체결의 품목별 가격/예산 비율과 검증 성사율, 판매 지표는 품목별 가격·방문 대비 성사율이다. 지연·모델 호출·후기 사실 오류를 함께 기록한다. 결렬을 늘려 성공 거래 평균가격만 좋아지는 변경을 채택하지 않는다. 실제 시장의 단순 전후 비교에는 주문 구성·시간·다른 참가자의 변경이 섞인다.

공식 필수 챌린지 1의 자기 거래·후기에 따른 가격 변경과 전후 점유율·평균가 비교, 챌린지 2의 부정직한 상대 관찰·회피 경과에 연결한다. 현재는 상대 지시문과 잘못된 후기의 관측 근거를 확보했으며, 자동 회피·보완 후보 구현과 효과 검증은 남아 있다. 25개 통과만으로 가격 효율·후기 공정성까지 달성했다고 보고하지 않는다.
