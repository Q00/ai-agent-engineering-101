# 구매 방문 중 가게 소개: 로컬 구현

최종 검증: 전체 오프라인 회귀 **317/317 PASS**([로그](offline.log)), 변경 Python 파일 Ruff PASS([로그](lint.log)), 변경 파일 strict 타입 **0오류·0경고**([로그](types.log)). 관련 13개 실행에서 CLI 옵션의 전달, 선택된 판매자 최초 요청의 공개 링크, 후속 제안의 숫자 전용 형식, 예산 검사, 원본 영수증·최종 JSON 보존을 확인했다. 실제 외부 판매자와의 호환성·홍보 효과, 새 버전 공식25개 전체 실행은 이번에 검증하지 않았다.

사용자 요청: 우리 구매자가 다른 판매자를 찾아갈 때 우리 가게를 홍보하는 경로를 반영한다.

시장 구매 CLI에 `--promote-shop`을 추가하고 `agent.json`의 시장 구매 명령에서 켰다. 해당 옵션이 켜진 구매의 최초 상품 요청에만 등록명·공개 가게 URL·Agent Card·자발적 공유 안내를 덧붙인다. 후속 숫자 제안에는 광고가 없고 구매 예산은 공개하지 않는다. 후기·별점·시장 결과 JSON·영수증은 기존 거래 사실을 유지한다. 옵션 없는 CLI와 기존 Week06 구매자는 기존 요청을 유지한다.

이 문구는 현재 운영하는 공개 가게의 소개이며 추천 할인 지급 약속은 아니다. 추천코드의 발급·타인 사용·서명된 실제 체결·중복 방지·하한가를 지키는 지급 원장이 없으므로 인센티브는 아직 구현·활성화하지 않았다. 추후 인센티브를 구현하더라도 별점이나 후기 문구와 보상을 묶지 않고 실제 추천 거래를 검증해야 한다.

현재 자동구매는 OFF다. 이번에는 로컬 코드만 변경했으며 VPS 배포·구매 시작·등록·외부 홍보 전송·공개 후기 작성은 하지 않았다. 상대 판매자가 소개를 기억하거나 다른 구매자에게 전달하는지, 유입 효과가 있는지는 미검증이다. 홍보가 붙은 자연어 요청을 엄격하게 파싱하는 상대와의 호환성은 상대 구현에 따라 달라질 수 있어 옵션으로 끌 수 있다.

검증 중 첫 `.venv/bin/python -m pytest ...` 시도는 해당 환경에 pytest가 없어 실패했다. 기존 캐시의 Python3.12 검증 환경으로 구매·주문·CLI 관련 13개를 통과했다. 최초 린트의 bool 위치 인자·줄 길이·중복 함수 설명 문제는 keyword-only 인자와 최소 구현으로 수정했다. 최초 폴더 전체 strict 타입 검사는 기존 deploy/vps·seller_history 등의 문제와 신규 테스트의 Any 할당을 포함해 220개 오류를 보고했다. 신규 Any 할당을 파싱 경계로 수정했으며 기존 영역의 오류는 이번 홍보 변경에 섞어 수정하지 않는다. 최종 검증 범위와 결과는 아래 로그를 따른다.
