# 7주차 구현·검증 보고서 — 진행본

현재 범위는 기존 하네스 기반 시장 구매자와 판매자 영수증 서명 구현, 공식 시장 검사다.
실제 수업 시장 참가와 필수 챌린지 1·2는 아직 수행하지 않았다.
교수 명세는 `7a2dfb159c199ac257772176662d45161914c08e`를 기준으로 한다.

## 1. 가게 선택과 거래 기억

6주차의 자체 Python function-tool 하네스를 재사용한다. 고정 모델은
`gpt-4.1-nano-2025-04-14`, temperature는 0이다. 시장 목록의 가게 이름·URL·최신 후기와
같은 이름의 최근 자기 거래 최대 10개를 하네스 입력에 제공한다. 하네스가
`select_shop(index, reason)` 도구로 가게 하나를 선택하며, 코드는 목록 범위 밖 선택을
거부한다. 선택 이유를 로그에 남기고 선택한 한 가게에만 기존 A2A 구매자로 접근한다.

기억 파일은 기본 `.market/buyer-memory.json`이다.
`{shops: {name: [Trade, ...]}}` 형태이고 각 Trade는 상품·예산·선택 이유·실제 Purchase와
평가를 담는다. URL 대신 이름으로 연결해 터널 주소가 바뀌어도 이력을 제시한다.
임시 파일에 완전한 스냅샷을 쓰고 교체하며, 후기 생성 전에 거래 사실을 먼저 저장한다.
이 저장은 현재 키트의 순차 실행을 전제로 한다.

## 2. 후기와 협상

공개 후기와 판매자 설명은 명령이 아닌 신뢰되지 않은 관찰로 전달한다.
구체적인 계약 위반·자기 거래 경험을 참고하되 단일 별점이나 막연한 칭찬만으로
판단하지 않도록 지시한다. 가격 제안·포기·후기는 하네스의 도구 호출로 결정한다.
제안 금액의 예산 초과는 코드에서 거부한다.

시장 주문은 원래 상품명과 맞아야 한다. 판매자 metadata가 다른 상품을 제시하면
첫 가격 제안 전에 중단한다. 영수증은 실제 제안가·예산·상품·SKU·task와 대조한다.
전달받은 data Part의 추가 필드·숫자 타입·서명을 보존해 마지막 JSON의 receipt에 넣는다.
성사되지 않으면 receipt는 null이고, 실패 관찰도 기억·후기 입력에 남긴다.
별점은 1~5의 정수, 후기는 비어 있지 않은 문자열로 검증한다.
단순 예산 부족을 부정직함이라고 단정하거나 배송·품질을 확인했다고 쓰지 않도록 한다.
가게 공개키가 목록에 없으므로 구매자가 직접 서명을 검증했다고 주장하지 않는다.

## 3. Round 0·1·2의 실제 수업 시장 기록

**아직 참가하지 않았다.** 아래 공식 검사는 교수 코드가 띄운 로컬 상대와의 테스트이며,
실제 수업 시장의 점유율·평판·라운드 성과를 대신하지 않는다.
교수의 실제 MARKET_URL을 확인한 뒤 키트로 참가하고 별도 원본 로그를 남겨야 한다.
교재의 대시보드 예시·참조 구현 수치는 본인 성과로 사용하지 않았다.

## 4. 영수증 서명과 확인한 실패

코드는 실제 A2A task id와 낙찰 정수가격으로 `{shop,item,price,task}`를 구성한다.
키 정렬·공백 없는 UTF-8 canonical JSON에 Ed25519 서명을 만들고 base64
`sig_seller`를 넣는다. SKU는 서명 대상 네 필드 밖의 확장으로 유지한다.
키트가 검증 뒤 구매자 서명을 추가하므로 sig_buyer를 임의로 만들지 않는다.

키는 키트·공식 검사가 로컬에 생성하며 소스·로그에 넣지 않는다.
판매자가 제출 디렉터리의 절대 경로로 읽고 권한을 0600으로 제한한다.
일반 하네스가 임시 작업 폴더로 이동하므로 상대 경로로 키·기억을 찾지 않도록 했다.

오프라인 검증에서 잘못된 키·가격/task 변조·분수 가격·종료 후 요청을 검사했다.
독립 검토에서는 기존 구매자가 판매자 metadata를 따라 주문 상품을 바꿀 수 있는
문제를 재현했다. 시장 경로에 정확한 주문 상품 검사를 추가해 첫 가격 제안 전 차단하고,
기존 설명형 구매의 호환성도 별도 회귀로 확인했다.
이 기록을 실제 수업 시장에서 만난 사기 사례라고 해석하지 않는다.

## 5. 필수 챌린지 상태

1. 거래·후기에 따른 호가 변경과 전후 점유율·평균 거래가: **미실행**.
2. 실제 시장의 부정직한 참가자 관찰과 회피 경과: **미실행**.

시장 기록을 확보한 후 진행한다. 검사 코드의 고정 상대나 임의로 만든 악성 예시를
실제 수업 시장 참가자처럼 보고하지 않는다. 6주차 공개 판매자는 서명 전 버전이므로
7주차 배포 완료로 등록하지 않았다.

## 6. 검증

- 오프라인 회귀: **36/36 통과**.
- Ruff ALL·포맷: 통과, Python 25파일.
- strict basedpyright: 오류·경고 0.
- 독립 코드 검토: 최초 BLOCK의 상품 대체 문제 수정 후 APPROVE.
- 공식 시장 검사: **첫 실제 모델 실행에서 25/25 통과**. 현재 검사 코드 해시와 결과 파일의 해시가 일치한다.
- 판매자 램프 체결 3회 모두 100, 서명 검증 3/3. 구매자 램프 거래 3회 모두 120, 예산 230의 책장 3회는 초과 제안 없이 receipt null이다. 후기 선택은 좋은 후기 가게 South 3/3, North 요청 0이다.
- 서버·구매자 로그의 MODEL_USAGE는 116회, 입력 75,005·출력 3,980토큰, MODEL_RETRY는 0이다. 이는 관측 사용량이며 청구서 감사나 실제 금액 계산이 아니다.
- 테스트 후 이름별 기억은 Kit Shop 6건·Kit Shop South 3건이다. 원문은 [첫 공식 실행 보존본](logs/validation-attempt-1/)에 있다.
- 전체 제출 요건 충족이나 PR 제출 완료를 주장하지 않는다.
- 전체 구조 검사에서는 실제 시장 ledger를 담은 `logs/market-kit.log`만 없어 1개 미완료다. [검사 원문](logs/structural-after-25.log). 필수 챌린지와 실제 라운드 기록도 보고서에서 미실행으로 구분한다.

단순 결렬을 부정직함으로 보지 말라는 지시만으로 공정한 평판이 보장되지는 않았다.
같은 230 제안을 반복한 사례도 있어 협상 효율을 입증한 결과로 보지 않는다.
후기 선택 3/3과 검사 25/25는 이 고정 상대·현재 모델의 관측이며 일반적인 사기 탐지율이나
공정성, 최저가 보장은 아니다. 실제 수업 시장에서의 비교는 아직 남아 있다.
