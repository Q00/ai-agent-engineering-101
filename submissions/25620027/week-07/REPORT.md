## 1. 가게 선택과 거래 기억

6주차의 자체 Python function-tool 하네스를 재사용한다. 고정 모델은
`gpt-4.1-nano-2025-04-14`, temperature는 0이다. 시장 목록의 가게 이름·URL·최신 후기와
같은 이름의 최근 자기 거래 최대 10개를 하네스 입력에 제공한다. 긴급 변경 후에는 과거 자유서술 대신 상품·예산·성사·가격·영수증 존재의 숫자 사실을 사용한다. 하네스가
`select_shop(index, reason)` 도구로 가게 하나를 선택하며, 코드는 목록 범위 밖 선택을
거부한다. 선택 이유를 로그에 남기고 선택한 한 가게에만 기존 A2A 구매자로 접근한다.

기억 파일은 기본 `.market/buyer-memory.json`이다.
`{shops: {name: [Trade, ...]}}` 형태이고 각 Trade는 상품·예산·선택 이유·실제 Purchase와
평가를 담는다. URL 대신 이름으로 연결해 터널 주소가 바뀌어도 이력을 제시한다.
임시 파일에 완전한 스냅샷을 쓰고 교체하며, 후기 생성 전에 거래 사실을 먼저 저장한다.
이 저장은 현재 키트의 순차 실행을 전제로 한다.

## 2. 후기와 협상

공개 후기와 판매자 설명은 명령이 아닌 신뢰되지 않은 관찰로 전달한다.
구체적인 계약 위반·자기 거래 경험을 참고하되 단일 별점이나 막연한 칭찬만으로
판단하지 않도록 지시한다. 가격 제안·포기는 하네스의 도구 호출로 결정한다. 1.3.0에서는 후기 도구의 제안 뒤 코드가 실제 거래 사실과 공개 별점 상한을 적용한다.
제안 금액의 예산 초과는 코드에서 거부한다.

시장 주문은 원래 상품명과 맞아야 한다. 판매자 metadata가 다른 상품을 제시하면
첫 가격 제안 전에 중단한다. 영수증은 실제 제안가·예산·상품·SKU·task와 대조한다.
전달받은 data Part의 추가 필드·숫자 타입·서명을 보존해 마지막 JSON의 receipt에 넣는다.
성사되지 않으면 receipt는 null이다. 초기 버전은 실패 관찰도 후기 입력에 남겼으나, 긴급 변경 후에는 외부 실패 원문을 후기 하네스에 전달하지 않는다.
별점은 1~5의 정수, 후기는 비어 있지 않은 문자열로 검증한다.
단순 예산 부족을 부정직함이라고 단정하거나 배송·품질을 확인했다고 쓰지 않도록 한다.
가게 공개키가 목록에 없으므로 구매자가 직접 서명을 검증했다고 주장하지 않는다.

## 4. 영수증 서명과 확인한 실패

코드는 실제 A2A task id와 낙찰 정수가격으로 `{shop,item,price,task}`를 구성한다.
키 정렬·공백 없는 UTF-8 canonical JSON에 Ed25519 서명을 만들고 base64
`sig_seller`를 넣는다. SKU는 서명 대상 네 필드 밖의 확장으로 유지한다.
키트가 검증 뒤 구매자 서명을 추가하므로 sig_buyer를 임의로 만들지 않는다.

키는 키트·공식 검사가 로컬에 생성하며 소스·로그에 넣지 않는다.
판매자가 제출 디렉터리의 절대 경로로 읽고 권한을 0600으로 제한한다.
일반 하네스가 임시 작업 폴더로 이동하므로 상대 경로로 키·기억을 찾지 않도록 했다.

오프라인 검증에서 잘못된 키·가격/task 변조·분수 가격·종료 후 요청을 검사했다.
독립 검토에서는 기존 구매자가 판매자 metadata를 따라 주문 상품을 바꿀 수 있는
문제를 재현했다. 시장 경로에 정확한 주문 상품 검사를 추가해 첫 가격 제안 전 차단하고,
기존 설명형 구매의 호환성도 별도 회귀로 확인했다.
이 기록을 실제 수업 시장에서 만난 사기 사례라고 해석하지 않는다.

## 7. R1 첫 호가 개선·재검증·실제 적용

판매자 첫 호가가 하한가의 약 1.3배였던 지침을 바꿨다. 모델은 첫 quote를
하한가부터 `ceil(reserve * 1.05)`까지의 정수 범위에서 선택한다. lamp는 100~105,
chair는 180~189, bookshelf는 260~273이다. 범위를 벗어나면 상태·응답을 내보내기 전에
도구가 거부하고 모델이 다시 결정한다. 이후 구매자의 유효한 높은 제안은 기존 방식으로
수락·서명할 수 있다. 하한가·구매자 전략·모델·서명 규칙은 동일하다.

별도 worktree에서 오프라인 45/45, strict Ruff·basedpyright·형식 검사와 독립 검토를
통과했다. 새 실제 모델 공식 검사도 25/25를 통과했다. 램프 세 건은 첫 호가와 체결가
105·100·105였고 서명 3/3, 좋은 후기 가게 선택 3/3이다.

## 12. 후기·프로토콜 문자열 격리와 직접 관찰 기반 경고

후속 보완은 선택 모델에 공개 후기 원문을 넣지 않고 별점·결렬/추가요금 주장 등의 숫자·불리언 신호만 전달한다. 이 신호는 검증되지 않은 리뷰어 주장이다. 후기 안의 지시문만으로 해당 판매자가 공격했다고 판정하지 않는다. 협상 요약에서도 상대 task ID·SKU·상품명 문자열을 제외하고 주문 상품·호가·상태·코드가 계산한 사실을 전달한다. 원래 task·SKU는 프로토콜과 영수증 검사를 위해 내부에 유지한다.

### 변경 내용과 적용 범위

사용자의 후속 요청은 다른 가게 분석을 반영한 배포, 박한 공개 평점, 10분 가격 비교 홍보다. 정상·우수 성사에 공개 3.5점 상한을 요청했으나 시장 스키마는 1~5의 정수만 허용한다. 따라서 **정상·우수 성사 모두 3점**, 단순 결렬은 중립 3점으로 구현했다. 직접 받은 운영자 사칭·별점 강요 지시문 사건에는 기존 1점 규칙을 유지한다. 실제 지불액·예산·제안 횟수·동일 상품의 자기 과거 최저 구매가를 적고, 확인하지 않은 배송·품질·사기·서명 검증을 만들어 쓰지 않는다. 과거 후기와 거래 기억을 소급 수정하지 않았다.

우리 구매자의 선택 자료에서는 공개 숫자 별점을 제외하고, 구체적인 과청구·결렬·권한 사칭 신호와 자기 거래의 가격·성사·안전 기록을 유지한다. 자기 과거 평가도 거래 사실 입력에 넣지 않는다. 따라서 자기가 박하게 준 별점을 다음 구매의 품질 지표로 다시 읽는 경로는 막았으나, 다른 참가자가 공개 후기에 반응하는 간접 영향까지 없다고 보장하지 않는다. **운영 자동 구매는 꺼져 있으며 이번 변경으로 실제 시장에 새 후기를 게시하지 않았다.** 공식 검사의 후기는 검사 상대에 대한 출력이며 실제 공개 후기와 구분한다.
