## 로그에서 확인한 차이

1. ReAct 실행 1은 파일 읽기와 24개 시간대 집계를 수행해 도구 25회·모델 3회를 호출했다. 실행 2·3은 파일을 한 번 읽고 곧바로 답해 모델 2회로 끝났다. 같은 하네스 안에서도 실행 경로와 비용이 달랐다.
2. Plan-then-Execute 실행 4·5는 6단계 계획을 만들었고, 실행 6은 읽기 1단계·24개 시간대별 집계·비교 답변으로 26단계를 만들었다. 실행 6은 모델 53회·161,116토큰으로 평균을 크게 올렸다. 계획 단계별로 모델을 재호출하고 누적 문맥을 다시 전달하는 구조와 로그가 이 차이를 설명한다.
3. 도구 호출 수가 같은 ReAct 실행 1과 Plan-then-Execute 실행 5·6도 모델 호출은 각각 3·10·53회였다. 실행 결과의 차이를 도구 개수만으로 설명할 수 없다.
4. 실행 6의 정규식 `04:.*ERROR`는 `2026-09-01 14:04:06 ERROR ...`도 잡는다. 시(hour)에 고정하지 않아 분(minute)까지 일치한 것이다. 원본 로그를 따로 집계하니 04·07·11·15·18·23시의 중간 건수가 잘못됐지만 최댓값은 여전히 14시여서 최종 성공 판정은 O였다.
5. 따라서 최종 정답 일치와 과정의 정확성을 구분해야 한다. 3회씩 실행한 하나의 짧은 태스크에서 ReAct가 더 적은 토큰을 썼다는 관찰이며, 모든 문제에서의 일반적 우열이나 통계적으로 확정된 차이를 뜻하지 않는다.
