# Challenge 1 검증 기록

## 결론

실제 시장 데이터의 수집과 가격·평판 분석까지는 마쳤지만, 분석을 바탕으로 바꾼 가격 전략을 시장에 다시 배포하고 전후 성과를 비교하는 단계는 수행하지 못했습니다. 따라서 이 Challenge를 완료했다고 주장하지 않습니다.

## 확인한 실제 데이터

`logs/operations/leaderboard.jsonl`에는 다음과 같은 시점별 집계가 남아 있습니다.

- 2026-10-27 14:47:11 KST: Seller 거래 1건, 방문 1회, 매출 295, 이익 35, 별점 3.00, Profit 47위
- 2026-10-27 15:41:45 KST: Seller 거래 40건, 방문 78회, 매출 8,692, 이익 932, 별점 4.28, Profit 42위
- 2026-10-27 17:41:54 KST: Seller 거래 101건, 방문 178회, 매출 22,492, 이익 2,712, 별점 4.43, Profit 39위

종료 시점의 판매 전환율은 `101 / 178 = 56.74%`이고, 거래당 평균 매출은 약 222.69, 거래당 평균 이익은 약 26.85입니다. 운영 중 확인한 최근 리뷰에서는 예산을 모두 사용한 거래보다 할인 폭이 있는 거래가 대체로 더 높은 별점을 받는 경향이 있었습니다.

## 실제 적용 여부

운영 중에는 거래 안정성과 기존 25/25 통과 상태를 우선하여 Seller의 프롬프트와 가격 결정 코드를 바꾸지 않았습니다. 따라서 위의 순위 상승과 실적 증가는 기존 전략으로 누적된 결과이며, 새로운 가격 전략의 효과로 해석하지 않습니다. 17:40:18 KST에 운영을 종료했으므로 새 전략의 실시장 배포와 전후 비교도 진행하지 않았습니다.

후속 실험에서는 같은 시간대의 방문 구성 차이를 줄인 상태에서, 구매 제안이 reserve 이상일 때 조기에 수락하는 전략과 현재 전략을 각각 운영하여 전환율·평균 이익·별점을 함께 비교할 필요가 있습니다.


## 갱신 (2026-10-27 18:00 이후, 2차 운영)

위의 "미완료" 상태 이후 가격 정책을 실제로 적용했습니다.

- `update_prices.py`가 대시보드 자기 행, 자기 리뷰, kit 로그의 주문 예산 299줄, 이전 모델 호가(lamp 150, bookshelf 340/350)를 읽고 `pricing-policy.json`(lamp 105, chair 225, bookshelf 295)을 썼습니다. 실행 로그는 `update-prices-1027-1801.log`, `update-prices-1027-1802.log`입니다(두 번째 실행은 이전 호가 수집 경로를 고친 뒤의 결과).
- `seller.py`는 정책이 있으면 첫 호가에 그 값을 씁니다. reserve는 바뀌지 않았습니다.
- 공식 Market Test 25/25를 다시 통과했고, 18:10:50 KST에 같은 이름과 키로 재등록했습니다.
- 변경 후 Seller의 협상별 결과는 `seller-trades.jsonl`, 전후 비교는 `compare-*.log`(`compare_prices.py`)에 있습니다.
