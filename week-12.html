지갑과 faucet

키트는 처음 실행할 때 Maroo testnet 지갑을 두 개 만든다. shop_wallet.key는 가게로서 서명하는 지갑이고, buyer_wallet.key는 다른 에이전트에게 대금을 보내는 지갑이다. 송금은 buyer만 하므로 돈이 필요한 쪽도 buyer 지갑이다. Round 3의 키는 Ed25519라 Round 4에서 쓸 수 없다.

M2

miniapp.js

app/은 내 프런트엔드라 마음대로 바꿔도 된다. 지킬 것은 <script src="/miniapp.js"></script> 한 줄이다. 이 스크립트가 페이지에 window.miniapp을 만든다.

함수하는 일
miniapp.chat(text, user)에이전트에게 메시지를 보내고 답을 받는다
miniapp.offer(name, description, fn)에이전트에게 도구 app_<name>을 건넨다. fn(args)는 페이지에서 돈다
miniapp.onState(fn)에이전트 이름, 채팅, 허용을 기다리는 MeshKit 호출, 최근 행동과 도구
miniapp.consent(id, approved)MeshKit 호출을 허용하거나 거절한다

페이지가 offer로 건넨 도구는 에이전트가 만들지 않고도 쓸 수 있는 유일한 도구다. 예를 들어 앱이 사용자의 장바구니나 위치를 offer로 내놓으면, 에이전트는 그 정보를 보고 시장에서 물건을 고른다. 휴대폰에 설치되게 하려면 starter 페이지의 <head>에 있는 viewport(viewport-fit=cover 포함), manifest, theme-color, apple-touch-icon을 남겨 둔다.

app/index.html
<script src="/miniapp.js"></script>
<script>
miniapp.offer("my_budget", "The user's budget for today, in credits",
              () => ({credits: 30000}));
miniapp.onState(s => render(s));
document.querySelector("form").onsubmit = async e => {
  e.preventDefault();
  const answer = await miniapp.chat(input.value, "me");
  show(answer);
};
</script>

FIG. 02의 A가 이 흐름이다. 앱에서 "오늘 예산 안에서 골라 줘"라고 말하면 에이전트는 필요할 때 app_my_budget을 부르고, 함수는 휴대폰 화면 안에서 돌아 결과를 돌려준다.

휴대폰에서 열기

어디서run에 더할 것여는 주소
이 컴퓨터없음http://127.0.0.1:8800/
어디서든 휴대폰--app-tunnel키트가 출력한 https://....trycloudflare.com/?k=...
같은 Wi-Fi의 휴대폰--app-host 0.0.0.0키트가 출력한 http://192.168.x.x:8800/?k=...
iOS 앱위 둘 중 하나출력된 링크를 앱에 붙여 넣는다

앱이 컴퓨터 밖에서 열리면 접속 코드를 묻는다. 키트는 코드가 붙은 링크(?k=...)를 터미널에만 출력하고 로그에는 남기지 않아서, 에이전트의 도구도 이 코드를 읽지 못한다. 브라우저는 코드를 쿠키로 기억한다. 코드는 .kit/app.key에 있고, 지우고 다시 실행하면 바뀐다. 링크를 가진 사람은 누구나 내 에이전트와 말하고 MeshKit 호출을 허용할 수 있으니 링크는 나만 가진다.

기기설치
AndroidChrome에서 https:// 링크를 열고 메뉴의 앱 설치. Chrome은 https:// 링크에서만 설치한다
iPhone, SafariSafari에서 https:// 링크를 열고 공유, 홈 화면에 추가. 코드를 물으면 k= 뒤를 넣는다
iPhone, 앱Xcode로 scripts/round4/ios/MiniApp.xcodeproj을 열고 Run. 실제 기기는 Signing에서 Team(무료 Apple ID 가능)과 bundle identifier를 바꾼다

macOS가 Python의 수신 연결을 허용할지 물으면 허용한다. 학교나 카페 Wi-Fi는 기기끼리의 연결을 막는 경우가 많아서, 그럴 때는 --app-tunnel을 쓴다.

MeshKit

다른 사람이 만든 미니앱의 기능을 내 에이전트가 쓰는 방법이다(FIG. 02의 B). meshkit.json에 그 앱을 적으면 그 앱의 기능 하나하나가 mesh_로 시작하는 도구가 된다. 에이전트가 이 도구를 부르면 내 휴대폰에 "에이전트가 허락을 구합니다" 창이 뜨고, 사람이 허용을 눌러야 상대 앱이 실행한다. 상대 앱은 결과에 서명한 영수증을 붙여 돌려주고, 키트는 서명이 맞을 때만 결과를 에이전트에게 넘긴다. 에이전트가 만든 도구는 앱 주소에 닿지 못해서 허용은 사람만 누를 수 있다.

MeshKit 저장소의 예제 앱 DailyMart로 먼저 해 본다. 생활용품을 주문하는 기능(grocery.purchase_essentials) 하나를 내놓는 앱이다.

에이전트가 처음 만드는 도구

키트는 매번 실행을 시작할 때 시장의 목록 카드를 에이전트에게 건넨다. 에이전트가 가진 것은 forge_tool, read_tool, reply, write_note, sleep뿐이라, 주문을 받든 입고를 하든 먼저 도구를 만들어야 한다. 도구는 tools/<name>/ 아래의 파일로 이루어진다.

파일내용
permission.ymlname, description, permission(network, write, identity, wallet, pay_limit, timeout, handles), version
logic.pydef run(args, kit) -> JSON
test.pydef test(run, kit)
forge.json키트가 남기는 기록: 버전, 시각, 세 파일의 해시

아래는 키트 테스트가 에이전트 대신 만들어 넣는 가게 응답 도구의 일부다. 손님이 원하는 SKU를 받으면 재고를 찾고, 없으면 도매시장에서 하나 사 오고, 가게 지갑으로 서명한 checkout_jwt를 돌려준다. 지갑 키는 보지 못하고 kit.sign_jwt만 부른다.

tools/shop_handler/logic.py
def run(args, kit):
    data = args.get("data") or {}
    acc = data.get("acceptable") if isinstance(data, dict) else None
    if not acc:
        return {"reply": "어떤 상품을 찾으세요?", "state": "input_required"}
    h = {"authorization": "Bearer " + kit.token("shop")}
    inv = httpx.get(kit.market + "/api/inventory", headers=h, timeout=20).json()
    unit = next((u for u in inv["units"] if u["sku"] in acc and u["grade"] != "expired"), None)
    ...
    return {"reply": f"{price} 크레딧에 드릴게요.",
            "data": {"checkout_jwt": kit.sign_jwt(co, "shop"), "price": price}, "state": "completed"}

키트는 test.py를 별도 프로세스에서 돌리고, 통과한 도구만 등록한다. 같은 이름으로 다시 만들면 다음 버전이 되고 옛 버전은 tools/.deprecated/로 간다. 해시가 맞지 않는 도구는 불러오지 않으므로 사람이 손으로 고친 도구는 쓸 수 없다. 에이전트가 무엇을 만들고 어떻게 썼는지는 logs/forge.jsonl과 logs/react.jsonl에 남고, agent_kit.py tools --dir ...로 만든 도구 목록을 볼 수 있다.
