## 확인하고 수정한 하네스 문제

- 결과 가격·실제 한도·완료된 위반 거래와 위반 시도, 보고서 표의 표시 반올림을 코드로 계산합니다.
- 명시적 도구 호출/응답과 사건 순서로 제안·거절·서버 거부·같은 턴 회복을 구분합니다.
  첫 제안과 주입 이후 제안을 섞거나 판매자 최저가를 최고가로 해석하지 않도록 근거를 제공합니다.
- 실패한 첫 시도와 재시도의 협상 ID·결과 표지를 분리합니다. 정상 재시도만 보고
  중단 시도의 원래 행이 보존됐다고 추정하지 않습니다.
- 커밋 메시지·시간 대신 Git 객체의 조상 관계를 수집합니다. 입증할 수 없는
  실행 순서를 만들어내지 않고, 지원되는 이력 관측은 모델이 덮어쓰지 못합니다.
- 여러 파일에 끝 개행이 없을 때 전체 파일 준비 예산이 모자라던 계산을 수정했습니다.
- MCP의 구버전 initialize 절차를 강요하던 오판을 막기 위해 고정 프로토콜의
  [공식 버전 설명](https://py.sdk.modelcontextprotocol.io/protocol-versions/)을 제공합니다.
  초기화가 없다는 이유만으로 감점하지 않습니다.
- 빈 작업 폴더·사용자 config 제외만으로 글로벌 AGENTS.md가 빠지지 않았습니다.
  `project_doc_max_bytes=0`을 적용하고 합성 표식의 기본/제외 설정을 실제 호출로 대조했습니다.
  이 대조는 지침 로드 여부의 증거이며 모든 판정 변동의 원인 규명은 아닙니다.
- Codex의 도구 실행을 제한하고 완료 응답·실패 이벤트를 구분합니다. 명시한
  비치명적 시작 안내와 실제 도구 실행을 혼동하던 검사도 수정했습니다.
- 가산 ID를 줄 번호가 아닌 구현 앵커에 연결하고, 후보 발견과 자격 판단을 분리합니다.
  유효한 후보의 지원 파일 요청을 잘못 거절하던 검증도 수정했습니다.
- 차이·미완료가 남은 벤치마크는 `acceptance.json`에 실패를 남기고 명령도 실패합니다.

  검증 전송이 실패해도 성공한 최초 관측은 재추첨하지 않습니다. 기본 재시도는 0회입니다.
- 실패→복구, 상한, 비용 보존, 정상 판정 재추첨 금지는 로컬 장애 주입으로 확인했습니다.
  최종 코드의 실제 항목 진단에서는 오류가 발생하지 않아 실제 장애 복구를 입증한 것은 아닙니다.
- #282 F07·#266 F08만 각각 최초·재생·독립 신규로 진단했습니다.
  두 항목 모두 상태/피드백 유형이 같았고 처리 실패는 없었습니다. 실제 호출 8회,
  저장 재생 0회입니다. **완전한 학생 채점이나 전체 항목 신규 일관성 검사가 아닙니다.**
- 최종 코드에서 기존 30조건을 모델 호출 없이 재조립했습니다. 항목 630/630,

  독립 신규 판정의 불일치를 해결한 결과는 아닙니다.
- Claude·다른 API·상위 모델은 이번 실제 호출 검증에 포함하지 않았습니다.

## 여전히 해결하지 못한 부분

1. **신규 의미 판단:** 일부 로그 누락의 중요도, 보고서의 범위·인과 표현,
   권한 위임 설명의 해석에서 상태나 수정 요청이 달라집니다. 검증 호출도 이를 없애지 못했습니다.
2. **자유 가산의 단위:** 같은 실험을 한 기여 또는 여러 기여로 묶고 구현 기능을
   독립 가산으로 중복 인정하는 차이가 남았습니다. 앵커 ID만 고정해서 해결되지 않습니다.
   후보 수를 임의로 제한하거나 가산을 제거해 통과시키지 않았습니다.
3. **정확도·감점 경계:** 교수자의 항목별 참조 판정이 없어 전체 정확도는 측정하지
   않았습니다. 실제 프로토콜 누락의 영향과 중심 요건 미충족 여부도 구별해야 합니다.
   예를 들어 최신 프로토콜에는 initialize가 없어도 되지만
   [Accept 헤더는 여전히 필수](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)입니다.
   어떤 감점이든 잘못됐다고 가정하여 전부 통과시키지 않았습니다.
4. **운영 준비:** 공식 배점·질문함의 미결 정책은 교수자 결정이며, 상위 모델로
   동일 표본을 비교하지 않았습니다. 경량 모델의 문제로만 단정할 수 없습니다.

[Harness² 적용 기록](harness2-adaptation.md)의 변경 제안→고정 표본 대조→근거 있는
변경 조합 절차를 사용했습니다. 확인된 구현 결함의 수정과 별개로, 이 조합을
완성된 자동 채점기로 승인하거나 모든 교수자 피드백을 해결했다고 보고하지 않습니다.
