2026-10-23. 이 기록은 구현 검증, 저장 판정 재생, 새 모델 판단의 일치와 정확도를
구분합니다. 학생 프로그램을 실행·import하지 않았고 학생 PR에 코멘트를 게시하지
않았습니다. 개별 평가와 원문·실패·사용량은 Git에서 제외한
`runs/criteria-validation-v09/`에 보존합니다.

## 변경한 평가 계약

- 기존 필수항목 18개와 무배점 정성 영역 3개를 유지합니다. 모델 검토 항목 14개를
  내부 사실 질문 72개로 나눴습니다. 질문 수가 배점이 되지는 않습니다.
- 모델은 최대 4개 질문에 값·근거를 반환합니다. 코드로 증명한 사실은 모델에게
  다시 맡기지 않습니다. 점수·피드백 유형·수정 문구·재실험 권고는 코드로 조립합니다.
- 긍정적인 JSON 로그 구조·행별 집계 증명, 요약 동일성, 산술과 Git 조상 관계를
  코드로 계산합니다. 지원하지 않는 형식은 미충족이나 0건으로 확정하지 않습니다.
- 보고서 모순 지적에는 실제 주장과 반례의 원문 인용이 필요합니다. 인용이
  존재하는지 검사하지만 의미상 모순인지까지 증명하지는 않습니다.
- 유효한 질문별 답은 독립 저장합니다. 같은 묶음의 일부 답이 실패해도 다른 답은
  보존합니다. 명시적 재시도는 실패한 질문만 처리하며 과거 결과를 소급 변경하지 않습니다.
- 모든 PR과 가산 단계가 하나의 제한된 작업 풀을 공유합니다. 가산 중복 관계의
  순환도 처리하되 같은 폴더라는 이유만으로 독립 기여를 합치지 않습니다.

설계와 실행 계약은 [작은 사실 검사](atomic-grading.md), 사용법은
[상세 가이드](usage.md)에 있습니다.

## 개발 중 발견해 고친 결함

첫 72질문 검사(`professor-regressions/`, `case-regressions/`)의 실패 기록은
보존했습니다. 다음 두 문제를 재현하는 테스트를 먼저 실패시킨 뒤 수정했습니다.

1. 인용 오류로 일부 질문만 유효한 작업을 다시 읽으면 유효한 답도 사라졌습니다.
   부분 영수증을 실패한 원래 시도에도 저장하고 캐시 경로가 이를 복원하도록 했습니다.
   미해결 질문은 보류로 유지하며 모델을 자동 재호출하지 않습니다.
2. 코드가 전체 로그에서 계산한 근거를 현재 모델 파일 묶음에 없는 인용으로
   거부했습니다. 모델의 원래 인용을 제공 범위 안에서 먼저 검증하고, 코드 소유
   근거를 별도로 검증하도록 했습니다. 모델의 보이지 않는 파일 인용은 계속 거부합니다.

추가로 서로 다른 역할의 응답을 같은 도구 이름만으로 대응시키지 않도록 했습니다.
역할이 다른 합성 로그의 회귀 검사와 다섯 표본에서 어댑터 출력이 바뀌지 않음을
확인했습니다. 이 세 보완을 적용한 `release-*-regressions/`에서는 모델이 구현 사실을 별도 교수자
정책 질문으로도 제출하여 이미 지지한 항목을 다시 보류시키는 문제가 관측됐습니다.
해당 검사는 중단 이유와 완료·미완료 기록을 보존하고 중단했습니다. 작은 사실
추출은 평가표의 `assessment.policy_questions`에 미리 선언한 질문만 선택하도록
제한했습니다. 기본값은 빈 목록이며, 새로운 사실 불확실성은 `null`로 남깁니다.
코드 소유 C02 정책 질문과 선언한 정책의 답변 전파는 유지합니다. 이 보완까지
위 최종 30조건을 시작하기 전에 적용했습니다.

초기 67질문 파일럿과 항목 한정 진단은 `pilot/`, `focused/`에 별도 보존합니다.
없는 보고서 주장을 인용한 답도 관측됐으며 이를 정상적인 수정 요청으로 채택하지
않았습니다. 이 탐색·중간 버전 및 명시적으로 중단한 검사의 호출은 최종 30조건 사용량과 합산하지 않습니다.

## 해석과 사용 한계

일치율이 높다는 것은 맞게 채점했다는 뜻이 아닙니다. 교수자의 항목별 참조 판정이
없어 전체 정확도·오탐률·누락률은 측정하지 않았습니다. 코드의 분기 인덱스도 실제
권한 검사의 정확성이나 실행 가능성을 보증하지 않습니다.
보안 결함 한 건은 코드 경로에서 정적 반례를 확인했지만, 같은 미충족 값을 낸
모델 설명 중에는 턴 순서가 맞지 않는 반례도 있었습니다. 판정 값의 일치와 설명의
정확성도 별개이며, 이 확인은 실행 실험이나 교수자의 참조 판정이 아닙니다.

같은 사실에서 점수를 계산하고 저장된 사실을 재생하는 부분은 결정적으로
만들었습니다. 반면 코드 동작의 의미·주장의 범위·추가 기여의 가치와 독립성은
모델 또는 사람의 판단입니다. 내부 질문을 더 잘게 나눈 것만으로 신규 모델 호출이
모두 같은 답을 낸다고 주장하지 않습니다. 미해결 사실·검토 실패를 숨기거나
보류를 0점으로 확정하여 안정성을 만들지 않습니다.

자유 가산은 후보 발견 단계부터 달라질 수 있습니다. 명시된 중복 관계의 계산을
고쳐도 후보 누락이나 서로 다른 기여 분할을 모두 해결하지는 못합니다. 가산 후보
수를 임의로 제한하거나 자유 가산을 끄는 방식으로 검사를 통과시키지 않았습니다.

공식 50:50 배점의 항목 배정·가중치와 `open_non_deal` 같은 미결 정책은 교수자가
확정해야 합니다. 하네스는 질문함·답변 전파·기존 판정의 배점 환산을 지원하며,
기본 1점 체크리스트를 공식 성적으로 바꿔 부르지 않습니다. 상위 모델·Claude·다른
API의 실제 채점 품질과 새 과제에 대한 일반화도 이번 검증 범위 밖입니다.

[Harness² 적용](harness2-adaptation.md)은 개발 중 제안→고정 표본 대조→근거 있는
변경 조합 절차입니다. 실제 학생 평가 중 기준을 스스로 변경하는 기능이나
Harness² 전체 프레임워크를 통합한 것은 아닙니다.

같은 엔진의 후속 Haiku 실험, 교수자 리뷰별 대응과 현재 미해결 사항은
[리뷰 대응 및 검증 현황](review-response-0.9.md)에 있습니다. 해당 Haiku 실험은
사용량 한도로 전체 조건을 완료하지 못했습니다.
