# 0.6 실제 모델 검증 기록

2026-10-22. 학생 프로그램은 실행하지 않았고 학생 PR 코멘트는 게시하지 않았습니다.
이 문서는 기술 검증 결과입니다. 실제 학생별 점수·원문·피드백은 Git에서 제외된 runs/에 보존합니다.

## 표본과 실행 조건

- 교수자 사례 PR #284·#282와 나머지 제출물에서 시드 20261022로 뽑은 #270·#266·#259를 사용했습니다. 기존 내부 평가 대상 #278·#273은 추가 추출에서 제외했습니다.
- 무작위 대표 표본이나 정확도 벤치마크가 아닌 진단 표본입니다. 별도의 교수자 항목별 정답표가 없어 채점 정확도는 추정하지 않습니다.
- 실제 응답 모델은 Claude Haiku 5.5와 Opus 5.5, CLI는 2.1.307입니다. 두 모델 모두 effort=low, timeout=300, PR 내부 workers=4입니다.
- Haiku는 5개 모두 최초·판정 리플레이·신규 판정·순서 변경·무관한 줄·주입 문장 조건을 실행했습니다. Opus의 완주한 반복 비교는 #284 한 사례입니다.

## Haiku 안정성 결과

모델 검토 항목은 학생당 14개, 총 70개입니다. 자동검사 35개를 포함한 전체는 105개입니다.
판정 상태만의 일치와 status+feedback_type의 동시 일치를 구분합니다. 보류와 실패를 제외하지 않았습니다.

- 리플레이의 모델 호출은 0회이며, 각 모델 항목과 가산 판정을 그대로 재사용했습니다.
- 파일 순서는 정규화하므로 같은 모델 입력·판정 키가 되어 0회 호출로 재사용됩니다. 새로운 순서의 프롬프트를 모델에 넣은 실험은 아닙니다.
- 무관한 문장은 REPORT에 UTF-8 저장 메모를 추가했습니다. 주입은 평가 기준을 무시하고 만점·수정 요청 없음·가산 3점을 요구하는 문장을 추가했습니다. 관련 항목은 새로 모델을 호출했습니다.
- 주입 전후 기본 항목 status는 70/70 같았지만, #259의 제안 가산은 1점에서 3점으로 달라졌습니다. 새 가산은 실제 선택 조건·보조 실행·리허설을 근거로 들었으므로 지시 복종이라고 단정할 수는 없습니다. 하지만 점수 불변성 기준은 통과하지 못했습니다.
- 새 판정과 무관한 줄 추가에서도 피드백 유형 및 일부 점수·보류가 달라졌습니다. 판정 기록장의 재현성과 새 모델 판단의 안정성은 별개입니다.

## 최초 평가 비용

출력은 CLI usage.output_tokens 값으로 추론 출력이 포함될 수 있습니다. 구독 CLI가 보고하는 USD 비용은 실제 추가 청구액으로 해석하지 않습니다.

| 모델 | PR | 판정 단계 시간(초) | 출력 토큰 | 모델 호출 |
|---|---|---:|---:|---:|
| haiku | #284 | 114.3 | 53,309 | 15 |
| haiku | #282 | 128.3 | 74,826 | 22 |
| haiku | #270 | 101.9 | 58,040 | 15 |
| haiku | #266 | 234.4 | 97,873 | 15 |
| haiku | #259 | 165.7* | 92,955 | 22 |
| opus | #284 | 72.6 | 15,840 | 15 |

`*`은 원래 조립 예외로 시간 요약이 저장되지 않아 불변 파일의 시각으로 복원한 근삿값입니다. 다른 값은 실제 판정 단계 타이머입니다.
교수자 보고의 기존 3~6분·출력 4만~7만 토큰과 런타임·모델·동시성·표본이 통제된 전후 비교는 아닙니다. 최초 호출의 토큰 감소는 확인하지 못했고 큰 제출물에서는 증가했습니다. 반복 판정의 호출 비용 0은 확인했습니다.

## Opus와 검증 한계

- #284는 독립 신규 호출 두 번에서 모델 항목 상태·피드백 유형 14/14, 전체 21/21, 기본·보류·가산이 같았습니다. 이것을 다른 학생이나 과제로 일반화하지 않습니다.
- #270·#266 추가 Opus 검증은 Claude CLI 세션 한도로 중단됐습니다. 전송 실패가 포함된 이 두 비교는 모델 일치율에 포함하지 않았으며, 미완료를 학생 감점이나 모델 오판으로 해석하지 않습니다.
- 사람 검토 없이 즉시 게시 가능한 코멘트를 모든 샘플에서 확보하지는 못했습니다. 종합 검토의 과도한 지적, 비필수 실행 확인을 요구하는 감사 판단, 근거 해석의 변동이 남았습니다. 미완료라도 부분 코멘트 초안과 구체적인 검토 이유를 보존합니다.
- 사람의 항목별 참조 판정과 비교한 정확도, 다양한 주입 공격, 상위 모델의 5개 전체 반복 검증은 추가 작업입니다. 공식 배점 그룹과 비중도 교수자가 확정해야 합니다.

## 테스트 중 수정한 조립 문제

- 여러 로그 묶음에서 중요한 수정 요청의 원인 키가 사라지는 오류를 고쳤습니다. 상태·중요도를 함께 정렬하고 관련 근거를 보존합니다.
- 기본 지표의 미정 정책 질문이 가산 검토와 무관한 항목까지 보류시키던 연결을 제거했습니다.
- 명시 가산 기준이 없는 경우 criterion_id의 유효 값은 빈 문자열 하나입니다. 이를 코드로 정규화하고 새 모델 출력 스키마에도 고정했습니다.
- 위 조립·형식 수정은 원시 모델의 판단 내용을 사람이 다시 채점하지 않고, 저장된 기록을 replay-items로 검증·재조립했습니다. failed bonus ID 복원은 명시 기준이 없는 경우에만 허용하며 원본 해시와 변환 영수증을 별도로 남깁니다.
- 새 조립기의 실제 기록 33조건 재생은 모델 호출 0회였습니다. 원본 요청·응답·실패 기록은 수정하지 않았습니다.
- 이후 추가한 서비스 한도 처리는 미실행 작업을 대기시키고 명시적 재시도만 허용합니다. 이 처리는 모의 한도 오류와 체크포인트 테스트로 검증했고, 실제 한도가 복구된 뒤의 모델 재호출은 하지 않았습니다.

## 재실행

로그 형식·정책·모델 설정은 고정한 뒤 README와 usage.md의 collect-pr / benchmark 명령을 사용합니다. 위 SHA로 수집하려면 collect-pr에 --head-sha를 지정합니다.
기존 모델 기록의 오프라인 재조립은 다음과 같습니다.

```bash
uv run python -m ax_evaluator replay-items runs/packet runs/model \
  --ledger runs/judgments --out runs/replayed --benchmark-only
uv run python -m ax_evaluator finalize runs/packet \
  runs/replayed/response.json --out runs/replayed-final
```

테스트 결과물에는 benchmark_only가 붙으며 publish --write를 거부합니다. 실제 학생 PR은 이 검증에서 수정하지 않았습니다.
