# Harness²를 채점 하네스 개선에 적용하는 방법

Google Research의 [Harness² 저장소](https://github.com/google-research/harness2)와
[논문 2절](https://arxiv.org/html/2610.14224v1#S2)을 확인했습니다.
Harness²는 모델 가중치를 바꾸지 않고 모델 주변의 지침·도구·기억 등을 개선합니다.
핵심 절차는 변경안을 제안하고(Propose), 같은 작업에서 시험하고(Probe), 실행의
차이가 뒷받침하는 변경을 조합하는 것(Compose)입니다. 작업 이후에는 채택한
변경과 근거 있는 교훈을 다음 개선에 활용합니다. 이것이 채점의 결정성이나
정확성을 보증하는 알고리즘이라는 주장은 원문에 없습니다.

## 이 프로젝트에서의 적용

다음은 원문을 바탕으로 설계한 이 프로젝트의 적용 방식입니다. Harness² 패키지를
설치하거나 학생 제출물을 그 프레임워크에서 실행하는 방식은 아닙니다.

| 관측한 문제 | 적용한 변경 | 검증 방법 |
|---|---|---|
| 정상적인 위반 실험을 CSV 불일치로 지적 | 가격·한도 산술, 에피소드 요약 대조를 코드로 제공 | 정확히 기록된 위반 거래의 회귀 검사 |
| 제안 거절을 서버 거부로 계산 | 명시적 호출·응답·역할·실행 턴 표지만 읽는 집계 | 정상 reject와 실제 거부 후 복구를 구별하는 검사 |
| 보고서에 있는 재시도 설명을 못 봄 | 로그 대조 항목에도 보고서 전체를 제공 | 항목별 제공 파일 명세와 원문 보존 |
| 제출물과 무관한 사용자 지침이 모델에 로드됨 | CLI 사용자 문서·기억·도구 자동 로드를 제한 | 합성 AGENTS.md 표식의 기본/제외 설정 대조 실험 |
| 구버전 MCP 초기화·스트리밍 요건을 잘못 적용 | 고정 프로토콜의 JSON/SSE 허용 범위와 중심 요건·국소 수정 경계를 질문에 명시 | 공식 문서, 회귀 검사와 독립 호출 비교 |
| 커밋 메시지나 시간으로 실행 순서를 추정 | Git 객체의 조상 관계를 수집해 코드로 계산 | 위조 메시지·없는 조상 관계·불충분한 이력 회귀 검사 |
| 명세에 없는 필드 배치를 강제 | 주입 문장의 노출과 정확한 내용만 기준으로 사용 | 고정 명세와 평가표의 요건 대조 |
| 추측성 오류 지적과 필수 구현 가산 | 사실 질문과 원문 인용 검증, 가산 후보·자격 분리와 명시된 중복 관계 조립 | 질문별 값·인용, 가산 판단의 독립 재채점 비교 |
| 한 답의 인용 오류로 유효한 다른 답도 사라짐 | 질문별 검증·저장, 실패한 질문만 명시적으로 재개 | 부분 실패·재개·과거 결과 불변 회귀 검사 |
| PR마다 별도 병렬 풀이 생겨 전체 동시 호출이 늘어남 | 모든 PR과 가산 작업이 하나의 제한된 작업 풀 사용 | 여러 PR의 실제 동시 작업 수와 제공자 한도 중단 검사 |
| 실패한 안정성 검사도 명령이 성공 | 엄격한 acceptance 결과와 실패 종료 코드 | 차이·누락·처리 실패·가짜 신규 호출을 거부하는 검사 |

0.9에서는 최대 4개의 고정 사실 질문을 한 번에 추출합니다. 점수·피드백 유형은
코드로 조립하고, 유효한 사실 답을 결과가 마음에 들지 않는다는 이유로 재추첨하지
않습니다. 보고서 모순 지적에는 실제 원문 인용이 필요합니다. 가산 후보 발견·자격과
이전 관측 계약의 부정적/불명확한 판단·보안 구현은 별도 검증 호출을 유지합니다.
이 조건은 실행 전에 고정하며 특정 학생에게만 다르게 적용하지 않습니다.

검증 모델에는 최초 응답이 정답이 아니라고 명시하고 원문을 다시 제공합니다.
검증 결과도 모델 판단이며, 같은 모델을 두 번 부른 것이 독립적인 정답 검증을
뜻하지는 않습니다. 과제 내용의 의미 판단을 모두 결정적으로 만들었다고
주장하지 않습니다.

명시적 전송 재시도는 최대 한 번이며 완료 응답이 없는 지정 오류에만 적용합니다.
점수나 안정성 검사의 결과를 보고 유효한 답을 다시 뽑는 절차가 아닙니다.
최초 실패와 추가 호출·사용량도 검증 기록에 남깁니다.

## 개선과 실제 채점을 분리

1. 실패 실행과 근거를 보존하고 원인을 특정합니다.
2. 일반적으로 적용할 수 있는 변경과 회귀 검사를 작성합니다.
3. 명세·평가표·정책·모델·코드를 고정하고 같은 스냅샷으로 비교합니다.
4. 저장 판정 재생, 독립 신규 호출, 입력 순서, 무관한 문장, 주입을 각각 측정합니다.
5. 판정·점수·가산·게시 준비 여부의 변화, 처리 실패와 비용을 공개합니다.
6. 실패가 남으면 변경을 완성된 자동 채점기로 승인하지 않습니다.

실제 학생 채점 중 평가 기준을 스스로 고치거나, 학생마다 다른 기준을 학습해
적용하지 않습니다. 개선 경험은 개발 문서와 회귀 검사로 남깁니다. 과거 학생의
점수나 결론을 다음 학생의 판단 근거로 재사용하지 않습니다.

## 별도로 남는 검증

- 같은 답을 반복하는 것은 맞는 답이라는 뜻이 아닙니다. 교수자의 항목별 참조
  판정과 비교해야 정확도·오탐·누락을 평가할 수 있습니다.
- 가산 후보 발견도 의미 판단입니다. 후보 ID/근거 선택의 차이와 실제 가산점
  차이를 함께 보고, 후보 수를 임의로 제한해 안정성을 만들지 않습니다.
- 순서 정규화 뒤 저장 응답을 재사용한 결과를 새 모델 호출의 일관성으로
  보고하지 않습니다. 다수를 보류로 돌리는 것도 통과의 근거가 아닙니다.
- 재현성과 함께 처리 완료율·오류 사례·토큰 사용량을 보고합니다. 상위 모델의
  성능이나 다른 과제로의 일반화는 해당 조건에서 별도로 시험해야 합니다.
