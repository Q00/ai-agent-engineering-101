# AX 과제 평가 하네스

PR로 제출된 AX 과제의 코드·보고서·실행 로그·결과표·커밋 이력을 검토하여
**사람 채점용 점수와 피드백 초안**을 생성합니다. 과제별 필수 요구사항을 확인하고,
보고서와 실제 구현의 모순, 과제 의도에 대한 해석, 추가 시도의 기여를 평가합니다.

학생 프로그램을 실행하지 않고 제출된 자료를 검토합니다. 결과는 교수자의 공식
성적을 대신하지 않습니다. 과제 명세에 맞는 평가표를 설정하여 사용합니다.

## 평가 기준

| 평가 영역 | 확인하는 내용 | 점수 처리 |
|---|---|---|
| 필수 요구사항 | 명세가 요구한 구현·실험·기록·보고서의 충족 여부 | 충족 항목당 1점 |
| 보고서와 구현·기록의 일치 | 수치, 성공 판정, 구현 설명을 코드·로그·결과표와 대조 | 무배점, 오류는 수정 요청 |
| 과제 의도와 해석 | 과제 질문에 답했는지, 주장과 실패 해석이 근거로 뒷받침되는지 | 무배점, 보완·수정 요청 |
| 추가 시도 | 필수사항을 넘는 기여와 검증 근거, 해석의 타당성 | 인정된 기여당 가산 1점 |

- 필수항목은 충족·미충족·보류로 판정합니다. 보류를 0점으로 확정하지 않습니다.
- 기본점수와 가산점은 별도로 표시합니다. 추가 작업이 많아도 기본점수 분모는 늘어나지 않습니다.
- 기본점수 분모는 해당 과제의 평가표에 정의한 필수항목 수입니다.
  과제 명세를 바탕으로 평가항목과 충족·미충족 기준을 먼저 정합니다.
- 명시적인 가산 기준은 시작 인터뷰에서 입력합니다. 별도 기준이 없어도 의미 있는
  추가 시도는 평가하며, 같은 기여를 중복 가산하지 않습니다. 기본 가산 상한은 없습니다.
- 정성 평가에서 필수 요구사항의 미충족이 드러나면 해당 필수항목에서 판단합니다.
  단순 표현 오류나 추가 분석의 국소적인 오류를 자동으로 기본 감점에 연결하지 않습니다.
- 실험 실패 자체나 허용된 모델·호스트의 선택은 감점 사유가 아닙니다.

평가표는 [설정 예시](rubrics/review-only.example.json)를 바탕으로 작성합니다.
같은 평가 묶음에는 동일한 명세·평가표·가산 정책을 적용합니다.

## 피드백을 만드는 방법

모델은 [assignment-review 지침](skills/assignment-review/SKILL.md)에 따라 근거의
파일과 행 번호를 기록하고, 잘한 점·수정 요청·개선 제안·확인 필요 사항을 구분합니다.

특히 다음 사항을 필수로 검토합니다.

1. **실제 성공 여부:** 학생의 성공 표시뿐 아니라 최종 답, 성공 판정 코드,
   검증 응답의 처리 경로를 대조합니다. 검토에 필요한 증거가 부족하면 명시합니다.
2. **재실험 필요 여부:** 기존 기록으로 고칠 수 있는 계산·문서 문제와 수정 후 새
   실행 근거가 필요한 동작 문제를 구분하고 이유를 남깁니다.
3. **같은 원인의 수정 요청:** 공통 식별자로 묶어 학생용 코멘트에서 한 번만
   표시합니다. 항목별 상세 평가와 근거는 보존합니다.

중요한 수정 요청은 기본점수 만점이어도 코멘트에 포함됩니다. 가산점도 수정 요청을
상쇄하지 않습니다. 같은 원인인지, 중복 감점인지에 대한 의미 판단은 모델·사람이
담당하며, 코멘트 통합 기능이 감점 중복까지 자동으로 제거하지는 않습니다.

## 구성과 재현성

| 구성 | 역할 |
|---|---|
| Tool — Python CLI | PR 수집, 지원되는 자동검사, 응답 검증, 점수 계산, 결과 생성 |
| Skill — 평가 지침 | 무엇을 어떤 근거로 판단하고 피드백할지 안내 |
| Model — 평가 모델 | 요구사항 충족, 모순, 해석과 추가 시도의 가치를 판단 |
| Observation — 도구 결과 | 수집 원문, 검사 결과, 모델에 제공한 근거와 생략 범위 |

수집한 제출 커밋과 과제 명세, 평가표, 모델 설정, 입력 파일의 해시를 기록합니다.
동일한 입력과 저장된 검토 응답으로 계산한 점수는 재현할 수 있습니다. 그러나
새 모델 호출의 판단이나 서로 다른 모델의 판단이 같다고 보장하지는 않습니다.
근거 위치의 존재는 코드로 검증하지만, 그 근거가 주장을 지지하는지는 별도 검토가 필요합니다.

자동검사 범위는 해당 과제에 연결한 검사기에 따라 다릅니다. 전용 검사기가 없는
과제는 모델/사람 검토 방식으로 평가하며, 검사기를 추가하면 자동 대조를 확장할 수 있습니다.

## 빠른 시작 — PR 목록 준비

Python 3.11 이상, `uv`, `git`, 로그인된 GitHub CLI(`gh`)가 필요합니다.
일괄 처리는 macOS/Linux에서 지원합니다. 다음 예시는 모델을 호출하지 않고
지정한 PR들의 평가 자료를 준비합니다. `PR_NUMBER_1`, `PR_NUMBER_2`, `week-NN`,
`FULL_SPEC_COMMIT_SHA`는 실제 PR 번호·과제 주차·전체 40자리 명세 커밋 SHA로 바꾸세요.
`runs/assignment-rubric.json`에는 해당 과제에 맞게 작성한 평가표를 준비합니다.

```bash
cd homework-evaluator
uv sync --locked

# 같은 평가 묶음에 사용할 가산 정책을 한 번 입력
uv run python -m ax_evaluator interview --out runs/bonus-policy.json

# 명시한 PR만 일괄 준비: 명세는 전체 커밋 SHA로 고정
uv run python -m ax_evaluator batch \
  --prs PR_NUMBER_1 PR_NUMBER_2 --week week-NN \
  --spec-ref FULL_SPEC_COMMIT_SHA \
  --rubric runs/assignment-rubric.json --policy runs/bonus-policy.json \
  --out runs/assignment-batch
```

준비 후에는 두 가지 방법으로 평가할 수 있습니다.

- **현재 세션/사람 검토:** PR별 템플릿에 판단을 작성하고 `import-review`로 가져온 뒤,
  같은 일괄 명령에 `--resume --stage finalize`를 추가하여 결과를 생성합니다.
- **모델 연결:** `--config`로 모델 설정을 지정하고 `--stage evaluate`로 실행합니다.
  준비와 모델 평가를 나눠 실행할 때는 처음부터 같은 `--config`를 사용합니다.
  모델 호출에는 해당 서비스의 사용량·비용이 발생할 수 있습니다.

일괄 실행은 일부 PR이 실패해도 나머지를 계속 처리합니다. 같은 입력에 `--resume`을
추가하면 저장된 작업을 재사용하며, 실패한 모델 호출은 `--retry-failed`를 지정할 때만
다시 시도합니다. 자동 PR 감지·예약 실행·일괄 게시는 포함하지 않습니다.

실행 가능한 전체 예시, 현재 세션 검토 가져오기, 재개 방식은
[상세 사용 가이드](docs/usage.md)를 참고하세요.

## 모델 연결

학생이 과제에 사용한 모델과 평가에 사용하는 모델은 별개입니다.
다음 연결 방식이 같은 평가 입력과 응답 형식을 사용합니다.

| 연결 방식 | 설정 예시 |
|---|---|
| Codex CLI | [codex.json](configs/codex.json) |
| Claude Code CLI | [claude.json](configs/claude.json) |
| OpenAI 호환 API | [openai-compatible.json](configs/openai-compatible.json) |
| Anthropic API | [anthropic.json](configs/anthropic.json) |
| 이미 실행 중인 OpenAI 호환 로컬 모델 | [local.json](configs/local.json) |

예시의 모델명·endpoint를 실제 환경에 맞게 설정하세요. API 키 값은 설정 파일에
넣지 않고 환경변수로 전달합니다. 로컬 모델 서버를 설치하거나 시작하는 기능은 없습니다.

## 결과물과 PR 코멘트

| 결과물 | 내용 |
|---|---|
| `snapshot.json`, `bundle.json`, `coverage.json` | 수집 원문, 고정된 평가 입력, 근거 생략 범위 |
| `evaluation.json` | 항목별 판정·점수·근거·보류·평가 주체 |
| `feedback.md` | 채점자용 상세 평가와 수정·보완 요청 |
| `pr-comment.md` | 학생용 주요 장점·수정 요청·근거 링크·재실험 판단 |
| `summary.md`, `summary.json` | 일괄 처리의 PR별 상태·점수·상세 결과 경로 |

학생용 코멘트에는 잠정 점수 대신 주요 피드백을 담습니다. 결과는 `runs/` 아래에
저장하며 Git에서 제외됩니다. 기존 평가와 실패 기록을 보존하고, 재평가는 새 출력
폴더에 저장합니다. 실제 학생의 평가 결과는 이 하네스 PR에 포함하지 않습니다.

`publish`는 코멘트를 미리보기하고, 명시적으로 `publish --write`를 실행할 때만
GitHub에 게시합니다. 게시 전 제출 커밋의 변경 여부와 검토 완료 상태를 확인합니다.
일반 PR 코멘트를 생성·갱신하며 GitHub의 Approve/Request changes 상태는 바꾸지 않습니다.

## 검증 범위와 남은 사항

```bash
uv run python -m unittest discover -s tests -v
```

- 테스트는 점수 계산, 근거·응답 검증, 중복 코멘트 통합, 일괄 처리의 실패·재개,
  모델 어댑터와 게시 절차를 검증합니다. 외부 호출과 GitHub 쓰기는 모의 응답을 사용합니다.
- 각 외부 모델 연결의 실제 종단 간 동작과 새로운 제출물에서의 판단 품질은 추가
  검증이 필요합니다. 학생 프로그램의 실행 가능성을 직접 보증하지 않습니다.
- 과제 명세만으로 판정이 어려운 정책은 평가 전에 교수자가 정하고, 같은 평가
  묶음에 동일하게 적용합니다. 정해지지 않은 기준은 임의로 확정하지 않습니다.

다른 과제에는 [평가표 예시](rubrics/review-only.example.json)를 바탕으로 필수항목과
판정 기준을 먼저 정의합니다. 학생별로 평가 분모를 바꾸지 않으며, 새로운 주차의
자동검사가 필요하면 검사기와 테스트를 함께 추가합니다.
